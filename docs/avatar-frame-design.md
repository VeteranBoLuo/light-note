# 轻笺头像框设计规范

> 版本：v1.0（2026-08-14）
>
> 本文是轻笺头像框视觉等级、结构预算、动效预算、新款设计流程与验收标准的唯一事实源。`docs/design.md` 继续管理全局品牌、主题与组件规则；`docs/points-economy.md` 和服务端目录继续管理价格、等级与获取条件，不得在其他文档另建一套头像框视觉梯度。

## 1. 目标与适用范围

本文同时约束：

- 当前 25 款积分兑换与成就领取头像框；
- 后续新增、重做或调价后需要重新评估的头像框；
- 商店卡片、顶栏、个人中心、聊天室、成就墙和后台用户管理中的全部佩戴态；
- CSS、SVG、静态插画、动效编排、性能降级和多尺寸验收。

本文使用以下规范词：

- **必须 / 禁止**：不可省略的验收门槛；
- **应 / 不应**：默认实现方式，偏离时必须说明理由并补充等价验收；
- **可**：在不突破本档预算和安全区的前提下选择。

## 2. 概念与判断顺序

### 2.1 获取方式

- **积分款**：`acquisition = shop`，用户用积分兑换。视觉强度同时受稀有度和同档价格约束。
- **成就款**：`acquisition = achievement`，本文也简称“免费款”。免费只表示不消耗积分，不表示可以粗糙；它必须准确表达对应成就的纪念意义。

### 2.2 四个稀有度

| 产品名称 | 代码值      | 设计定位                                         |
| -------- | ----------- | ------------------------------------------------ |
| 基础     | `basic`     | 完全静态，简洁、完整、不丑                       |
| 进阶     | `rare`      | 积分款从这里开始有动效，设计感明显高于基础       |
| 炫彩     | `epic`      | 动效、材质、轮廓和第一眼美感均强于进阶           |
| 传说     | `legendary` | 全部使用顶级效果，并继续按积分价格或成就难度分层 |

### 2.3 视觉等级的判断顺序

设计前必须依次确认：

1. 获取方式是积分还是成就；
2. 稀有度是基础、进阶、炫彩还是传说；
3. 积分款在同档中的价格位置，或成就款的实际完成难度；
4. 名称、描述和获取条件能够提供什么独有语义；
5. 它的直接下位与上位对照款分别是谁。

禁止只看稀有度颜色，或只因价格更高就增加转速、亮度和圆环数量。

## 3. 总视觉阶梯

### 3.1 非传说的固定关系

非传说款使用以下单向阶梯，右侧必须在第一眼品质上高于左侧：

`成就基础 S0 < 成就进阶 S1 < 积分基础 S2 < 成就炫彩 M1 < 积分进阶 M2 < 积分炫彩 M3`

这条阶梯同时表达以下硬规则：

- 同为基础档时，积分款必须比成就款更精致；二者都完全静态。
- 成就进阶是积分基础的轻度弱化版，整体接近，但必须略低一档；成就进阶仍完全静态。
- 成就炫彩是积分进阶的轻度弱化版，必须保留可见动效，但层次、幅度或材质预算略低。
- 除传说外，成就款都按“前一个低稀有度积分款的弱化版”设计，不能直接复制同档积分款。
- 积分进阶、积分炫彩必须有动效；所有积分传说和成就传说也必须有动效。

“弱化版”只允许减少一至两个维度，例如少一层材质深度、少一个次级动效、降低局部光效幅度或缩小外轮廓变化；不得把完整主题弱化成单色圆圈，也不得删掉该预算要求的核心动效。

### 3.2 传说的独立关系

传说不套用“免费等于前一积分档弱化版”。传说全部从顶级基线起步，再根据价格或难度继续分层：

- 积分传说严格满足：`霓虹 6000 < 星河 9000 < 龙曜 12000 < 天穹 16000`。
- 成就传说中，`万卷星库 = 翰墨星海 = 寰宇云藏`，三款使用同一视觉预算，以不同成就语义区分，不互相压级。
- `岁序长明`是成就传说唯一冠冕档，必须明显强于上述三款。
- `天穹`与`岁序长明`是当前项目并列的两款全局天花板：前者代表最高积分价值，后者代表最高完成难度。它们必须高于龙曜和普通成就传说，但彼此不要求复制结构、颜色或动效。

## 4. 可执行视觉预算

这里的“结构层”指用户能独立感知的轮廓或深度职责，例如主框、外冠、前景身份件和背光；多个伪元素堆成同一条圆环仍只算一层。“动效通道”指一套可独立感知的运动逻辑；十个图标跟随同一轨道公转仍只算一个通道。

| 类别         | 预算码                | 自动动效 | 静态结构预算                                 | 动效预算                                           | 必须形成的第一眼印象                           |
| ------------ | --------------------- | -------- | -------------------------------------------- | -------------------------------------------------- | ---------------------------------------------- |
| 成就基础     | S0                    | 禁止     | 1 个主框 + 最多 1 个小型语义细节             | 无                                                 | 简洁、干净、能对应成就，不像默认描边           |
| 成就进阶     | S1                    | 禁止     | 1～2 个结构层，有完整轮廓和轻材质            | 无                                                 | 接近积分基础，但在材质深度、细节或对比度上略弱 |
| 积分基础     | S2                    | 禁止     | 2 个左右结构层，材质、边缘和焦点完整         | 无                                                 | 静态也值得兑换；不惊艳，但绝不简陋或难看       |
| 成就炫彩     | M1                    | 必须     | 2～3 个结构层，主题轮廓完整                  | 1 个持续核心通道，可带 1 个低强度点光              | 是积分进阶的弱化版，动态清楚但不过度           |
| 积分进阶     | M2                    | 必须     | 2～3 个结构层，材质比基础更精细              | 1 个持续核心通道 + 最多 1 个次级通道               | 不等待完整周期就能察觉它是动态框               |
| 积分炫彩     | M3                    | 必须     | 3～4 个结构层，有明显外轮廓或材质变化        | 1 个核心通道 + 1～2 个协调的次级通道               | 美感、动效与辨识度都明显强于积分进阶           |
| 积分传说     | L1～Ln（当前 L1～L4） | 必须     | 独有轮廓、前中后景和身份焦点，不得套通用圆环 | 持续底层动效、名称语义动效和高光事件相互衔接       | 任意价位都一眼属于传说；价格越高，综合表现越强 |
| 成就传说标准 | LA                    | 必须     | 与积分传说同级的定制结构                     | 至少 2 个协调通道，并有成就语义事件                | 三款同预算、不同主题，均明显高于炫彩           |
| 全局天花板   | LX                    | 必须     | 完全定制的冠冕级轮廓、材质系统和视觉焦点     | 持续底层、主体语义、局部结构与峰值光效形成完整编排 | 不看名称和价格也能认出是全项目最高级别         |

结构数量是设计参考，不是鼓励堆层。一个构图完整的三层方案优于六层重复圆环。

## 6. 高级感的构成标准

高级感不等于“更多圆圈 + 更亮光晕 + 更快旋转”。设计必须同时处理以下五个维度：

1. **轮廓**：在纯色剪影下仍有可辨识的外形。积分炫彩和传说不能只靠同心圆、椭圆与放射线区别。
2. **材质**：建立一致的光源、明暗、边缘高光和表面逻辑。金属、晶体、墨、云、火、星空不能只换颜色。
3. **层级**：背景承托、主框包裹、前景身份件轻搭框沿，遮挡关系必须让装饰与头像属于同一空间，而不是贴上去的图标。
4. **视觉焦点**：每款只能有一个主要身份焦点，其他发光、粒子和轨迹用于衬托，不能抢头像面部。
5. **动效编排**：运动必须有主次、起承转合和无缝衔接；高级感来自协调，不来自所有部件同时旋转。

### 6.1 名称语义必须进入主体设计

名称相关设计必须在静态帧中已经可读，动效只负责强化：

- 名词或意象决定主轮廓与材质，例如龙、书库、星海、天穹、日月年轮；
- 动词或状态决定运动语言，例如流转、燃烧、潮汐、渐盈、长明；
- 获取条件决定纪念结构，例如 7 日、30 日、365 日、500 篇可转化为节律、刻度或阶段，而不是直接写数字；
- 色彩只服务主题，不单独承担辨识。

禁止把名称对应的小图标贴在圆周上统一公转来充当主题。图标、动物头部、门、书本或星体若是核心身份，必须与框体在轮廓、材质、遮挡和光照上整合。例如龙应形成环绕框体的身躯、前后景关系和局部生命感，而不是一枚悬浮龙头；天穹应以星冠、天体核心、晶体或穹顶结构建立冠冕感，而不是普通圆环外再放一个星星。

### 6.2 插画风格与头像层级

- 身份插画的线宽、边缘锐度、饱和度和阴影应与框体统一，禁止出现独立贴纸感。
- 写实度不能突然高于头像和产品整体插画体系；复杂细节应在 32px 时自动收敛成清楚剪影。
- 头像本身保持静止，不跟随框体缩放、摆动或旋转。
- 前景只能轻搭框沿，不能遮住面部；高级感应通过向外生长、材质深度和局部展开获得，不能靠把框做粗、把头像孔做小。

## 7. 动效标准

### 7.1 静态与动态边界

- 成就基础、积分基础、成就进阶的框体必须完全静态，不使用自动循环、加载入场或悬停动效。卡片选中态等外部 UI 反馈不计入头像框动效。
- 成就炫彩、积分进阶、积分炫彩、全部传说必须有自动动效。
- 动态框在 64px 预览中进入视野后 2 秒内，必须能看出至少一个与主题相关的运动；不能要求用户盯完整周期才能发现。
- 全局缩放呼吸不能作为唯一或主要动效，头像不得参与缩放。呼吸应发生在光、材质或局部结构上。

### 7.2 推荐运动语言

可按名称语义选择，不要求所有框旋转：

| 运动语言        | 适合表达                             | 使用要求                                         |
| --------------- | ------------------------------------ | ------------------------------------------------ |
| 材质呼吸        | 晶体、月光、火光、能量               | 作用于局部亮度、透明度或细小形变，不缩放整套框体 |
| 流光汇聚        | 金属、墨流、星河、潮汐               | 有明确起点与汇聚目标，不能只是无意义扫光         |
| 局部展开 / 折叠 | 羽翼、花瓣、冠冕、门扉、书页         | 幅度在 32px 仍可读，收合后轮廓仍完整             |
| 小幅往返 / 摆动 | 生物、挂饰、星盘指针                 | 需要正确变换原点和自然缓动，不做机械抖动         |
| 显隐 / 相位切换 | 日月、月相、极光、云雾               | 前后状态连续，不能突兀闪烁                       |
| 轨道运动        | 星体、天体、年轮等确有轨道语义的主题 | 最多作为一个主通道，禁止所有主题套同一 360° 公转 |
| 粒子 / 彗星事件 | 炫彩和传说的高潮点                   | 只能做强调，不能替代主体轮廓与持续核心动效       |

### 7.3 连续性与节奏

- 每个动态框必须保留一个低成本、低干扰的持续核心通道；主体事件结束后不能出现明显“完全停住等下一轮”的空档。
- 刻意停顿可以存在，但全框所有通道同时静止不得持续超过约 400ms。
- 峰值动作的缩小或收合尚未完全结束时，下一段底层流光、呼吸或轻摆就应开始接管；相邻阶段应有重叠，不能一个动画归零后再等待另一个启动。
- 循环首尾的位移、角度、缩放和透明度必须相容，不得跳帧、突然复位或先停再弹。
- 同一方向的无限旋转只能用于有明确语义的轨道；生命体、冠冕和主体结构优先使用往返、展开、呼吸、汇聚和阶段切换。
- 禁止快速闪烁、频繁高亮反转或依赖大面积 `filter` 变化制造刺激感。

### 7.4 动效降级与性能

- 优先动画 `transform` 与 `opacity`；`filter`、大面积模糊和多重阴影只作为次要效果。
- 动画不得改变布局尺寸，也不得触发布局抖动。
- `prefers-reduced-motion: reduce`、`animated="false"` 和离屏暂停时必须停止全部装饰动画；静止帧仍需完整、高级，不能只剩残缺轨道。
- 聊天列表快速滚动时可以停用滤镜、粒子和次级通道，但应保留一个低成本核心身份动效；离屏头像应暂停。
- 新增动态层时，必须同步加入组件的 reduced-motion、motion-paused 和聊天室滚动降级规则。

## 8. 画布、头像安全区与层叠

### 8.1 统一画布

- 所有入口必须复用 `AvatarFramePreview` 的 `64px` 头像设计基准、每侧 `6px` 框沿和 `76px` 外层设计画布，再整体等比缩放。
- 禁止为 30/32/40/64/80/86px 入口分别重排几何；小尺寸只能通过统一缩放和必要的可读性变量降级。
- 硬质主体轮廓应收在统一设计画布内。SVG 描边和柔光可预留透明出血，但不得借出血扩大实际身份结构、侵入相邻文字或改变页面占位。

### 8.2 粗细与遮挡

- `64px` 基准下，头像中心至少保留约 `56px` 的清楚可视直径；增加高级感优先向外扩展轮廓，不向内加粗。
- 不透明前景默认不得进入头像圆内部；确需跨沿的主题细节最多轻搭约 `3px`，并避开中心面部区域。
- 外冠、翅片、龙身、星体等不得因尺寸或动画超出卡片安全范围，不能覆盖名称、价格、按钮或相邻头像框。
- 任一关键帧都必须保持头像居中、完整、可读；不能只在动画起点看起来正确。

### 8.3 前后景实现

- 需要跨越头像的装饰必须拆成兄弟层：背景主体低于头像，前景局部高于头像；禁止让子元素依赖高 `z-index` 逃出带 `filter` 或 `transform` 的父级层叠上下文。
- 前景与背景必须通过材质、光照和连续轮廓看成同一物件，不能出现主体在头像后、头部却像独立贴纸浮在前面的层级断裂。
- 复杂 SVG 必须为粗描边、圆角端点、须角和滤镜预留 `viewBox` 安全区；放大素材盒只用于抵消扩展视口的缩放，不得改变框体实际视觉尺寸。
- 静态 SVG、Path 或 Data URL 统一定义在 `apps/web/src/config/icon.ts`，组件通过 `SvgIcon` 引用；禁止在 Vue 模板直接新增静态 `<svg>` 或 `<path>`。

完整的层叠裁切根因与回归方法见 [LN-PIT-041](./pitfalls.md#ln-pit-041头像框前后景不能共用低层叠容器复杂-svg-必须预留出血安全区)。

## 9. 后续新增头像框实施协议

后续 AI 或开发者新增、重做头像框时，必须先完成本节，不能打开组件后直接堆圆环和动画。

### 9.1 先填写设计立项卡

```md
- 名称 / ID：
- 获取方式：积分 / 成就
- 稀有度：基础 / 进阶 / 炫彩 / 传说
- 价格或成就条件：
- 视觉预算码：S0 / S1 / S2 / M1 / M2 / M3 / L1～Ln / LA / LX
- 直接下位参照：
- 直接上位参照：
- 名称语义关键词：
- 主轮廓：
- 主材质与光源：
- 持续核心动效：无 / 具体说明
- 次级与峰值动效：无 / 具体说明
- 32px 简化后仍保留的身份特征：
- reduced-motion 静止帧：
```

若无法明确预算码或相邻参照，必须先确认产品定位，不能自行把普通新款做成天花板，也不能因实现困难向下降级。

### 9.2 用决策表分配预算

| 新款条件   | 默认预算                                                                |
| ---------- | ----------------------------------------------------------------------- |
| 成就基础   | S0，静态                                                                |
| 成就进阶   | S1，静态，略弱于积分基础                                                |
| 积分基础   | S2，静态                                                                |
| 成就炫彩   | M1，动态，略弱于积分进阶                                                |
| 积分进阶   | M2，动态                                                                |
| 积分炫彩   | M3，动态                                                                |
| 新积分传说 | 按价格插入现有传说序列并新建或重排 L 子级；效果必须位于两个价格邻居之间 |
| 新成就传说 | 按实际完成难度评审；默认进入 LA，只有明确高于现有最高难度才可进入 LX    |

如果新积分传说高于 16000，或新成就条件明确难于岁序长明，必须同步评审全局天花板定义和既有相邻款，不能只给新款加一个更亮的光效。

### 9.3 实施顺序

1. **确认静态剪影**：先在无动画、无光晕状态完成 64px 与 32px 轮廓；仅靠颜色变化仍像既有款时必须重画。
2. **确认材质和层叠**：建立统一光源、前中后景和头像安全区，先解决“像一个整体”，再添加运动。
3. **绘制动效分镜**：动态预算款至少写出持续段、主题事件、恢复衔接和循环首尾；禁止只写“旋转 + 呼吸”。
4. **接入统一组件**：在 `AvatarFramePreview` 内增加变体，身份静态素材走 `icon.ts`，所有入口只传 `frameId` 和尺寸。
5. **补齐降级**：同步 reduced-motion、显式暂停、离屏暂停和聊天室滚动降级。
6. **建立相邻对照**：同屏放置直接下位、新款、直接上位；无法一眼说明三者差距时不得验收。
7. **完成代码与视觉回归**：更新目录映射、国际化和测试，并逐入口查看完整周期。

### 9.4 同档内部的升级方法

同一档位中，价格或难度更高的款至少要在下列维度中提升两项；最高价或最高难度款至少提升三项：

- 独有外轮廓与静态剪影；
- 材质深度与光源一致性；
- 前中后景结构完整度；
- 动效通道与阶段编排；
- 名称语义的整合程度；
- 32px 小尺寸身份辨识度。

升级不能只靠提高饱和度、加粗框体、放大光晕、增加同心圆、增加同轨图标或提高转速。

## 10. 验收标准

### 10.1 必验尺寸与场景

- 商店卡片与详情：`64px`、`86px`；
- 个人中心：约 `80px`；
- 顶栏与常规列表：`40px` 左右；
- 聊天室：`32px`；
- 浅色背景、深色背景、`?renderProfile=mobile` 共享移动渲染基线；
- 默认头像、浅色真人头像、深色真人头像和满幅插画头像。

### 10.2 静态验收

- 轮廓、材质与名称语义在暂停状态仍成立；
- 头像不偏心、不被厚框或前景身份件遮住；
- 硬质轮廓、描边、须角、翅片和阴影无裁切；
- 小尺寸没有糊成一团、只剩光圈或丢失核心身份；
- 与相邻档同屏时，视觉排序符合本文阶梯。

### 10.3 动态验收

- 必须观看至少两个完整循环，检查启动、峰值、恢复和首尾连接；
- 2 秒内能察觉核心动效，循环中没有超过约 400ms 的全框静止空档；
- 运动幅度在 32px 可读，在 86px 不夸张，不撞文字或相邻卡片；
- 头像本体保持静止，前后景不跳层，任何关键帧都不遮脸；
- reduced-motion、显式暂停、离屏暂停和滚动降级均能得到完整静止态；
- 多个头像同时出现时不造成明显滚动掉帧或持续高 GPU 占用。

### 10.4 自动化与自检

新增或重做时至少检查：

- 服务端完整目录与前端 `FRAME_VARIANTS` 一一对应；
- 稀有度排序、积分价格和成就获取条件未被视觉代码误改；
- 静态档没有新增关键帧或自动动画；动态档的新增层已进入暂停与降级规则；
- 商店、个人中心、顶栏、聊天室、成就墙和后台继续复用同一个 `AvatarFramePreview`；
- 未知 `frameId` 仍回退普通头像；
- 相关单元测试、类型检查或前端构建通过，并保留相邻档多尺寸截图用于人工审美验收。

自动化只能证明接入、边界和降级正确，不能替代视觉验收。头像框属于强审美资产，最终必须以相邻档同屏截图和完整动效周期判断。

## 11. 禁止清单

- 禁止以同心圆、椭圆、放射线和统一公转作为所有档位的通用模板。
- 禁止在圆周贴一个名称图标旋转，就声称完成主题设计。
- 禁止把“更贵”实现成框更粗、光更大、颜色更艳、转得更快。
- 禁止只做整体放大缩小，或让动画结束后长时间完全静止。
- 禁止为表现前景而遮挡头像面部，或让头像跟着框体运动。
- 禁止身份硬结构越出统一画布并侵入文字、价格、按钮和相邻卡片。
- 禁止只在商店大预览优化，导致 32px 顶栏或聊天室入口失真。
- 禁止复制前一档全部结构后仅换色；同系列也必须至少有独有剪影或主题事件。
- 禁止用大量模糊、滤镜和阴影掩盖材质与轮廓问题。
- 禁止改动某一个入口的局部几何来修补裁切，必须修复统一设计画布或素材安全区。

## 12. 变更与维护

- 新增头像框时，必须在本文“当前目录对应关系”中登记其预算码与相邻参照。
- 积分价格或成就条件变化时，经济与成长目录仍由各自权威来源更新，同时必须按本文重新评估视觉位置；调价本身不得静默改变几何或动效。
- 调整视觉阶梯、天花板定义、动效门槛或画布安全区时，只修改本文，并让 `docs/design.md`、`docs/points-economy.md` 与 `docs/architecture.md` 保持链接引用，禁止复制一份新规则。
- 具有复发风险的实现坑继续记录在 `docs/pitfalls.md`，本文只维护长期设计与验收标准。
