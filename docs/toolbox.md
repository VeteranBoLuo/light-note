# 知识工坊

本文是轻笺知识工坊的产品边界、执行模式、计费结算、任务成果与隐私约束的唯一规范。工具清单、输入上限和动态价格以共享协议、服务端目录和契约测试为准，不在页面或本文维护第二份可执行配置。

## 产品入口与能力分层

- 知识工坊是“把资料变成可交付成果”的二级生产入口，不与工作台、资料、待办和聊天争夺一级导航。PC 从顶栏更多菜单、全局搜索和资料上下文进入；移动端底部中间位是“收集”动作中心，统一承接新建笔记、待办、书签、上传文件和“生成与处理资料”，后者再进入知识工坊。工作台和任务成果仍是二级页，使用顶部返回；有确定父页时返回原页，直接深链或外部历史则替换为工坊根页，禁止用固定 `push` 制造循环返回栈。
- PC 更多按钮与“知识工坊”菜单项可以用同一版本化红点提示入口调整；仅点击“知识工坊”视为已读，打开更多菜单或点击其他入口不得清除。登录账号的已读版本写入服务端用户偏好，普通偏好保存不得清空或伪造该事实；游客按本机设备身份保存。每次提示必须声明绝对发布时间和失效时间，过期后包括新注册与长期未访问用户在内均不再展示；发布下一次入口级上新时递增公告版本，不复用旧已读状态。
- `phase` 只表达产品阶段，`availability.enabled` 与服务端禁用配置共同决定当前能否执行；前端不得因本地旧目录自行开放工具或回退旧价格。
- 首页按“继续现场 → 直接产出成果 → 常用与最近 → 全部工具”组织；访客省略续接区。“继续现场”只展示有明确下一动作的活跃工作区、进行中任务和待保存成果，不是基于历史的推荐。“直接产出成果”只放少量有清晰交付物的主路径，不以工具数量或 Office 功能覆盖率制造价值感。“常用与最近”在同一区域切换用户固定工具与按实际打开时间排序的最近工具，同一工具只保留最新一次，不再用两段页面重复陈列。服务端目录读取失败时只展示协议中明确启用、免费且能完全在浏览器执行的本地能力，并明确降级状态；账号服务与 AI 能力一律失败关闭，不得因目录失败自行开放服务端已禁用工具。
- “全部工具”只读取 `availability.enabled` 的公开能力，并用唯一一套完整目录按“持续工作区、从资料生成、整理知识库、导入前处理、数据处理”分组；默认展示全部分组，顶部分组导航只负责定位而不隐藏其他分组，搜索时跨全部分组匹配，搜索与“全部 / 免费 / AI 或积分”筛选只作用于该目录，不展示没有决策价值的工具总数或“免费数量”。分组与顺序由 `apps/web/src/config/toolbox.ts` 维护，契约测试必须保证每个启用工具在完整目录中恰好出现一次。
- 首页账号活动通过 owner-scoped 读模型获取，不返回资料正文、处理要求或成果正文。仅打开工作区时由单独写入接口节流更新 `lastOpenedAt`，不改写内容更新时间，不在 GET 中隐式写库。前端补充的工具级打开记录只在本地按当前身份保存有限的 `toolId + time`，不保存文件名、问题、材料或正文；用户固定的工具和由其组成的快捷入口同样按账号或访客身份隔离，切换身份不得串用。活动读取失败必须与真实空态区分，且不得阻断快捷入口与全部工具目录。
- 知识工坊只为关键成功写动作记录低敏操作日志：工作区变更、任务创建与取消、成果保存由服务端终态记录，浏览器侧工具成果仅在登录用户发起导出交付时记录稳定工具 ID；禁止记录文件名、材料标题、问题、正文或导出内容。目录读取、搜索筛选、报价、轮询与 Worker 阶段不写操作日志，任务、计费与 AI 执行继续由各自领域账本解释。
- 低频、通用开发类或需要专业配置的能力可以保留稳定协议、实现注册和历史任务展示，但必须设为 `availability.enabled = false`；首页不展示，直接访问工作台也失败关闭。功能重新开放前应先证明知识库场景价值与低门槛交互，不能仅因为实现已经存在就重新上架。
- 知识工坊同时承担两种边界清晰的工作：持续工作区保留长期项目的上下文和推进状态；处理工具把材料变成可继续使用的独立成果。浏览器本地工具直接下载文件；AI 工具生成独立成果，用户确认后才保存为笔记。

现有能力按执行方式分为：

| 执行方式    | 能力边界                                                                                         | 用户资产      | 数据边界                                                                             |
| ----------- | ------------------------------------------------------------------------------------------------ | ------------- | ------------------------------------------------------------------------------------ |
| 浏览器本地  | PDF 工作台、图片压缩与 JPG/PNG/WebP 格式转换、Word 转可编辑文字、Markdown 体检和表格与数据工作台 | 免费          | 原文件与文本不上传，不创建报价、任务或成果记录                                       |
| 账号内服务  | 研究项目、学习计划、写作工程，以及知识库结构巡检                                                 | 免费          | 工作区只保存账号内资料引用、事项和推进记录；结构巡检只返回衍生元数据，不返回正文片段 |
| AI Skill    | 灵感成稿、资料转笔记、研究简报、学习套件、概念图谱、多资料对照与内容体检                         | AI 额度或积分 | 每次执行只选一种介质；无材料工具只读本次想法，资料型工具重新校验归属与版本           |
| 文档 Worker | 扫描件转文字                                                                                     | 积分          | 只处理已确认归属、格式、大小与时效的云文件或临时上传                                 |

AI 工具围绕四类持续使用场景：灵感成稿让用户从主题、目标或想法直接生产第一版；整理与研究用于形成可引用成果；学习套件与概念图谱用于理解和复习；内容体检用于发现重复、冲突、疑似过时内容与证据缺口。每类固定成果绑定一个独立的工坊内部 Skill Profile，但复用同一套 Execution、计费与一次平台修复基础设施；资料型工具再复用资源加载与 Grounding。用户的处理要求只能调整关注点、读者、详略和表达，不能把当前成果切换成其他工具；多资料对照与内容体检等成果也不得合并成同一套提示词。

## 产出边界

- 知识工坊不提供通用 PPT、Excel 或 Word 编辑器，也不以复刻 Office 功能面作为产品价值。当前架构不存在结构化作品项目、修订历史或兼容路由；知识工坊只保留与知识库形成明确闭环的持续工作区、一次性成果和专属处理工作台。
- 笔记库是知识正文、报告、文章和连续长文的唯一创作事实源。工具任务生成的 Markdown 成果只通过正式笔记 Service 存为笔记，后续目录、正文、历史与助手能力全部遵循笔记详情规则。
- 云空间继续支持 DOCX、XLSX、PPTX 等文件预览；预览组件只负责可靠查看，不借知识工坊编辑器写回原文件，也不暗示具备 Office 替代能力。
- 表格与数据工作台保留为任务型能力：围绕一次载入的数据集完成体检、清洗、校验、对比、合并拆分、脱敏、透视和图表，并导出结果。它不是长期工作簿编辑器，不创建独立项目或版本体系。
- 专属工作台只在共享主要输入资产、能够复用连续处理状态且交互确有任务特色时存在。PDF 使用页面缩略图与处理动作，图片使用批次队列与前后对照，数据使用操作轨、处理设置与结果预览；不能为了页面数量复制同一套表单。
- 新增重型能力必须同时证明高频或高价值任务、与轻笺资料的不可替代闭环、可验收的核心交付质量和可持续维护成本。未通过门禁时优先建设资料到成果的窄而深路径，而不是扩张通用办公套件。

## 工作室合并规则

- 只有共享主要输入资产、能够复用同一编辑状态且允许连续处理的能力才合并为一个工作室。历史任务仍保存原 `toolId`，旧深链映射到规范工作室的对应模式，不改写历史记录。
- PDF 工作台统一承接页面整理、图片转 PDF、PDF 转图片和普通文字提取；扫描件 OCR 可以在同一工作室被发现，但仍是独立积分 Worker，不得伪装为本地免费能力。
- 图片工作台统一承接压缩和 JPG/PNG/WebP 转换，后续扩展批量尺寸、裁剪旋转、水印、重命名和 EXIF 清理；抠图、智能放大和背景替换属于独立积分能力。
- 表格体检、清洗、校验、对比、合并拆分、脱敏、透视和图表共用“表格与数据工作台”；浏览器 SQL 保持独立且暂不公开，只有在能够复用同一数据集状态与安全执行边界后再评估合并。Markdown 转换、体检、Frontmatter 和引用处理进入 Markdown 出版台；文本对比、批处理、正则和结构化文本进入文本实验室。
- AI 资料转笔记、研究简报、学习套件、概念图谱、多资料对照和内容体检可以共用“知识研究台”外壳，但底层 Skill、报价、固定成果结构和失败语义保持独立。
- 连续长文不从笔记库拆出同构工作室；图片像素处理不与结构化图示合并；表单不与工作簿合并；通用看板不与具有稳定知识推进语义的研究、学习、写作工作区合并。

## 持续工作区

- 研究项目、学习计划与写作工程是同一持久化引擎的三种业务模板，不是三套互相复制的页面或数据模型。模板只改变引导文案、三段看板的语义和默认工作方式；材料、事项、推进记录、状态与权限边界保持一致。
- 一个工作区由目标、目标日期、当前下一步、账号内资料引用、三段事项和推进记录组成。结束一次推进时至少记录“本次进展”或“下一步”；推进记录按日期形成连续天数，但连续天数只是反馈，不产生积分或强制签到。
- 三段看板的稳定语义是 `inbox / knowledge / action`：研究对应待探索、研究发现、下一步；学习对应待学习、已掌握、复习行动；写作对应待展开、素材观点、写作行动。服务端保存稳定枚举，前端负责模板化呈现。
- 工作区链接只保存资源类型、ID、权威版本与服务端重读的标题快照，不复制笔记、书签或文件正文。每次新增引用都必须在写入事务内重新校验当前账号归属和版本，并对资源行加共享锁直到引用提交；原资源删除或失权后不能继续加入。
- 工作区免费且不创建报价或零价任务。用户从工作区主动调用研究简报、学习套件等 AI 成果时，仍按该 AI 工具单独确认计费介质；不得把后台自动 AI 调用伪装成免费工作区能力，也不得为了维持连续天数自动计费。
- 页面刷新与浏览器前进后退通过 URL 中的工作区标识恢复当前项目；列表和详情共用页面主滚动，材料选择弹窗可以独立滚动，但详情看板不得创建互相争抢滚轮的嵌套滚动区。

音视频转写与外部网页抓取不属于当前工具目录。前者需要独立的录音授权、隐私提示、媒体存储和转写质量链路；后者需要统一的 URL 安全校验、重定向约束、SSRF 防护与动态页面解析。未具备这些基础设施前，不得用普通 AI 工具入口伪装为已支持能力。

## 费用边界

- 浏览器本地工具和账号内服务免费；扫描件 OCR 等固定计算型 Worker 只使用积分；纯 AI 成果工具在每次执行前允许选择“AI 额度”或“积分”，默认引导 AI 额度，但任何一次只结算一种介质，禁止双扣。
- 免费 `service` 能力不走报价、任务或积分链路；若客户端误调报价或任务接口，服务端必须明确拒绝，不能生成零价任务伪装成免费执行。
- 选择积分时，受信任的工坊 Worker 在统一 AI Execution、Span、Gateway 和 usage 审计内注入固定 `system` 主体，用户 AI 额度不结算；选择 AI 额度时不注入该覆盖，根 Execution 按实际 Provider Token 结算用户额度，积分账本不产生预占或流水。
- 工坊 Skill 仍为 internal-only，不进入公开 Skill 执行配置；它们的可读动作名可进入用户 AI 用量目录。两种计费介质都必须由已登记 Worker 调用，客户端 body、query、Header 或 `surface` 不能伪造内部身份或声明 `system` 覆盖。
- 成果页只提供“免费存为笔记 / 打开笔记”，不从知识工坊触发笔记助手；保存后的编辑、组织和 AI 能力遵循笔记详情页自身的产品规则。
- 报价快照同时绑定工具、权威输入摘要与单一 `billing_medium`；切换介质必须生成新报价。积分动态价格只由服务端根据允许的输入特征计算，AI 额度不做伪预估，任务后在 AI 明细展示真实 Token。

计费任务使用以下闭环：

1. 服务端重新读取材料归属、版本和文件元数据，生成输入摘要与限时报价；
2. 用户确认单一计费介质后创建绑定同一输入摘要的任务；积分分支在事务内预占报价上限，AI 额度分支不触碰积分账本；
3. Worker 在租约内执行，首次外部成本发生前仍可取消排队任务；
4. 积分分支按确认价或部分成果规则结算并退差额；AI 额度分支交由根 Execution 按真实用量结算；失败且未产生可用成果时按各自规则释放；
5. 请求重放返回同一收据，同一请求号换工具或输入失败关闭。

积分流水与消费幂等的经济边界见 [积分经济](./points-economy.md)，AI 内部计费覆盖见 [模块化 AI Skills](./ai-skills.md)。

## 任务、成果与保存

- 报价、任务、任务输入、成果和保存收据分表保存。任务状态不能冒充积分终态，成果存在也不能冒充“已保存到笔记”。
- Worker 开始执行前再次校验账号限制、材料归属和资源版本；材料在报价后变化时停止任务，不使用过期快照静默生成。
- 每次领取任务必须生成独立租约令牌，并在资料解析、OCR 与 AI 生成全程按短于失联窗口的周期续租；阶段更新不能代替长调用心跳。同一进程标识再次领取也不能复用旧令牌，旧执行在租约丢失后不得保存成果、重试任务或结算积分。
- 同一工具任务的每次自动尝试使用独立且可复现的 AI Execution 请求标识，避免把重试误判为首次执行的重复请求；工坊后台调用可在 Skill 自身上限内收紧输出规模并设置异步任务时限，公开请求不能覆盖这些策略。
- Skill 除通用引用与长度校验外，还校验当前工具的固定成果结构；必需部分必须是代码围栏外真实、非空且按契约可区分的 Markdown 章节，不能用关键词堆叠或伪标题冒充。首版不合格时在同一根 Execution 内最多做一次平台修复。修复后仍不合格、引用越界或其他确定性输出契约失败直接进入终态并释放本次计费，Worker 不得再重跑整个模型任务；只有网络、Provider 临时不可用、限流和超时等基础设施失败才可进入有界自动重试。
- 排队重试与最终失败是两个用户可见状态：只有任务仍处于 `retrying` 阶段时才能提示“正在自动重试”；进入终态后必须明确本次计费已按规则释放并引导重新发起，禁止继续承诺系统会重试。
- 文档输入复用统一解析来源。临时上传与云文件都必须经过格式、大小、归属和解析状态校验，解析失败不能进入 OCR 成果。
- AI 成果保存为笔记时复用正式笔记 Service；保存收据只证明某一代保存效果曾成功完成，不证明目标笔记当前仍存在或可打开。成果页必须重新核验目标为可用、已回收或缺失：只有可用目标提供“打开笔记”，目标不可用时保留原成果并由用户显式“重新存为新笔记”。重新存储进入下一保存代次，复用既有成果而不重新执行 AI、重复计费或复用旧目标；每个代次仍由服务端固定派生幂等身份并使用带代次令牌的租约，避免并发点击创建多份笔记或旧执行覆盖新终态。
- AI 工作台由唯一的工具工作流配置声明场景、单一“处理要求”输入和预期成果。用户在同一输入框中描述问题、读者、重点、判断标准与输出格式，其内容必须作为 AI Skill 的 `question` 输入参与生成，不能只借用为成果标题；页面只提交稳定的场景 `intent`，服务端将其映射为受控内部 `instruction`，客户端不能提交第二个自由提示字段绕宽输入上限或替换成果类型。`title` 仅保留为 API 兼容字段和可选成果标题。无材料创作工具的协议输入为 `prompt`，工作台不展示资料选择器且允许零项材料，但问题必填；服务端仍按独立 Skill 和固定成果结构执行，不能根据用户措辞路由到其他工具流程。
- 研究速读包默认标记为待核验草稿；来源覆盖、冲突、未知项与部分成功必须在成果页可见，不能只用成功文案掩盖不完整材料。
- 学习套件固定包含知识框架、记忆卡片、自测题与答案；概念图谱以可编辑 Mermaid 代码块保存；内容体检只能依据所选材料中的日期、版本、冲突与证据判断风险，不得借外部常识直接宣判内容错误。
- 账号删除会先按引用顺序清理工作区推进记录、事项、资料引用和工作区，再清理工坊报价、任务、输入、成果与保存收据；具体保留期和清理批次以 Service 常量与任务测试为准。

## 本地处理与交互约束

- 全部 `browser` 工具通过统一前端注册表接入，禁止引用 HTTP、上传和工坊任务 API；新增本地工具不在工作台堆叠按工具 ID 分支。
- 全部免费 `service` 工具通过独立服务注册表接入。“知识库整理”响应只包含问题清单、健康评分等当前视图需要的派生结构信息；持续工作区响应只包含当前项目的结构化状态和资料引用元数据。两类服务不得向前端返回资料正文。
- “知识库整理”的问题清单与健康评分只评价笔记自身的可维护结构；没有建立站内引用不得被列为问题、扣分或修复建议。目录 Markdown 导出不属于整理动作，不再作为产品能力提供。
- 资料选择复用全站资源搜索，并在知识工坊中启用连续多选、类型筛选和“加入当前结果”；“全部”视图按类型取样以保持扫读效率，单类型视图使用服务端游标分页和前端虚拟列表持续加载完整结果，禁止一次请求全量。首个游标页返回权威总数后必须立即预留稳定的逻辑列表高度，后续页面只替换占位项，禁止每加载一页就扩展滚动范围；按“全部 / 笔记 / 书签 / 文件”分别保存由资源键、索引和项内偏移组成的语义锚点，切回时优先恢复同一资源，尚未加载时才按索引回退。选择父笔记目录时，前端读取权威完整子树并展开为普通笔记引用后再报价，因此材料数量上限、去重与价格仍由同一工具协议约束。整目录超过当前工具上限时必须整体拒绝并提示缩小范围，不能静默截断。
- 资料选择区使用高度稳定的已选托盘：PC 两列、移动端单列，仅允许纵向滚动且禁止横向滚动；空态与有内容共用同一占位，筛选、搜索和结果列表不得因首项选择突然位移。清空操作保持单行且在移动端满足触控高度。
- 文件类工具的对象 URL 在删除、重新处理和组件卸载时释放；文本类工具设置字符、行列组合与文件体积上限，避免同步算法耗尽页面内存。
- 表格与数据工作台以已载入数据集作为持续状态：体检在成功载入单个文件后自动生成，其他动作按各自设置显式执行；切换动作只清理上一动作的结果，不清空已载入数据。历史工具深链仍进入工作台并默认选中原动作。双文件动作最多读取两份文件且合计不超过共享协议上限；桌面使用操作轨，移动端使用单一模式选择器，均不得创建嵌套滚动容器。
- Markdown 预览复用统一内容清洗管线；Mermaid 使用 `strict` 安全级别渲染，运行时生成的 SVG 只承担图表预览与导出，不接受任意未经清洗的 HTML。
- 图片压缩与格式转换同时展示同尺寸的“处理前 / 处理后”预览、各自体积和尺寸；批量统计同样使用明确方向，部分失败逐项标记并允许调整设置后重试。
- 浏览器本地工具、账号内服务和持续工作区继续使用页面级主滚动；资料型 AI / Worker 工作台采用显式分区滚动。宽度不小于 1200px 时锁定工作台外层，资料列与设计执行列同时展示并各自纵向滚动；768–1199px 时同样锁定外层，以常驻的“选择资料 / 设计成果”两步切换一次展示一栏；小于 768px 时保留页面主滚动与常驻步骤切换，切换后回到工作区步骤起点。资料列表的回顶入口只控制该列表，在超过一个半视口且至少 720px 后出现；长距离或减少动态效果环境立即回顶，短距离可平滑滚动。所有模式都必须能到达最后一项并保留底部安全间距，分类与已选材料不得制造横向滚动区抢占手势。
- 成果页不得直接展示内部 warning code、资源 UUID、结构化 locator 或原始执行阶段；前端必须映射为用户可理解的来源类型、参与范围、可读定位和核验建议，未知值只能降级为通用说明，不能通过 `String(object)` 泄漏实现对象。
- 工坊 AI 正文的数字引用先在服务端完成来源校验，成果展示与“存为笔记”的副本再移除数字角标；代码下标、Markdown 数字链接和脚注定义保持不变。材料名称、实际读取范围与异常统一在“材料”账本中展示，不为无法交互的 `[1]` 角标增加伪 hover。
- 处理中只展示 Worker 已到达的真实里程碑与当前运行态，不按预计耗时伪造连续百分比；执行端在输入校验、资料读取、内容生成和成果保存边界写入阶段，前端按阶段呈现。后台刷新瞬时失败必须保留最后一次成功状态并有界退避重试，不能把已有任务替换成整页失败。
- 页面覆盖目录加载、空与筛选无结果、报价中、报价失效、余额不足、排队、处理中、可取消、成功、部分成功、失败、成果过期、保存中、已保存与保存失败等适用状态；持续工作区额外覆盖空列表、创建、加载、错误、进行中、暂停、完成、空材料、空看板和首条推进记录。

## 验收门禁

- 共享协议、目录、报价范围、未知字段、身份归属、版本冲突、任务租约、积分预占/结算/释放、保存幂等与账号删除有自动测试。
- 本地工具测试覆盖格式/数量/体积上限、输出像素上限、对象 URL 释放与“零网络依赖”源码契约。
- 前端至少执行类型检查、受影响测试和生产构建；视觉验收覆盖 PC/移动端、浅色/深色、窄屏顶栏、导航 hover/current、长列表滚动到底及默认/处理中/成功/部分失败状态。
- 发布前运行只读 Schema 与 Worker 门禁；真实 Provider、线上文件或线上数据库只在当前任务得到明确授权后使用。
