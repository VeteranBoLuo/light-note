# 知识工具箱

本文是轻笺知识工具箱的产品边界、执行模式、积分结算、任务成果与隐私约束的唯一规范。工具清单、输入上限和动态价格以共享协议、服务端目录和契约测试为准，不在页面或本文维护第二份可执行配置。

## 产品入口与能力分层

- PC 一级导航提供“工具箱”，并与聊天室复用同一套轻量胶囊 hover、focus 和当前态；全局搜索只在顶栏保留图标，输入框位于搜索浮层顶部。该入口代表“从资料生产成果并继续推进”的独立闭环，不另建“继续”一级入口。一级入口成立的前提是根页同时提供跨工具的恢复工作、近期活动和完整能力发现，而非只陈列一次性工具；若这些生产与回访能力被移除，工具箱应降级到更多菜单或资料模块内。
- 移动端底部一级导航为“今日｜资料｜工具箱｜待办｜聊天室”。今日页顶栏加号继续承担快速添加，工具箱不复制创建入口。只有工具箱根页显示底部一级导航；工作台和任务成果是二级页，使用顶部返回。有确定工具箱父页时返回原页，直接深链或外部历史则替换为根页，禁止用固定 `push` 制造循环返回栈。
- `phase` 只表达产品阶段，`availability.enabled` 与服务端禁用配置共同决定当前能否执行；前端不得因本地旧目录自行开放工具或回退旧价格。
- 首页先提供“从零开始”，让用户无需先收藏资料即可新建长期工作区、生成初稿，或进入笔记无法承载的结构化生产工作室；登录用户随后按“继续已有工作 → 快捷工具 → 全部工具”组织生产、回访与能力发现，访客则省略续接区。“继续已有工作”只展示有明确下一动作的活跃工作区、进行中任务和待保存成果，不是基于历史的推荐；“快捷工具”在同一区域切换用户固定的常用工具与按实际打开时间排序的最近工具，同一工具在最近视图只保留最新一次，不再用两段页面重复陈列。
- “全部工具”只读取 `availability.enabled` 的公开能力，并用唯一一套完整目录按“持续工作区、从资料生成、整理知识库、导入前处理、数据处理”分组；默认展示全部分组，顶部分组导航只负责定位而不隐藏其他分组，搜索时跨全部分组匹配，搜索与“全部 / 免费 / 积分”筛选只作用于该目录，不展示没有决策价值的工具总数或“免费数量”。分组与顺序由 `apps/web/src/config/toolbox.ts` 维护，契约测试必须保证每个启用工具在完整目录中恰好出现一次。
- 首页账号活动通过 owner-scoped 读模型获取，不返回资料正文、处理要求或成果正文。仅打开工作区时由单独写入接口节流更新 `lastOpenedAt`，不改写内容更新时间，不在 GET 中隐式写库。前端补充的工具级打开记录只在本地按当前身份保存有限的 `toolId + time`，不保存文件名、问题、材料或正文；用户固定的工具和由其组成的快捷入口同样按账号或访客身份隔离，切换身份不得串用。活动读取失败必须与真实空态区分，且不得阻断快捷入口与全部工具目录。
- 低频、通用开发类或需要专业配置的能力可以保留稳定协议、实现注册和历史任务展示，但必须设为 `availability.enabled = false`；首页不展示，直接访问工作台也失败关闭。功能重新开放前应先证明知识库场景价值与低门槛交互，不能仅因为实现已经存在就重新上架。
- 工具箱同时承担两种边界清晰的工作：持续工作区保留长期项目的上下文和推进状态；处理工具把材料变成可继续使用的独立成果。浏览器本地工具直接下载文件；AI 工具生成独立成果，用户确认后才保存为笔记。

现有能力按执行方式分为：

| 执行方式    | 能力边界                                                                                         | 用户资产 | 数据边界                                                                             |
| ----------- | ------------------------------------------------------------------------------------------------ | -------- | ------------------------------------------------------------------------------------ |
| 浏览器本地  | PDF 工作台、图片压缩与 JPG/PNG/WebP 格式转换、Word 转可编辑文字、Markdown 体检和表格与数据工作台 | 免费     | 原文件与文本不上传，不创建报价、任务或成果记录                                       |
| 账号内服务  | 研究项目、学习计划、写作工程，以及知识库结构巡检与目录索引                                       | 免费     | 工作区只保存账号内资料引用、事项和推进记录；结构巡检只返回衍生元数据，不返回正文片段 |
| AI Skill    | 灵感成稿、资料转笔记、研究简报、学习套件、概念图谱、多资料对照与内容体检                         | 积分     | 无材料工具只读取本次想法；资料型工具只读取重新校验归属与版本的轻笺材料               |
| 文档 Worker | 扫描件转文字                                                                                     | 积分     | 只处理已确认归属、格式、大小与时效的云文件或临时上传                                 |

AI 工具围绕四类持续使用场景：灵感成稿让用户从主题、目标或想法直接生产第一版；整理与研究用于形成可引用成果；学习套件与概念图谱用于理解和复习；内容体检用于发现重复、冲突、疑似过时内容与证据缺口。每类固定成果绑定一个独立的工具箱内部 Skill Profile，但复用同一套 Execution、计费与一次平台修复基础设施；资料型工具再复用资源加载与 Grounding。用户的处理要求只能调整关注点、读者、详略和表达，不能把当前成果切换成其他工具；多资料对照与内容体检等成果也不得合并成同一套提示词。

## 生产工作室与作品项目

工具箱不以单功能工具数量衡量价值，而以用户能否从空白开始、跨会话继续编辑并交付作品衡量。产品分为三层：

- 工作室（Surface）是用户看到的入口与专属编辑页面，例如 PDF、图片、演示和数据工作室；一个工作室可以承接多个明确动作。
- 工具能力（Tool）仍是一次确定的本地处理、Worker 或 AI Skill，继续承担输入、报价、审计、失败和历史兼容；工作室不得用自由问句静默切换能力或计费方式。
- 作品项目（Project）保存可持续编辑、版本化和导出的演示、工作簿、表单、看板与图示。一次性任务成果仍保留在 Artifact 中，用户确认采用后才以幂等事务写入项目新版本。

笔记库是知识正文、报告、文章和其他连续长文的唯一创作事实源，目录、正文、历史与笔记助手不得再由工具箱复制一套。笔记不能充当演示、工作簿、表单或白板的通用容器，因此这些具有独立编辑状态的作品使用项目模型。作品项目至少具有类型、标题、状态、当前版本、资料引用、可选所属工作区、最后打开时间和带 `schemaVersion` 的内容；普通编辑使用乐观版本和自动保存，命名版本、AI 应用和导入转换建立可恢复检查点。导出文件是某个版本的派生物，不是项目唯一事实源。

工作区负责目标、上下文和推进过程，作品项目负责可编辑交付物；两者可以显式关联。例如研究项目关联报告、数据图表和演示，写作工程关联主稿和发布素材。关联只保存经服务端重新校验的资源或项目引用，不复制原始正文。

首批高级生产工作室按以下顺序建设：

| ---- | ------------------ | ----------------------------------------- | -------------------------------------------------------------- | ------------------------------------------------------- |

| P1   | 表单与调研台       | 空白、模板、一句话生成                    | 编辑、手机预览、发布、响应与实时统计                           | 普通创建与统计免费，AI 题目、开放题归纳和报告消耗积分   |

报告、提案、简历和讲义属于笔记模板或未来具有分页排版能力的出版工作室；在只有 Markdown 连续正文时不得另建“文档工作室”。路演稿和课程演示是演示模板；预算表、进度表和数据看板是工作簿模板；封面、海报、知识卡片和信息图是视觉素材模板。不得为每个模板再造一套编辑引擎或首页卡片。

工作室只共享返回、保存状态、版本、费用和权限等外壳，不共享一张千篇一律的内容表单。演示使用缩略图与画布，工作簿使用工作表与公式栏，表单使用编辑/预览/响应三视图，白板使用无限画布与小地图，视觉素材使用画布、图层与尺寸变体，PDF 使用页面缩略图与处理动作，图片使用批次队列与前后对照，数据工作台使用操作轨、处理设置与结果预览。移动端可以压缩为分步流程或底部面板，但不得丢失当前作品、选择范围和处理中状态。

首页一句话可以推荐一至三个工作室，但推荐只负责导航，不能直接执行、扩大材料范围或扣费。每个固定成果继续绑定独立 Skill Profile；跨工作室操作必须由用户显式确认。AI 生成先形成预览或新版本，用户确认后才成为当前版本，局部改写必须展示影响范围。

作品项目落地时在现有 Artifact/任务链路之外建立独立的项目、版本、资料关联与导出事实源；大型版本快照和二进制导出进入受控对象存储。现有 `canSaveToNote` 逐步扩展为受控保存目标，不能让客户端提交任意目标类型。

首批作品项目统一使用 `@lightnote/shared/production-project-protocol` 作为 Project、不可变 Revision、内容 Schema 与双重乐观锁的事实源；数据库结构由 `20260830_toolbox_production_projects.sql` 维护，服务端项目事务集中在 `apps/server/util/toolbox/project.js`。演示和工作簿共享项目列表、保存状态、命名版本、恢复版本与本地冲突稿保护，但内容编辑状态必须分别遵循 `presentation/v1` 和 `workbook/v1`，不得在客户端互相强制转换。已经创建的 `document/v1` 项目保留兼容访问、编辑与导出，首页不再提供新建入口，旧深链也不得因产品收口而丢失用户数据。

`presentation/v1` 在兼容旧版标题、正文和版式字段的同时，以有序元素列表保存文本、形状和图片的几何与样式；列表顺序就是图层顺序，插入、移动、缩放和样式调整必须写入同一项目快照，PPTX、PDF 与图片导出也必须消费该快照，避免编辑画布与交付结果分叉。`workbook/v1` 的稀疏单元格同时保存显示样式，工作表视图保存冻结行列；范围选择本身是临时界面状态，但批量格式、行列结构调整和公式引用变化必须持久化，并由 XLSX 导出读取同一快照。

已接受的作品修订按不可变记录保留到账号删除，不做静默自动清理；服务端以项目和账号累计快照字节配额约束增长，超限时拒绝新修订并由客户端继续保留本地草稿。普通自动保存只有在双重 CAS 校验通过且内容 hash 与当前修订一致时才作为 no-op 返回；命名版本与恢复版本即使内容相同也必须留下新修订。配额数值和保留策略标识以 `apps/server/util/toolbox/project.js` 为事实源。

模板只是同一编辑引擎的起始内容，统一登记在 `apps/web/src/config/productionProjectStarters.ts`；模板创建时保存稳定 `templateId`，后续内容仍是普通项目版本。首批公开导入边界为：演示支持 Markdown/纯文本提纲，工作簿支持 CSV、TSV、JSON 和 XLSX（保留多工作表与公式）。未实现可逆结构解析的格式不得伪装成可编辑导入，例如演示工作室当前只导出 PPTX，不宣称支持 PPTX 反向导入。导出文件由当前 Revision 派生，PPTX、XLSX 必须生成真实 OOXML 包，不能用扩展名包装 HTML、JSON 或纯文本；旧版文档项目原有导出能力仅用于兼容既有项目。

工具任务的 Markdown Artifact 只通过正式笔记 Service“存为笔记”，不再创建另一套连续正文项目。保存后的目录、正文编辑和助手能力全部遵循笔记详情规则；演示、工作簿等结构化成果若要从 Artifact 创建作品项目，必须使用明确目标类型、稳定幂等键和独立的受控转换协议。

## 工作室合并规则

- 只有共享主要输入资产、能够复用同一编辑状态且允许连续处理的能力才合并为一个工作室。历史任务仍保存原 `toolId`，旧深链映射到规范工作室的对应模式，不改写历史记录。
- PDF 工作台统一承接页面整理、图片转 PDF、PDF 转图片和普通文字提取；扫描件 OCR 可以在同一工作室被发现，但仍是独立积分 Worker，不得伪装为本地免费能力。
- 图片工作台统一承接压缩和 JPG/PNG/WebP 转换，后续扩展批量尺寸、裁剪旋转、水印、重命名和 EXIF 清理；抠图、智能放大和背景替换属于独立积分能力。
- 表格体检、清洗、校验、对比、合并拆分、脱敏、透视和图表共用“表格与数据工作台”；浏览器 SQL 保持独立且暂不公开，只有在能够复用同一数据集状态与安全执行边界后再评估合并。Markdown 转换、体检、Frontmatter 和引用处理进入 Markdown 出版台；文本对比、批处理、正则和结构化文本进入文本实验室。
- AI 资料转笔记、研究简报、学习套件、概念图谱、多资料对照和内容体检可以共用“知识研究台”外壳，但底层 Skill、报价、固定成果结构和失败语义保持独立。
- 连续长文不从笔记库拆出同构工作室；图片像素处理不与结构化图示合并；表单不与工作簿合并；通用看板不与具有稳定知识推进语义的研究、学习、写作工作区合并。

## 持续工作区

- 研究项目、学习计划与写作工程是同一持久化引擎的三种业务模板，不是三套互相复制的页面或数据模型。模板只改变引导文案、三段看板的语义和默认工作方式；材料、事项、推进记录、状态与权限边界保持一致。
- 一个工作区由目标、目标日期、当前下一步、账号内资料引用、三段事项和推进记录组成。结束一次推进时至少记录“本次进展”或“下一步”；推进记录按日期形成连续天数，但连续天数只是反馈，不产生积分或强制签到。
- 三段看板的稳定语义是 `inbox / knowledge / action`：研究对应待探索、研究发现、下一步；学习对应待学习、已掌握、复习行动；写作对应待展开、素材观点、写作行动。服务端保存稳定枚举，前端负责模板化呈现。
- 工作区链接只保存资源类型、ID、权威版本与服务端重读的标题快照，不复制笔记、书签或文件正文。每次新增引用都必须在写入事务内重新校验当前账号归属和版本，并对资源行加共享锁直到引用提交；原资源删除或失权后不能继续加入。
- 工作区免费且不创建报价或零价任务。用户从工作区主动调用研究简报、学习套件等 AI 成果时，仍按该 AI 工具单独报价；不得把后台自动 AI 调用伪装成免费工作区能力，也不得为了维持连续天数自动扣积分。
- 页面刷新与浏览器前进后退通过 URL 中的工作区标识恢复当前项目；列表和详情共用页面主滚动，材料选择弹窗可以独立滚动，但详情看板不得创建互相争抢滚轮的嵌套滚动区。

音视频转写与外部网页抓取不属于当前工具目录。前者需要独立的录音授权、隐私提示、媒体存储和转写质量链路；后者需要统一的 URL 安全校验、重定向约束、SSRF 防护与动态页面解析。未具备这些基础设施前，不得用普通 AI 工具入口伪装为已支持能力。

## 费用边界

- 浏览器本地工具和账号内服务免费；AI Skill 与文档 Worker 按积分报价。工具箱页面只展示与本次工具执行有关的免费/积分信息，不展示笔记助手等其他模块的 AI 额度。
- 免费 `service` 能力不走报价、任务或积分链路；若客户端误调报价或任务接口，服务端必须明确拒绝，不能生成零价任务伪装成免费执行。
- 积分 AI 工具仍经过统一 AI Execution、Span、Gateway 和 usage 审计，但由受信任的工具箱 Worker 使用 `system` 计费策略并标记固定系统主体；公开请求不能提交或伪造该覆盖。
- 工具箱内部 Skill 不进入公开 Skill 配置或用户 AI 动作目录，只接受进程内已登记的 Worker 调用者和 `system` 策略同时成立的执行；客户端 body、query、Header 或 `surface` 均不能声明该身份，防止绕过积分报价直接调用。
- 成果页只提供“免费存为笔记 / 打开笔记”，不从工具箱触发笔记助手；保存后的编辑、组织和 AI 能力遵循笔记详情页自身的产品规则。
- 动态价格只由服务端报价器根据工具、材料数量、成果详略与其他允许的输入特征计算。页面只展示报价响应，不写死计算公式。

积分任务使用以下闭环：

1. 服务端重新读取材料归属、版本和文件元数据，生成输入摘要与限时报价；
2. 用户确认后事务内预占报价上限，并创建绑定同一输入摘要的任务；
3. Worker 在租约内执行，首次外部成本发生前仍可取消排队任务；
4. 成功按确认价结算，部分成功按实际规则结算并退回差额，失败或未产生可用成果释放预占；
5. 请求重放返回同一收据，同一请求号换工具或输入失败关闭。

积分流水与消费幂等的经济边界见 [积分经济](./points-economy.md)，AI 内部计费覆盖见 [模块化 AI Skills](./ai-skills.md)。

## 任务、成果与保存

- 报价、任务、任务输入、成果和保存收据分表保存。任务状态不能冒充积分终态，成果存在也不能冒充“已保存到笔记”。
- Worker 开始执行前再次校验账号限制、材料归属和资源版本；材料在报价后变化时停止任务，不使用过期快照静默生成。
- 每次领取任务必须生成独立租约令牌，并在资料解析、OCR 与 AI 生成全程按短于失联窗口的周期续租；阶段更新不能代替长调用心跳。同一进程标识再次领取也不能复用旧令牌，旧执行在租约丢失后不得保存成果、重试任务或结算积分。
- 同一工具任务的每次自动尝试使用独立且可复现的 AI Execution 请求标识，避免把重试误判为首次执行的重复请求；工具箱后台调用可在 Skill 自身上限内收紧输出规模并设置异步任务时限，公开请求不能覆盖这些策略。
- Skill 除通用引用与长度校验外，还校验当前工具的固定成果结构；必需部分必须是代码围栏外真实、非空且按契约可区分的 Markdown 章节，不能用关键词堆叠或伪标题冒充。首版不合格时在同一根 Execution 内最多做一次平台修复。修复后仍不合格、引用越界或其他确定性输出契约失败直接进入终态并释放积分，Worker 不得再重跑整个模型任务；只有网络、Provider 临时不可用、限流和超时等基础设施失败才可进入有界自动重试。
- 排队重试与最终失败是两个用户可见状态：只有任务仍处于 `retrying` 阶段时才能提示“正在自动重试”；进入终态后必须明确积分已释放并引导重新发起，禁止继续承诺系统会重试。
- 文档输入复用统一解析来源。临时上传与云文件都必须经过格式、大小、归属和解析状态校验，解析失败不能进入 OCR 成果。
- AI 成果保存为笔记时复用正式笔记 Service；保存收据只证明某一代保存效果曾成功完成，不证明目标笔记当前仍存在或可打开。成果页必须重新核验目标为可用、已回收或缺失：只有可用目标提供“打开笔记”，目标不可用时保留原成果并由用户显式“重新存为新笔记”。重新存储进入下一保存代次，复用既有成果而不重新执行 AI、重复扣积分或复用旧目标；每个代次仍由服务端固定派生幂等身份并使用带代次令牌的租约，避免并发点击创建多份笔记或旧执行覆盖新终态。
- AI 工作台由唯一的工具工作流配置声明场景、单一“处理要求”输入和预期成果。用户在同一输入框中描述问题、读者、重点、判断标准与输出格式，其内容必须作为 AI Skill 的 `question` 输入参与生成，不能只借用为成果标题；页面只提交稳定的场景 `intent`，服务端将其映射为受控内部 `instruction`，客户端不能提交第二个自由提示字段绕宽输入上限或替换成果类型。`title` 仅保留为 API 兼容字段和可选成果标题。无材料创作工具的协议输入为 `prompt`，工作台不展示资料选择器且允许零项材料，但问题必填；服务端仍按独立 Skill 和固定成果结构执行，不能根据用户措辞路由到其他工具流程。
- 研究速读包默认标记为待核验草稿；来源覆盖、冲突、未知项与部分成功必须在成果页可见，不能只用成功文案掩盖不完整材料。
- 学习套件固定包含知识框架、记忆卡片、自测题与答案；概念图谱以可编辑 Mermaid 代码块保存；内容体检只能依据所选材料中的日期、版本、冲突与证据判断风险，不得借外部常识直接宣判内容错误。
- 账号删除会先按引用顺序清理工作区推进记录、事项、资料引用和工作区，再清理工具箱报价、任务、输入、成果与保存收据；具体保留期和清理批次以 Service 常量与任务测试为准。

## 本地处理与交互约束

- 全部 `browser` 工具通过统一前端注册表接入，禁止引用 HTTP、上传和工具箱任务 API；新增本地工具不在工作台堆叠按工具 ID 分支。
- 全部免费 `service` 工具通过独立服务注册表接入。“知识库整理”响应只包含当前视图需要的派生结构信息，并在同一工作台内切换“查看问题 / 生成目录”；持续工作区响应只包含当前项目的结构化状态和资料引用元数据。两类服务不得向前端返回资料正文。
- 资料选择复用全站资源搜索，并在工具箱中启用连续多选、类型筛选和“加入当前结果”；“全部”视图按类型取样以保持扫读效率，单类型视图使用服务端游标分页和前端虚拟列表持续加载完整结果，禁止一次请求全量。虚拟窗口必须绑定工具箱页面的根滚动容器，不能让资源列表再次接管滚轮。选择父笔记目录时，前端读取权威完整子树并展开为普通笔记引用后再报价，因此材料数量上限、去重与价格仍由同一工具协议约束。整目录超过当前工具上限时必须整体拒绝并提示缩小范围，不能静默截断。
- 资料选择区使用固定高度的已选托盘：空态展示选择说明，选择后在同一位置展示可横向浏览的资料摘要；筛选、搜索和结果列表的文档坐标及页面总高度不得因首项选择突然改变，清空操作保持单行且在移动端满足触控高度。
- 文件类工具的对象 URL 在删除、重新处理和组件卸载时释放；文本类工具设置字符、行列组合与文件体积上限，避免同步算法耗尽页面内存。
- 表格与数据工作台以已载入数据集作为持续状态：体检在成功载入单个文件后自动生成，其他动作按各自设置显式执行；切换动作只清理上一动作的结果，不清空已载入数据。历史工具深链仍进入工作台并默认选中原动作。双文件动作最多读取两份文件且合计不超过共享协议上限；桌面使用操作轨，移动端使用单一模式选择器，均不得创建嵌套滚动容器。
- Markdown 预览复用统一内容清洗管线；Mermaid 使用 `strict` 安全级别渲染，运行时生成的 SVG 只承担图表预览与导出，不接受任意未经清洗的 HTML。
- 图片压缩与格式转换同时展示同尺寸的“处理前 / 处理后”预览、各自体积和尺寸；批量统计同样使用明确方向，部分失败逐项标记并允许调整设置后重试。
- 三类工具箱页面复用一个纵向滚动基线，页面根节点是唯一滚动所有者；长文件列表必须能滚动到最后一项并保留底部安全间距。桌面双栏只负责布局，不再给资源列创建独立滚动容器；移动端分类胶囊自动换行，不制造横向滚动区抢占手势。
- 成果页不得直接展示内部 warning code、资源 UUID、结构化 locator 或原始执行阶段；前端必须映射为用户可理解的来源类型、参与范围、可读定位和核验建议，未知值只能降级为通用说明，不能通过 `String(object)` 泄漏实现对象。
- 工具箱 AI 正文的数字引用先在服务端完成来源校验，成果展示与“存为笔记”的副本再移除数字角标；代码下标、Markdown 数字链接和脚注定义保持不变。材料名称、实际读取范围与异常统一在“材料”账本中展示，不为无法交互的 `[1]` 角标增加伪 hover。
- 处理中只展示 Worker 已到达的真实里程碑与当前运行态，不按预计耗时伪造连续百分比；执行端在输入校验、资料读取、内容生成和成果保存边界写入阶段，前端按阶段呈现。后台刷新瞬时失败必须保留最后一次成功状态并有界退避重试，不能把已有任务替换成整页失败。
- 页面覆盖目录加载、空与筛选无结果、报价中、报价失效、余额不足、排队、处理中、可取消、成功、部分成功、失败、成果过期、保存中、已保存与保存失败等适用状态；持续工作区额外覆盖空列表、创建、加载、错误、进行中、暂停、完成、空材料、空看板和首条推进记录。

## 验收门禁

- 共享协议、目录、报价范围、未知字段、身份归属、版本冲突、任务租约、积分预占/结算/释放、保存幂等与账号删除有自动测试。
- 本地工具测试覆盖格式/数量/体积上限、输出像素上限、对象 URL 释放与“零网络依赖”源码契约。
- 前端至少执行类型检查、受影响测试和生产构建；视觉验收覆盖 PC/移动端、浅色/深色、窄屏顶栏、导航 hover/current、长列表滚动到底及默认/处理中/成功/部分失败状态。
- 发布前运行只读 Schema 与 Worker 门禁；真实 Provider、线上文件或线上数据库只在当前任务得到明确授权后使用。
