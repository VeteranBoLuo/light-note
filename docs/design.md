# 轻笺设计文档

## 品牌色

轻笺使用 4 种资源语义色，分别对应 4 大功能模块：

| 模块 | 色值      | CSS 变量                    | 用途                   |
| ---- | --------- | --------------------------- | ---------------------- |
| 书签 | `#615ced` | `--resource-bookmark-color` | 书签卡片、图标、强调色 |
| 笔记 | `#00a884` | `--resource-note-color`     | 笔记卡片、编辑区辅助色 |
| 文件 | `#ff8a00` | `--resource-file-color`     | 文件卡片、上传状态     |
| 标签 | `#ec4899` | `--resource-tag-color`      | 标签圆点、标签选择     |

- TS 配置：`src/config/resourceColor.ts`
- CSS 变量：`src/assets/css/theme.less`

待办属于行动对象而不是资源类型，独立使用天空蓝 `#0ea5e9`（`--todo-accent-color`）。该颜色用于待办页头、搜索类型标识和普通待办强调态；逾期、高优先级、完成与低优先级仍分别使用危险色、危险色、成功色与中性色，不被待办模块色覆盖。资源中心作为四类资源的聚合入口继续使用中性色。

官网封面渐变大字使用 4 色渐变过渡。

## 品牌标识

- 主标识名为“笺结”，以抽象纸带的循环、连接和聚合表达个人知识空间。
- 标识中的四向转折是保证小尺寸稳定与视觉平衡的几何骨架，不对应产品模块数量，也不随功能增减而改变。
- 浏览器 favicon 使用透明底彩色标识，外轮廓约占画布 90.6%，以补偿中心负形造成的视觉收缩；Apple Touch 与 PWA 图标使用浅色完整底板并保留系统裁切安全区；单色环境使用同一负形轮廓。
- 标识只使用品牌紫的明度层次，不套用书签、笔记、文件等资源语义色，避免产生功能数量或模块映射。

## 主题系统

### 切换机制

- 通过 `data-theme` 属性挂载在 `<html>` 上实现主题切换
- 切换逻辑在应用层控制，支持亮色/暗色

### 主题变量

主题变量定义在 `src/assets/css/theme.less`，主要分为几类：

**文本色：**

| 变量                    | 亮色 | 暗色 | 用途     |
| ----------------------- | ---- | ---- | -------- |
| `--text-color`          | 深灰 | 浅灰 | 正文     |
| `--sub-text-color`      | 中灰 | 中灰 | 辅助文字 |
| `--disabled-text-color` | 浅灰 | 深灰 | 禁用态   |

**背景色：**

| 变量                          | 亮色         | 暗色      | 用途                           |
| ----------------------------- | ------------ | --------- | ------------------------------ |
| `--background-color`          | 白           | 深黑      | 页面背景                       |
| `--surface-page-bg`           | `#ffffff`    | `#1c1e24` | 资源页画布，兼容映射到页面背景 |
| `--workspace-panel-bg-color`  | `#f6f7fb`    | `#252933` | 筛选区、内容工作区             |
| `--card-background`           | `#ffffff`    | `#2e333e` | 内容卡片、表单和表格容器       |
| `--surface-raised-background` | 白到淡紫渐变 | 蓝灰渐变  | 概览、搜索入口等提升表面       |
| `--hover-background`          | 浅灰         | 稍亮黑    | hover 态                       |

资源页的大块筛选区、内容工作区统一使用 `--workspace-panel-bg-color`。它位于页面底色与内容卡片底色之间，用来建立稳定的三层表面层级；业务页面不得再用卡片背景色直接充当整块工作区背景。

同一视觉区域最多使用一层大面积工作区底色；工作区中的资源卡片必须使用 `--card-background`，不能透明继承父级颜色。概览和入口类内容可使用 `--surface-raised-background`，普通内容卡片不滥用渐变。

暗色主题中的云文件图片和视频缩略图使用轻量内缩的中性预览底板，避免大面积纯白内容直接贴住暗色卡片边缘；浅色主题保持原有满幅预览。

**边框色：**

| 变量                      | 用途                            |
| ------------------------- | ------------------------------- |
| `--card-border-color`     | 卡片边框、分割线                |
| `--surface-border-color`  | 新资源页与 BCard 的通用表面边框 |
| `--surface-card-shadow`   | 普通卡片的轻阴影                |
| `--surface-raised-shadow` | 提升表面的轻阴影                |

**编写原则：**

- 不在业务组件中硬编码亮色/暗色两套样式
- 颜色、背景、边框、阴影优先使用主题变量
- 新增变量请在 `theme.less` 中统一添加
- 状态与层级不能只靠 `color-mix()` 混色或阴影表达：移动浏览器与 App 的共享移动基线会把混色稳定化、把混色阴影回退成透明，因此选中、今天、激活、错误等状态必须另有实色描边、实心圆点/圆底、图标或明确文字色，淡混色只作为锦上添花。机制与自检方法见 `docs/development.md` 的「移动浏览器 / Android App 共享渲染基线」

## 组件体系

### 基础组件（BComponent）

项目维护了一套自研基础组件，前缀为 `B`，位于 `src/components/base/BasicComponents/`：

| 组件       | 作用     | 关键特性                               |
| ---------- | -------- | -------------------------------------- |
| `BTable`   | 表格     | 内置分页、排序、自定义列宽             |
| `BModal`   | 弹窗     | 支持深浅主题、移动端适配               |
| `BButton`  | 按钮     | 支持多种风格                           |
| `BCard`    | 主题卡片 | `card`、`panel`、`raised` 三种表面层级 |
| `BTabs`    | 页签切换 | `line`、`pill`、`segment` 三种形态     |
| `BSelect`  | 下拉选择 | Teleport 到 body，自动翻转方向         |
| `BTooltip` | 工具提示 | Teleport 到 body，自适应方向           |
| `BMessage` | 消息提示 | 全局消息                               |
| `BList`    | 列表     | 侧边栏 + 筛选 + 分类管理               |

### UI 组件库

**以自研 B 系列组件为主，Ant Design Vue 正在逐步淘汰（不新增 `a-*`，存量改到哪替到哪，最终完全移除）。**
**有 B 组件的场景禁止使用原生 HTML 控件。** 常用映射：

- 表格 `BTable`（禁 `a-table`）
- 按钮 `b-button`（禁原生 `<button>`、`a-button`）
- 下拉选择 `BSelect`（禁原生 `<select>`、`a-select`）
- 输入框 `BInput`（禁原生 `<input>`、`a-input`）
- 确认弹窗 `Alert.alert()`（禁 `Modal.confirm`）
- 业务弹窗 `BModal`（禁 ant-design-vue 的 `Modal`）
- 气泡 `BPopover` / 提示 `BTooltip` / 消息 `BMessage` / 加载 `BLoading`
- 确无对应 B 组件才用原生，并在自检说明里注明原因

### 后台数据页布局

- 操作日志、API 日志、用户管理、用户反馈、图片管理、AI 调用监控等“标题 + 可选指标 + 工具栏 + 表格”页面统一使用 `src/components/admin/AdminDataPage.vue`。
- 指标区按业务价值选配，禁止为凑固定卡片数量展示当前分页区间、分页尺寸等重复信息；列表型页面应优先保证表格可视高度。
- 页面表格使用 `BTable` 的 `fill` 模式填满剩余空间，由表格正文承担单一纵向滚动。持续增长的后台列表使用虚拟渲染与服务端游标增量加载，不保留占据表格高度的分页器。
- 图片等大数据列表必须分页或使用虚拟列表，禁止一次性请求或渲染全部记录。虚拟渲染只负责控制 DOM 数量，数据层仍必须分批加载。

### 图标体系

- 新增或修改静态 UI 图标时，唯一配置入口是 `src/config/icon.ts`，统一由 `SvgIcon` 渲染。
- 业务组件只负责图标的使用场景、交互和布局，不保存 SVG 路径；不得为单个静态图标创建专用 Vue 组件。
- 新图标默认使用 `24 × 24` 的 `viewBox`、一致的视觉尺寸以及圆角端点；同组操作图标应保持相近的描边粗细和留白。
- 单色图标优先使用 `currentColor`，通过品牌色、资源语义色或危险操作色控制外观，并自动兼容深浅主题。
- 编辑等普通操作使用品牌主色；删除等危险操作使用危险语义色，但颜色应由按钮或容器控制，不固化在共享 SVG 中。
- 多色品牌标识、favicon、用户上传内容及服务端动态图标可以保留原始颜色，不纳入单色图标约束。
- 只有图标组合具备独立的交互、状态或多形态布局时才封装组件；纯图形复用应通过 `icon.ts` 完成。
- 数据可视化、关系图、复杂插画以及运行时数据驱动的 SVG 不属于静态 UI 图标，按对应组件的设计目标实现。
- 书签、笔记、云空间、标签四类通用资源图标使用轻笺自研的 `icon.resource` 图标组；统一为 `24 × 24` 圆角线性轮廓和 `currentColor`，禁止再以第三方彩色图标替代通用资源语义。
- 网站 favicon 统一通过 `BookmarkFavicon.vue` 展示。亮暗主题都保持透明容器并让原图直出，不铺统一底色、不反色、不描边，优先完整保留站点品牌色和线上一致的自然观感。

### 空状态与加载态

- 列表页、卡片流、搜索结果使用结构化骨架屏（skeleton）
- 禁止仅用纯色块或空白区域占位

### 滚动条

- 内容区的滚动容器（侧边目录、资源列表、卡片流、抽屉内长列表等）统一加 `v-auto-scrollbar` 指令：滚动时滑块出现，停止滚动后缓慢淡出。指令在 `config/globalDirect.ts`，配套样式是 `assets/css/common.less` 的 `.auto-scrollbar`。
- **滚动条槽位必须恒定，显隐只切换滑块颜色。** 禁止用切换 `::-webkit-scrollbar` 宽度（例如 `0 → 3px`）的方式做显隐：宽度变化会挤压内容宽度，鼠标移入或滚动时列表右侧内容会横向抖动。需要预留槽位时用 `scrollbar-gutter: stable`。
- 不要给单个组件重复实现"正在滚动"的定时器逻辑，一律复用该指令；确有特殊滚动语义时在自检说明里注明原因。
- 内容与滚动条之间保留呼吸位（约 4px），并让容器内的选中态高亮、列表项右边缘对齐到同一条竖线，不要让高亮块贴着滑块。
- 页面主滚动、浏览器默认滚动条沿用 `assets/css/browser.less` 的全局样式，不在本约定内；因此过渡期会同时存在两种滚动条表现，迁移按"改到哪加到哪"推进。

## 响应式设计

### 断点体系

断点定义在 `src/store/bookmark.ts`：

| 设备     | 判断                       | 使用方式                                          |
| -------- | -------------------------- | ------------------------------------------------- |
| 手机     | `bookmark.isMobile`        | `<768px`，简化布局、堆叠排列                      |
| 平板     | `bookmark.isTablet`        | `768–1199px`；或 `1200–1399px` 且为粗指针触控设备 |
| 桌面     | `bookmark.isDesktop`       | 其余宽度，保留桌面导航                            |
| 紧凑排版 | `bookmark.isCompactLayout` | `<1400px`，仅收紧密度，不改变设备类型             |

判断依据：布局优先看可用宽度；`1200–1399px` 只有在 `(pointer: coarse)` 时才算平板。不能把 1400px 以下一律判成平板，否则 1366px 笔记本和桌面窄窗口会错误切换为触控导航。

### 布局策略

- 不新增 UA 判断或重复断点
- 移动端和桌面端使用各自的路由映射（`src/App.vue` 中的 `phoneReplaceMap` / `deskReplaceMap`）
- 新增页面入口需同时检查 PC 和移动端路由配置

### 页面宽度语义

- 工作台、书签、笔记库、云空间、资源中心、书签管理、标签管理、回收站等高信息密度工作区应使用可用宽度，仅保留响应式页面边距；禁止再通过 1280px、1540px 等固定内容上限制造大面积两侧留白。
- 使用 `ResourcePageShell` 的工作区显式设置 `layout="workspace"`；新增、编辑、设置、详情和阅读类页面沿用默认 `layout="contained"`，保证表单与长文本的阅读宽度。
- 桌面端一级工作区（资源中心、书签管理、标签管理等）页头统一显示语义色圆点、标题和说明，不放返回按钮；返回按钮只用于新增、编辑、详情等二级页面。移动端可由独立顶栏保留返回能力。
- 卡片流通过 `auto-fill` / `auto-fit` 配合合理的卡片最小宽度自动增减列数，不按设备型号或某个分辨率写死列数；列表、表格及固定侧栏后的主内容区应使用 `minmax(0, 1fr)` 吃满剩余空间。
- 宽屏卡片流应根据实际内容容器同步放大卡片最小宽度，避免只增加列数而把卡片长期压在最小尺寸；可使用容器查询单位配合 `clamp()`，并让真实内容与骨架屏共用同一网格规则。2560 CSS 视口下书签、笔记和文件卡片可控制在约 6 列，作为视觉验收参考而非固定断点。
- 桌面端视觉验收至少覆盖 1280、1440、1920、2560 CSS 视口宽度，并记录 `window.innerWidth`；物理屏幕尺寸、系统缩放和截图像素不能代替 CSS 视口判断。
- 2560 CSS 视口下工作区应保持正常页面边距、无横向滚动，并通过增加卡片列数或扩大主内容区利用空间；表单和阅读页不要求铺满。
- 桌面端 AI 助手普通抽屉使用 `clamp(480px, 28vw, 720px)` 随视口渐进加宽，保证 1280/1440 下不挤占内容、1920/2560 下不过窄；移动端继续全屏，最大化模式保持独立的全屏布局。
- AI 助手在 1280～1470 CSS 视口下采用紧凑阅读密度：桌面端推荐问题保持约 30px 的单行最小高度并允许长问题换行，用户提问气泡使用约 10px 的垂直内边距，来源卡片保持约 54px；移动端推荐问题与确认、选择操作仍保留至少 40～44px 的触控高度，不为追求紧凑牺牲操作安全。

### 移动端与中等宽度注意

- 移动端页面统一使用三级层级：一级页使用共享顶栏与底部导航；共享顶栏左侧头像是「我的」的固定一级入口，底栏为「今日｜资料｜AI｜待办｜聊天室」，AI 保持中间强调。头像可聚合成长升级和 App 新版本红点，在个人中心使用实色描边标识当前入口；二级页仍用 `MobileTopBar` 的返回键、居中标题和最多两个右侧动作。编辑/创建页使用二级页顶栏，并把提交动作放进 `MobileStickyActionBar`。页面不要再各自复制 56px 顶栏或悬浮底栏。
- 高频扫描列表统一使用 `MobileListSurface` 包裹 `MobileListRow`：一个外层实色描边与圆角，行间只用分隔线，禁止每一行再做独立投影卡片。资源图标、标题/摘要和右侧操作分别使用 leading/body/trailing 槽位；复杂行最小高度 82px，普通行最小高度 68px。
- 移动端行级“更多”、筛选和批量入口统一使用底部 `MobilePageActionsDrawer`；动作标题需说明当前对象，危险动作放在分隔线之后并使用实色危险描边/底色，执行删除仍需 `Alert.alert()` 二次确认。直接动作只保留高频、安全且结果明确的操作。
- 批量态顶栏使用“取消 / 已选数量 / 全选”，执行按钮固定在 `MobileStickyActionBar`；底栏必须预留 `safe-area-inset-bottom`，正文同时增加对应底部留白，禁止让最后一行被遮住。
- 短提示、容量说明和引导文案使用 `MobileNoticeStrip`，不再为了单行提示创建带投影的大卡片。移动端布局 Token 统一维护在 `assets/css/theme.less` 的 `--mobile-*` 变量族，业务组件只在确有语义差异时局部覆盖。
- 移动端状态必须经过 `html.light-note-mobile-rendering` 基线验收：选中、当前、未读、逾期、完成、危险和警告至少同时具备实色描边、圆点/图标或明确文字色之一，不能只依赖 `color-mix()`、透明度、阴影或中间字重。禁止新增 Android 专属视觉补丁。
- 社区客厅一级入口不得先渲染访问申请/项目介绍卡再切换工作区。首个请求期间使用与“会话头 + 消息 + 输入区”同构的单栏骨架；成功后原位替换，维护或失败只在同一工作区显示重连。冷启动期只展示 `general / 轻笺聊天室`：桌面不放频道侧栏，移动端不放顶部频道标签，公告使用通知中心或流内置顶，新手问答、技巧与功能想法共用一个消息流。只有达到方案定义的活跃与信息淹没阈值才增加第二房间，底层房间数组可以保留但不能提前暴露空频道。公共模式下登录用户直接进入并发言，游客进入同一公开消息工作区但输入区替换为 `BButton` 登录/注册引导，不显示回复、举报、屏蔽或个人未读。消息头像展示用户公开头像，存在已佩戴框时用 `AvatarFramePreview` 叠加，不能把头像框素材当头像本身；纯文本正文只用 Vue 文本插值，回复引用有实色左边框。通知深链定位的消息必须同时使用实色描边和明确的“回到最新消息”动作，不能只靠阴影或滚动位置表达；目标不可见时回到最新消息。移动文本输入由共享壳根据 `visualViewport` 保持输入区位于软键盘上方并暂时隐藏底栏。桌面会话头用“实时同步 / 实时重连中 / 前台自动刷新”明确表达传输状态，并同时使用实心圆点与文字，不能只靠颜色或动画；移动端可隐藏这段次要文案。实时或前台刷新失败都保留旧消息，不清空列表、不抢滚动位置。
- 紧急只读在消息列表顶部使用实色警示描边、图标和明确文字，输入区原位替换为“历史可读、发言暂停”状态，不使用空白、灰掉按钮或整页维护页表达。登录用户在只读期间不显示“回复”，但消息更多菜单仍保留举报和屏蔽，已有图片继续可查看。
- 聊天消息行保留直接“回复”，他人消息的低频治理动作收进 `BActionMenu`；举报使用 `BModal + BSelect + BInput`，屏蔽使用 `Alert.alert()` 二次确认，顶部“屏蔽管理”可解除屏蔽。移动端更多按钮与弹窗操作保持可触达，不能把长按作为唯一入口。屏蔽后重新读取服务端权威列表；实时移除事件和低频安全刷新都必须能移除已被 Root 隐藏的消息，不能只做永不删除的增量合并。
- Root 社区准入页桌面使用 `AdminDataPage + BTable` 展示申请与成员双状态，移动端改用 `MobileListSurface + MobileListRow`，不压缩宽表。待审核、已通过、已拒绝以及待确认规则、已加入、已撤销、已封禁均使用实色 `BChip`；通过、拒绝和撤销使用 `BModal + BInput + BButton`，拒绝/撤销原因必填，移动操作按钮保持至少 42px 高。
- Root 消息审核页沿用同一响应式后台结构，只展示举报提交时的必要证据快照，不提供无目的漫游聊天记录。待处理、已处置、已驳回与消息可见/已隐藏使用实色 `BChip`；处置弹窗用 `BSelect` 选择无需处置、隐藏、禁言或封禁，所有动作原因必填，官方安全账号只允许“无需处置”。
- 同一 Root 审核页必须显示数据库权威的发言运行状态卡，“正常发言 / 紧急只读 / 环境级只读 / 消息未开启”均使用实色 `BChip`。切换使用 `BModal + BInput + BButton`，原因必填；环境级只读时恢复按钮必须禁用并说明原因。
- 移动端视觉回归至少覆盖 320、375、430 CSS 像素宽度及真实平板宽度、浅色/深色主题；检查 44px 触控高度、长标题省略、底部安全区、抽屉关闭与系统返回，并在相同 CSS 视口下对照移动浏览器与 Debug App。电脑可使用 `?renderProfile=mobile` 快速预览。
- 弹窗、抽屉、下拉等浮层避免遮挡、滚动穿透
- Android App 的底部一级页不形成可回退的页签历史；一级页返回只把任务移到后台并保留 WebView 实例，再次打开恢复原任务，不结束进程或重新播放开屏。成长页的概览、任务、成就和资产四个内容 Tab 切换后统一回到页面顶部，带目标锚点的入口不受影响；AI 消息区继续按会话规则定位到最新消息。下拉刷新只在可滚动内容位于顶部时接管纵向手势，并保留“下拉 / 松开 / 刷新中”三态反馈。刷新反馈按触发方式分工，同一次刷新不在两处表达：手势下拉用跟手的胶囊指示器，静默刷新（回到前台的陈旧刷新、切标签一类的软刷新）用页面顶部那条全局进度条。两者都只有一处实例：胶囊由 `MobileAppShell` 渲染在顶栏正下方的定位槽里（不能挂在各页内容区 —— 内容区顶边会随资源 Tab 的有无上下移动，同一手势在不同模块弹出的高度就会差一个 Tab）；进度条复用 `App.vue` 里既有的 `BLoading bar`（视口级 fixed，PC 与移动端同一位置），由 `useGlobalRefreshBar` 汇总各页状态驱动。任何静默刷新都不得进 loading、不闪骨架屏、不清空列表，失败时保留旧数据并且不打扰用户；批量选择中、左滑面板展开、重命名或上传进行中一律不刷。
- 关系图等高密度桌面可视化在手机端应改成可扫描的列表与渐进披露，不直接压缩复刻画布；知识地图使用“主题列表 → 底部主题抽屉”，主题内容优先于相关主题，类型切换使用带数量的 `BTabs`
- 移动端知识地图页头只保留标签主题与已整理资源两项紧凑概览；关系强度、隐藏孤立标签和重置归入筛选抽屉，避免常驻工具栏挤压主列表
- 卡片左滑操作使用“横向拖动后露出右侧操作区”的渐进交互：必须区分纵向滚动意图，手势结束生成的点击不得透传到卡片主操作；同屏只展开一项，点击卡片外、滚动或切换视图时收起，外部点击本身继续执行。危险操作仍需二次确认，且必须保留可发现的菜单或按钮入口，不能把左滑作为唯一入口
- Flexbox 子项设置 `min-width: 0; overflow: hidden` 防止溢出
- 表格内容可左右滚动
- 长笔记在手机和平板/中等宽度布局中使用顶栏 `BButton` 作为稳定目录入口，正文无标题时不显示；目录通过底部 `BDrawer` 展示，最高不超过约 72dvh，并为底部安全区留白。只有完整桌面布局保留常驻侧边目录，禁止在两种布局之间留下无入口断档
- 目录标题项触控高度至少 44px，层级缩进最多展示三层；当前阅读章节需随滚动高亮，打开抽屉时定位到当前项，点击标题后定位正文并关闭抽屉
- 移动目录必须保留对话框标题、关闭按钮、遮罩/Escape 关闭和焦点陷阱；关闭时让焦点自然回到页面，不强制跳回原触发按钮，不能用悬浮图标 + 无语义小面板替代
- 笔记页面树在完整桌面布局使用常驻左栏：标题打开对应正文，箭头只展开/收起结构，“在库中浏览子页面”才改变卡片/列表范围；移动端不压缩复刻常驻树，使用底部 `BDrawer` 逐级进入。当前正文、当前浏览范围和 AI 目录范围必须同时有实色描边、文字色、图标或明确文字标记，不能只依赖 `color-mix()` 背景、阴影或中间字重；共享移动基线下仍须可辨。
- 笔记详情工作区的左右侧栏偏好与当前断点的实际形态分离：宽屏可双侧常驻，中宽左侧常驻而 AI 按需覆盖，紧凑桌面使用轨道或互斥 Overlay，移动端只使用“页面 / 大纲”统一底部导航。断点切换只收起临时 Overlay，不能擅自改写用户的常驻偏好。
- “页面树目录”与详情页“正文大纲”必须使用不同标题与入口：前者组织页面关系，后者导航当前正文标题。父页面可编辑正文，不能设计成只有文件夹图标的空容器。

- 深色主题
- 桌面端保留 5 页全屏幻灯片滚动；移动端改为自然纵向内容流，避免固定一屏容纳桌面布局

- 封面：左右布局（左文字 + 右产品截图轮播）

- 移动端首屏使用不超过 430px 的内容列：主按钮为紧凑主操作、示例入口降为轻量次操作，PWA 安装条保持单行，产品预览默认展示移动界面；五个预览标签位于截图上方且始终显示文字。正文区块按内容自然增高，覆盖 320px、360px、390px、430px 常见宽度
- 普通移动浏览器仅首次展示官网，挂载成功后写本地首访记录；回访由预渲染官网 `<head>` 中的守卫在首次绘制前进入 `/app`。无本地记录的首访用户与搜索引擎仍展示同一份完整响应式官网，不按爬虫 UA 或伪造 PC 视口分流。Android APK 与移动 PWA 固定恢复资料模块；桌面浏览器与桌面 PWA 的根路径保留官网，应用内 Logo 与官网主 CTA 进入 `/app`：登录用户按账号默认应用首页进入，游客或无偏好用户回退书签 `/home`
- 官网认证探测在后台自动完成并渐进退避重试；页面只展示“开始使用 / 免费注册 / 进入我的轻笺”等用户目标，不展示“确认登录状态”或手动重试等内部技术状态
- 品牌大字使用 4 色渐变

## 资源语义

| 资源类型 | 图标风格     | 颜色代码  |
| -------- | ------------ | --------- |
| 书签     | 圆角方形图标 | `#615ced` |
| 笔记     | 文档图标     | `#00a884` |
| 文件     | 文件图标     | `#ff8a00` |
| 标签     | 圆形点       | `#ec4899` |

书签、笔记、文件、标签相关的点、边框、图表线条、卡片强调色必须复用这套配置。

### 胶囊语义配色

资源胶囊按内容语义统一，不按当前页面或资源模块染色：

| 内容语义        | Tone                         | 视觉色       | 典型内容             |
| --------------- | ---------------------------- | ------------ | -------------------- |
| 用户标签        | `tag`                        | 粉           | 工作、待读、项目标签 |
| 优先状态        | `pin`                        | 紫           | 置顶                 |
| 工作流状态      | `pending`                    | 琥珀         | 待整理               |
| 技术元信息/计数 | `neutral`                    | 灰           | HTML、MD、+N         |
| 资源身份        | `bookmark` / `note` / `file` | 资源紫/绿/橙 | 类型图标、类型徽章   |

实现约束：

- 胶囊基础组件为 `apps/web/src/components/base/BasicComponents/BChip.vue`；常规展示与筛选中的业务用户标签使用 `apps/web/src/components/tag/ResourceTagChip.vue`。
- 多选下拉值使用 `BSelect chip-tone="tag"`；带移除按钮的复合标签直接组合 `BChip tone="tag"` 与 `BButton`，避免交互控件嵌套，同时保持同一语义色。
- `PinBadge`、`InboxPendingBadge`、`NoteFormatBadge` 分别锁定 `pin`、`pending`、`neutral`，业务页不重复维护颜色。
- 同一用户标签跨书签、笔记、文件、搜索中心和标签详情必须保持粉色，不能跟随书签紫、笔记绿或文件橙。
- 用户标签 hover 只使用 `--chip-tag-hover-fg/bg` 轻微加深，不切换为高权重实心反白。
- 选中态同时使用实色描边和字重；状态识别不得只依赖 `color-mix()`、透明阴影或颜色本身。
- 小型胶囊：11px 字号、16px 行高、`2px 7px` 内边距、最小高度 20px；常规胶囊：12px、`3px 9px`、最小高度 22px；圆角统一 999px。
- day/night Token 统一位于 `apps/web/src/assets/css/theme.less` 的 `--chip-*` 变量族。关键语义使用显式实色，加载 `light-note-mobile-rendering` 共享移动基线后仍须保留前景、背景和描边差异。
- 文件具体类型现阶段可保持文件模块既有橙色；需要进一步细分时使用 `FILE_TYPE_COLOR_HEX`，但文件类型色不能承担用户标签语义。
