# 轻笺设计系统

本文只描述跨页面复用的品牌、主题、组件、布局与交互规则。单个功能的字段、流程和文案不在这里展开；实现入口和专题文档见 [文档目录](./README.md)。

## 设计原则

- 信息层级优先于装饰：先用排版、间距、表面和结构组织内容，再使用语义色强调。
- 一个页面只保留一个主要任务；次级能力渐进披露，不复制平行入口或第二套页面。
- 状态必须同时有文字、图标、形状或实色描边，颜色、阴影和动画只作辅助。
- PC、移动端、浅色、深色和中英文属于同一个功能的基本验收面，不是后补兼容。
- 优先复用主题 Token、B 组件和既有页面壳，业务页面不建立私有设计系统。

## 品牌与资源语义

| 语义 | 色值      | CSS 变量                    |
| ---- | --------- | --------------------------- |
| 书签 | `#615ced` | `--resource-bookmark-color` |
| 笔记 | `#00a884` | `--resource-note-color`     |
| 文件 | `#ff8a00` | `--resource-file-color`     |
| 标签 | `#ec4899` | `--resource-tag-color`      |
| 待办 | `#0ea5e9` | `--todo-module-color`       |

- 资源色的代码事实源是 `src/config/resourceColor.ts` 与 `theme.less`。
- 资源色用于图标、圆点、胶囊、图表线和局部强调，不默认铺满整卡。
- 待办是行动对象，不加入资源类型；逾期、高优先级、完成和低优先级继续使用各自状态色。
- 笔记的 Markdown/手绘格式色只在需要区分正文格式时使用，不能替代笔记绿色身份。

### 胶囊语义

| 内容     | Tone                 | 用途               |
| -------- | -------------------- | ------------------ |
| 用户标签 | `tag`                | 业务标签           |
| 置顶     | `pin`                | 优先状态           |
| 待整理   | `pending`            | 工作流状态         |
| 技术信息 | `neutral`            | 格式、数量等元信息 |
| 资源身份 | `bookmark/note/file` | 类型徽章           |

胶囊基础组件使用 `BChip`，用户标签优先使用 `ResourceTagChip`。选中态必须有实色描边和明确前景变化；同一用户标签跨资源页面保持标签粉，不跟随所在资源染色。

## 品牌标识

- 主标识“笺结”使用纸带循环、连接和聚合表达个人知识空间。
- 四向转折是几何骨架，不映射产品模块数量。
- 标识只使用品牌紫的明度层次；favicon 使用透明底彩色标识，PWA/Apple Touch 使用带系统裁切安全区的底板。
- 品牌标识、资源图标和功能插画是三类不同资产，不混用语义。

### 聊天表情层级

- Emoji 面板同时承载系统 Unicode Emoji 与轻笺“笺团”行内小表情；笺团按 8 列展示。输入框中的笺团视觉尺寸为 `1.45em`，但排版占位保持在 `1em` 文本行盒内，既不得改变编辑器高度，也不得移动同一行文字的基线；发送后的消息正文使用 `2em` 展示，并随文字基线排布。
- “纸灵”和“我的表情”仍是独立发送的贴图消息，不与文字混排；不得为了复用入口把笺团升级成第四个顶层标签。
- 笺团资源使用透明 PNG，在普通与自己的品牌紫消息气泡、浅色与深色主题下都不能出现底板；分类选中同时使用实色描边和明确前景变化。

## 主题与表面

主题通过 `<html data-theme>` 切换，Token 统一定义在 `src/assets/css/theme.less`。

### 工作区配色

书签、笔记、云空间、待办、标签、资源中心与知识工坊共用工作区语义 Token。浅色以书签目录的淡紫灰为色值基准，目录统一白底，右侧保留各模块原有白底／淡紫灰的区域组合；深色统一采用中性灰层级。页面背景与顶部导航沿用全局主题，模块品牌色只用于图标、局部强调与操作。

| 区域 | Token | 浅色 | 深色 |
| --- | --- | --- | --- |
| 淡紫灰画布 | `--workspace-canvas` | `#F6F7FB` | `#25272E` |
| 浅色白底区域、深色画布 | `--workspace-open-canvas` | `#FFFFFF` | `#25272E` |
| 卡片、表格、编辑器、问答面板 | `--workspace-content` | `#FFFFFF` | `#2E3038` |
| 工作区边框 | `--workspace-border` | `#E6E9F2` | `#414550` |
| 内部分隔线 | `--workspace-divider` | `#EDF0F6` | `#383C46` |
| 导航悬停 | `--workspace-hover` | `#ECEEF5` | `#353842` |

通过 `assets/css/workspace-surfaces.less` 的 `workspace-canvas-surface()` / `workspace-open-surface()` / `workspace-content-surface()` 接入。共享样式只管理颜色，不引入尺寸、间距、包裹卡片或滚动容器。普通文字使用 `--workspace-text`，次要文字使用 `--workspace-muted`；继承全局可读文字色。

- 浅色左侧目录统一白底，沿用已有边框；右侧书签和笔记保留淡紫灰画布，云空间、待办和标签保留白底；资源中心与知识工坊保留既有区域分工，不为统一色值新增整块底色。深色目录与工作画布统一中性底色。
- 白色区域用 `workspace-open-surface()`，不要写页面内浅色主题特判。卡片、列表行、表头和正文面板使用清晰的内容表面。表头不单独染暖色，卡片不叠加品牌渐变。
- 七个模块之外的菜单、弹窗和后台继续使用既有全局表面变量。`--workspace-panel-bg-color` 是存量兼容入口，不用于新增工作区；不更改菜单或全局卡片 Token 的含义来修复局部配色。
- 图片／视频舞台、代码块、用户正文自定义颜色与图谱节点表达属于例外。知识地图外围画布仍遵守共享配色。

### 目录交互与强调文字

目录默认行透明；悬停使用共享轻量背景；选中使用对应的 `--workspace-*-selected` 实色填充、强调文字及描边。边框空间在默认态预留，选中与悬停不得改变位置；键盘焦点沿用可辨识的焦点环。导航通过 `workspace-navigation-colors()` 选择身份，配合共享 default / hover / selected mixin。

| 身份 | 强调文字 Token | 浅色 | 深色 |
| --- | --- | --- | --- |
| 品牌紫／书签 | `--workspace-purple-text` | `#5146D9` | `#AAA6FF` |
| 笔记绿 | `--workspace-note-text` | `#087F68` | `#51D4B0` |
| 文件橙 | `--workspace-file-text` | `#9B5600` | `#FFB45C` |
| 标签粉 | `--workspace-tag-text` | `#B42365` | `#FF8EC3` |

这些色值用于导航与工作区小字，不替换按钮填充色。目录顶部统计入口的选中边框与总数使用 `--workspace-*-stat`，浅色保留模块品牌色，深色使用对应明亮文字色；普通行计数保持次要文字层级。按钮、状态胶囊继续使用成对前景／背景规则。普通文字对比度至少 4.5:1，必要的控件边界及状态标识至少 3:1；装饰性卡片边框无需机械加深到 3:1。

验收在真实浏览器中检查七个模块的目录、画布、内容表面及选中项，覆盖 PC、平板、移动基线、浅深主题和适用状态。检查实际计算颜色及文字对比度，再检查截图；仅匹配源码或计算色值不能替代视觉验收。移动基线不得把共享表面重新映射到菜单背景。未覆盖的设备或状态在交付中明确说明。

## 组件体系

基础组件位于 `src/components/base/BasicComponents/`。

| 场景           | 使用                                    |
| -------------- | --------------------------------------- |
| 按钮           | `BButton`                               |
| 输入           | `BInput`                                |
| 选择           | `BSelect`                               |
| 表格           | `BTable`                                |
| 页签           | `BTabs`                                 |
| 卡片           | `BCard`                                 |
| 弹框/抽屉      | `BModal` / `BDrawer`                    |
| 菜单/气泡/提示 | `BActionMenu` / `BPopover` / `BTooltip` |
| 消息/加载      | `BMessage` / `BLoading`                 |
| 确认           | `Alert.alert()`                         |

- 有 B 组件的场景禁止使用原生控件或新增 Ant Design Vue。
- 操作菜单使用左对齐图标槽与文字起点；危险范围和后果放在确认层，不把长警告塞进菜单。
- 后台“标题 + 指标 + 工具栏 + 数据”页面复用 `AdminDataPage`。PC 用 `BTable`，移动端用可扫描列表，不压缩宽表。
- 图片预览复用共享 Viewer，业务层不重复实现缩放、旋转、拖拽、全屏和下载状态机。
- 持续增长列表同时使用服务端分页/游标与虚拟化，不能一次性加载全量。

### 移动端尺寸、布局密度与触控

- 移动端元素以内容需要的高度为准，按钮、页签、页头、卡片和空态均避免无意义的高占位、过大内边距与层层留白。优先让正文和主要任务进入首屏；不直接沿用桌面的固定高度或最小高度，也不为消除滚动强行压缩内容、裁字或缩小必要的触控目标。
- 尺寸优先使用现有 B 组件能力。核对最终盒模型中的 `height`、`min-height`、行高、上下内边距、边框和 `box-sizing`，同时检查父级拉伸与外层包裹；不能只降低一个高度值，却让其它约束继续撑高元素。

| 场景 | 移动端尺寸原则 |
| --- | --- |
| 页头、工具栏、卡片内操作、空态并排按钮 | 默认视觉高度 32px；主次层级通过按钮类型表达，不把同组主按钮单独拉高 |
| 底部固定提交栏、独立全宽主操作、重要确认动作 | 使用约 44px 的操作高度，按所在共享组件的规范执行 |
| 少量同级页签、紧凑分段切换 | 单项视觉高度通常 32～36px，含外层内边距的整组高度约 40～44px；文字水平、垂直居中，不叠加组件固定行高与业务上下内边距 |
| 图标操作、全局导航、可点击列表行 | 按对应组件的触控区域规范执行，不套用紧凑文字按钮高度 |

- 触控区域通常以不小于 44px 为目标，但不等于按钮背景必须高 44px。紧凑文字按钮允许使用 32px 高度，须有清晰文字、足够横向空间与相邻操作间距；需要扩展点击区域时，扩展区域必须真实响应同一按钮的点击，不可用不可点击的外边距充数，也不能与相邻目标重叠。危险操作、纯图标小目标与底部主要提交动作不使用该紧凑例外。
- 禁止在页面根节点、整个卡片或移动共享基线中用 `button` / `:deep(.b_btn)` 等宽泛选择器统一设置按钮最小高度；仅对明确的操作组或组件变体设置尺寸，避免同时撑高空态按钮、工具栏按钮和列表行。具有专用尺寸规范的组件（如 `BBatchToggle`）继续遵循自身规范。
- 同组按钮保持等高、文字垂直居中。长文案优先调整横向布局或将按钮组换行，不因父级拉伸、固定行高叠加内边距而被动变高；确需多行说明的入口使用对应列表或卡片模式。
- 占独立一行的少量同级页签优先铺满内容区并等分可用宽度，不保留桌面窄宽度上限造成右侧空白；与设置等操作同排时铺满剩余空间。较多分类或长文案按组件规则横向滚动或调整布局，不强行等分到无法阅读。
- 验收最终渲染高度、可用宽度、文字居中与相邻控件比例，覆盖 320/390px、浅深主题、中英文及适用的默认、焦点、选中、禁用、加载和空态；切换、加载图标和文案变化不应无故撑高控件或移动布局锚点。按共享移动渲染基线检查浏览器与 App，不以截图物理像素推断 CSS 高度。

### 页签变体

`BTabs` 按信息层级选择变体，同一区域最多出现一组强强调页签；嵌套筛选必须比上层导航更轻。

| 变体      | 适用场景                                           | 不适用场景                                     |
| --------- | -------------------------------------------------- | ---------------------------------------------- |
| `line`    | 页面内容视图、详情分区等需要保持内容连续性的切换   | 需要强提示“这里可以切换”的独立分类入口         |
| `pill`    | 工具栏中的状态、筛选和移动端紧凑模式切换           | 页面主导航或与另一组同重量页签并列             |
| `segment` | 弹框、面板内少量互斥设置或预览模式                 | 宽页面的主要内容分类                           |
| `solid`   | 商店分类等独立、同级且需要高可发现性的 2～4 个入口 | 高密度工具栏、状态筛选、嵌套页签或连续两组切换 |

- `solid` 选中项使用实色底与明确前景色，项间保留可见间距；业务语义色通过组件开放的强调色变量注入，不复制整套样式。
- 一组页签同时承担“内容视图”和“状态筛选”时应拆成不同视觉层级，例如主状态用 `pill`、视图模式用 `line`，不得把两组都升级为 `solid`。
- 数量徽标是辅助信息，不能取代选中、焦点和可点击状态；所有变体继续由 `BTabs` 提供键盘方向键、Home/End 与语义属性。

### 图标

- 静态 UI 图标唯一入口是 `src/config/icon.ts`，由 `SvgIcon` 渲染。
- 使用前实际确认完整属性路径存在；缺失时先补配置，不能依赖默认占位。
- 共享单色图标使用 `currentColor`；同组图标保持相近的描边、圆角和留白。
- 业务组件只封装交互和布局，不保存静态 SVG Path。
- favicon、品牌多色图、用户内容、复杂插画和数据可视化按各自职责管理。

## 状态与反馈

每个用户可见模块按适用范围覆盖：

- 默认；
- hover 与 focus-visible；
- 选中/当前；
- 加载与保留旧数据的静默刷新；
- 空与筛选无结果；
- 错误、受限与重试；
- 业务状态，如完成、逾期、待领取/已领取、处理中、成功和部分失败。

### 切换与刷新时的视觉稳定性

- 能保持稳定的元素不闪动。切换目录、标签、页签、筛选或刷新数据时，导航、目录、概览、页签、工具栏和面板框架保持挂载与原位显示；仅文字、图标、数字或选中状态变化时原位更新，不先清空、隐藏、重建或用不透明遮罩盖住整个区域。
- 页签（Tab）切换必须保持布局锚点稳定：在视口、缩放和用户滚动位置不变时，仅切换选中项不得改变页签栏自身的位置、高度及其上方元素的位置、占用高度。上方控件因当前页签显隐、文案或数量变化时，应通过稳定的行高、预留空间等方式避免重排；选中样式不得因边框、内边距或字体变化撑高、换行或推动页签位移。页签下方内容可按当前视图调整，但不得反向挤动页签及上方区域。验收逐项切换并对比页签栏与上方元素的边界位置和高度，同时覆盖加载、空结果与有内容状态。
- 加载反馈只作用于实际等待数据的最小内容区，优先使用不引发布局位移的局部 `BLoading` 或按钮 loading；仅首次进入且无可展示内容时，在对应区域使用结构化骨架。静默刷新保留已有内容，不闪骨架；无关区域的滚动位置和交互状态保持不变。
- 保留旧内容不能混淆数据归属：属于同一业务对象的名称、统计和结果应一致更新，切换期间明确加载状态并阻止误操作旧对象。账号、权限或敏感上下文变化时应及时清除不应继续展示的数据，不为防闪保留越权内容。
- 验收覆盖快速连续切换、快慢请求、失败和空结果：无关区域不消失、不被遮挡、不跳动；加载结束后数据归属一致，旧响应不覆盖新目标。按受影响端型与主题进行真实浏览器检查，结构测试不能替代视觉验收。

### 今日简报

- 桌面简报在工作台顶部独占一行，完整展示且随内容自然增高；宽屏洞察按阅读顺序分两列，窄屏单列，不折叠、不设置正文内部滚动条。关闭后不保留占位，不与成长、回顾卡片绑定高度。
- 管理员预览和内容代管都保留目标用户的今日简报卡片，只读展示已经保存的简报；没有当日产物或目标用户关闭功能时展示只读默认态。管理员上下文不显示生成、更新与设置动作，也不因页面打开、前后台切换或定时刷新触发事实检查和 AI 生成。

### 每日回顾入口

- 移动「今日」只显示单行名称、进度和开始入口，通过详情弹框回顾；完成后只保留结果行，正常空清单不占位置。桌面回顾与每日任务是独立卡片，直接展示当前资料、理由、进度和操作，不再套回顾弹框；沿用共同的读模型、打开资料与奖励语义。加载、失败与状态待核对保留明确反馈，不用空态冒充失败。
- 不提供「收起／重新展开」交互；旧收起会话在用户主动开始时恢复。设置 → 通用（移动端为「内容与交互」）的每日回顾开关复用账号偏好，关闭后隐藏入口并停止页面加载，管理员代管不可修改。

### 资源中心与整理中心

- 资源中心一级页签固定为“查找｜整理中心｜全局图谱”；三个入口同级，共用“资源中心”一级页头，整理中心自己的名称与说明放在内部内容区。整理中心页签显示全部待处理事项角标，口径为“待整理工作流数量 + 资源治理发现数 + 知识结构发现数”；这是任务量而非去重资源数，同一资源命中多个问题时可计多项。摘要尚未完整加载或总数为零时隐藏，超过 99 显示 `99+`。
- 整理中心内部为“概览、待整理、无标签、重复网址、疑似失效、知识结构”。待整理是收集工作流，后四项是治理问题；概览中的每个分类仍保留自己的统计单位，汇总角标只能表达待处理事项数，不得解释成唯一资源总数。知识结构角标统计空内容、异常父级、同名标题、未命名和层级过深的问题条数，详情另行说明涉及笔记数；无标签笔记继续归“无标签资源”，不得重复计数。
- PC 使用左侧内部导航与右侧工作区；移动端使用可横向滚动、内容宽度自适应的紧凑入口，不把五项压成等宽页签。选中态必须有实色描边或侧边条，不能只靠混色背景或阴影。
- 整理总览只提供现状概括与分类详情入口，不包含资源筛选、标签编辑、删除或逐项处理。四项治理指标保留资源、重复组和问题条数的各自单位，下方展示无标签资源类型构成、书签检测覆盖、知识结构问题分布与待整理构成；各图表读取完整汇总，不用近期预览或去重键截断样本推算比例。未知、加载失败与零项区分展示；没有历史快照时不绘制趋势。详情页承载实际整理操作，窄屏将双列图表改为单列，图例与数值始终可见。
- 待整理复用原书签、笔记、文件筛选、排序、批量处理与检查器能力；默认是浏览和单项整理模式，卡片可直接打开并提供“整理 / 整理完成”，只有显式点击“批量选择”后才显示复选框与批量栏。移动端无资源类型参数时固定回落“全部资源”，不能继承待办的默认页签。
- 工作台的汇总卡以“整理中心”命名、显示相同的全部待处理事项数并进入整理中心概览；下方待整理明细仍是具体工作流入口，“查看全部”直达整理中心的待整理子页。
- 无标签、重复网址和疑似失效都覆盖加载、空、错误、部分失败与操作中状态；重复网址确认层明确保留项、将移入回收站的成员、关系阻断和标签合并结果。
- 整理建议以整次任务为审核工作区，按书签、笔记、文件切换，并独立筛选标签、标题／名称、空内容和重复检查。重新整理按资源、项目、范围、确认四步进行，每步只呈现当前选择，完成的步骤可以返回修改；笔记库和书签管理的批量智能打标签交接明确选择、仅预选标签检查，自动预检后直达确认页，用户主动返回修改后必须重新预检；项目适用关系见[资源标签与待整理](./architecture.md#资源标签与待整理)。默认最近新增每类 20 项，“全部资源”不隐含截断。确认页展示冻结范围、类型和所选检查，正文相关数量标注“检查后确定”；不突出 Token 估算，仅保留简短计费提示，不提供用量说明折叠区与明细入口。规则先交付、AI 陆续补充，分别展示进度，部分失败不显示全部成功。暂停、继续和结束按服务端能力呈现；暂停期间区分原因和在途项目，结束及新任务替换旧任务单独确认。刷新不创建任务，展开与折叠只在当前页面会话内保留，不写入本地存储；重新进入按建议状态默认展开；后台生命周期边界见[架构](./architecture.md#资源标签与待整理)。页面仅展示最新一轮整理，不提供历史任务切换入口；结果按资源唯一分入优先处理、手动补充、分析未完成、未发现问题和已处理分组；数量按当前资源类型及检查筛选的完整范围统计。优先处理与手动补充分组及其中资源默认展开，其余分组折叠；用户手动收起后本轮刷新保留选择；资源详情通过明确的展开箭头呈现多条独立建议，正常结论只用于已完成且确无问题的检查，忽略建议不等同于没有问题。
- 文件整理副信息区分读取中、正文、视觉、部分读取和仅文件名；展开显示已处理页数、缺失范围及可操作原因。读取失败属于分析未完成，真实分析后无可靠主题才需要手动补充；旧记录缺少覆盖字段时明确提示历史记录未提供详情。预览按钮加载时在固定图标位置只显示转圈，保留标题位置和点击区域。重新分析入口先展示服务端冻结的未推荐文件范围，再确认启动。 待审核的新标签在同一标签胶囊内以“· 新”标记，已有标签不加标记；新仅表示应用时创建，已应用结果不保留待创建标记。
- 标签图标整理在同一审核工作区独立分页展示，只纳入默认图标标签。推荐图标预选，批量复选框默认不选；可切换备选、搜索与调色、单项应用或勾选批量应用。无匹配显示待手动选择，服务失败显示搜索失败，不表示“未发现问题”。普通搜索免费，AI 扩展由用户明确触发；应用前说明影响全部标签引用。分页保留本轮已选项，切号、换任务或离开工作区清空草稿与选择。
- 同一资料的标题和标签分别编辑、应用或忽略；依据不足时保留手动名称及统一标签选择／新增入口。普通整理仅补齐无标签资料；批量智能打标签为明确选中的资料追加标签，保留原关联。标题只针对缺失、默认或重名。空笔记须闲置满 7 天且没有有效文字、媒体、附件、嵌入或子页面；画布不参与空内容与重复删除。置顶、引用、待办关联及分享中的笔记展示使用情况，不能直接清理。重名不同正文仅建议区分标题；文件同名同大小仅展示疑似重复对照，解析失败不等于空文件。所有清理单独确认并进入回收站，不与元信息应用混在一起。
- 疑似失效对用户只提供“检测全部书签／重新检测全部”，内部批次和并发不暴露；排队或执行时显示已处理数与总数，并明确离开页面后任务继续。重复点击复用当前任务，完成后同时展示正常、疑似失效、无法判断以及跳过/重试失败口径。
- 知识结构在整理中心展示轻量健康摘要、问题筛选和受影响笔记入口；完整体检仍由知识工坊承载，不提供只导出 Markdown 的目录生成功能。两处必须复用同一知识结构分析事实，单类加载失败不得阻断其他整理能力。从结构问题打开笔记时必须携带整理中心当前地址作为来源，笔记内返回应回到原问题视图。

### 批量选择操作与 AI 成果入口

- 工具栏中进入/退出批量模式的独立按钮统一复用 `BBatchToggle`：默认使用多选列表图标与“批量操作”，激活使用关闭图标与“退出批量”，以中性表面、品牌色实线描边和文字表达模式。支持 `small/default/large` 及 `--batch-toggle-height/font-size/padding-x/radius/gap` 尺寸变量，宽度由两种状态文案共同撑开，不能在业务页另设固定宽度或重写状态颜色。移动触摸高度至少 44px；移动端抽屉菜单保留菜单布局，实际执行批量删除、标签等业务动作继续使用对应动作按钮。

- 云空间、资源中心、书签管理、笔记库、整理中心的无标签资源与待办列表进入批量态时，只增加复选框与选中信号，页面原有标题、筛选、列表和检查器不得为批量按钮重排。进入与退出必须复用同一个按钮位置和稳定宽度，仅切换必要的文案与动作，不能隐藏同排其他上下文控件；整理中心的无标签资源入口与搜索、类型筛选同排，默认浏览时不显示卡片复选框，进入批量态后点击资源行或复选框都能切换选择，行内按钮维持原动作且不得连带选择。批量上下文统一由不占文档流的底部悬浮操作栏承载；零选择时保留选择提示，悬浮栏不重复提供退出。资料类模块显示选中数量与类型摘要、少量高频整理动作以及唯一主动作“生成与处理”；整理中心的无标签资源以“管理标签”为主操作，保留“标记为无需标签”和“移入回收站”两项治理动作。待办只复用交互骨架，保留“完成、删除、取消选择”等任务动作，不进入资料 AI 链路。笔记库和书签管理不再提供页面级 AI／智能打标签入口，批量智能打标签在 PC、平板与移动端统一进入整理中心。书签与笔记原有单项 AI 快捷操作继续直达对应能力，不强制先经过批量成果选择。
- PC 悬浮栏左侧固定放全选控制，动作区直接展示高频动作和需要二次确认的删除，不再为这两项增加“更多”菜单；笔记库直接展示“管理标签”，加入待整理、移动和导出等上下文操作收进“更多”。移动端保留全选控制、摘要和“更多”，具体动作进入 `MobilePageActionsDrawer`，危险动作位于分隔线后；资料类模块的“生成与处理”也遵循这一规则，待办抽屉则仅展示待办动作。悬浮栏必须避让底部导航和安全区，不能遮住列表最后一项或依赖透明阴影表达边界。
- 资源中心、云空间、笔记库、书签主页与管理入口共用一个内存选择会话，按当前模块及完整身份范围隔离。切目录、标签、关键词、排序、分页和展示方式保留显式选择及批量模式；“清空选择”清空整个集合但不退出批量。退出批量、成功导航到其他主模块、刷新页面或切换账号/管理员上下文结束会话；取消导航不清理。整理中心和待办保持各自选择规则。
- 普通全选只增减当前已加载列表，与其他已选项做并集/差集；加载新范围时禁用旧列表全选。空结果、刷新失败和分页未返回都不构成资源失效证据。底栏显示总数和“当前列表 N 项 · 其他已选 M 项”，点击摘要打开共享已选清单，可逐项取消和清空。列表外选择与空列表下的操作入口仍可用。
- 选择项以“资源类型 + 字符串 ID”去重，仅保存名称和必要操作元数据快照。显式选择上限由共享资源选择常量约束，超限整次拒绝；AI、导出等动作继续执行自身上限。各动作在打开操作层时锁定选择快照，准备及写入期间禁止改选；核对失败保留选择，权威核对发现不可用项时移除并提示，同时停止本次动作，不能静默缩小确认范围。
- 加标签、加入待整理、移动、下载和导出成功后保留选择，刷新受影响资源数据与目录缓存。删除仅移除权威结果确认删除/不可用的项目；成功写入后核对失败显示待核对及重试入口，重试仅核对，不重复删除。失败、取消与迟到回执不能清空选择或影响新身份、新会话、新操作层。
- 批量标签通过共享抽屉在来源页面处理，锁定绑定来源模块与身份的内存操作快照；关闭只结束子操作，成功后静默刷新来源资源并保留已加载范围、选择和浏览位置。PC 使用右侧抽屉，移动端使用全屏抽屉；资源清单默认折叠，标签使用紧凑双列，变更摘要与提交动作固定在底部。旧批量标签 URL 仅作兼容入口，刷新后交接失效不得回退到其他选择范围。进入整理中心 AI 建议或知识工坊时先交接明确材料，再按主模块导航结束来源会话。
- 云空间文件夹菜单的批量标签入口默认只处理本层文件，可显式包含全部子文件夹，范围不继承页面的搜索或类型筛选。服务端核对后交接显式文件快照，原有跨目录选择保持独立。笔记、书签和云空间桌面批量栏直接提供“管理标签”，移动端放入批量操作菜单；笔记的“加入待整理”放入更多菜单。桌面书签批量入口位于页头操作区，普通浏览中开启批量时自动进入管理模式。资源标签操作统一由“管理标签”进入共享抽屉，在抽屉内切换添加/移除；切换操作清空标签草稿，搜索保留选择，全选只作用于当前可操作候选。移除只解除资源关联，不删除标签本体；提交期间禁止重复提交、关闭或导航，失败保留草稿并可重试。变更数量集中在预览区，按完整资源范围的已有标签关系计算，不能用资源数乘标签数或局部预览清单冒充实际变更数。
- 资源中心“全部匹配结果”为独立入口，与显式选择互斥。替换已有显式选择需明确确认，预览成功才切换，并固定当时的匹配条件；排序、展示方式和追加加载不退出，关键词、类型、标签、时间等匹配条件变化则退出并提示。查询全选不展开为前端全量资源清单，也不能进入 AI。

- “生成与处理”使用共享抽屉锁定当前显式选择的资料快照，先展示资料范围，再让用户选择固定成果；快速总结、快速对比是次级即时入口，不替代固定成果。资源中心的“全量匹配”只用于确定性整理操作，AI 入口必须要求逐项明确选择，禁止把未展开的查询范围静默提交给 AI。
- 抽屉覆盖目录加载、不可用、输入数量或类型不匹配、报价中、报价失效、余额不足、任务创建失败与成功跳转等状态；移动端使用全屏抽屉。选中成果、场景和计费介质必须同时具备实色描边、明确文字色和勾选图标，在共享移动渲染基线下不得只靠混色或阴影。

反馈规则：

- 错误靠近发生位置展示，并提供明确下一步；长表单的局部错误不复用页底总错误槽。
- 成功只在获得权威终态后表达；上传受理、请求发出或桥接投递不等于业务完成。
- 动画关闭、弱网和共享移动基线下仍能理解所有状态。

## 响应式布局

断点来自 `config/responsive.ts` 与 bookmark Store：

| 类型    | 语义                                    |
| ------- | --------------------------------------- |
| Mobile  | 小于 768px                              |
| Tablet  | 768–1199px，或 1200–1399px 的粗指针设备 |
| Desktop | 其他完整桌面布局                        |
| Compact | 小于 1400px 的密度调整，不改变设备类型  |

- 不新增 UA 分支或页面私有断点。
- 工作台、资源列表和后台等高密度工作区使用可用宽度；表单、编辑和阅读页使用受控阅读宽度。
- 卡片流使用 `auto-fit/auto-fill` 与合理最小宽度，不按设备型号写死列数。
- 固定侧栏后的主区使用 `minmax(0, 1fr)`；可收缩文本子项使用 `min-width: 0`。
- 桌面视觉验收覆盖至少 1280、1440、1920 和 2560 CSS px；截图像素或物理屏幕尺寸不能代替 `window.innerWidth`。

### 应用级导航与搜索

- PC 顶栏中的工具箱与聊天室复用同一套轻量胶囊入口；默认、hover、focus-visible 与当前态只维护一份样式规则，当前态必须同时有实色描边和明确前景变化。
- PC 全局搜索在顶栏只保留图标触发器，搜索输入位于结果浮层顶部；打开后自动聚焦，Escape/关闭后把焦点还给触发器，并在浮层内约束 Tab 顺序。
- 小屏桌面通过收窄间距与图标搜索释放顶栏空间，不隐藏核心一级入口，也不恢复常驻搜索框。

### 移动页面结构

- 一级页复用共享顶栏与底部导航；二级页使用返回、居中标题和最多两个右侧动作。
- 创建/编辑页把提交动作放进 `MobileStickyActionBar`，并预留安全区和正文底部空间。
- 高频列表使用 `MobileListSurface + MobileListRow`，以一个外层表面和行分隔线组织，不把每行做成投影卡片。
- 行级更多、筛选和批量操作使用 `MobilePageActionsDrawer`；云空间多级菜单复用相同的菜单样式。单行最小高度 52px，有说明文字时 64px，图标 20px、图标栏宽 24px，间距 6px、圆角 12px。普通操作使用中性色，选中使用主题色，危险操作使用红色并放在分隔线后再次确认。模块页头菜单使用“书签操作／笔记操作／云空间操作”，批量入口统一称“批量操作”。
- 高密度桌面可视化在手机端改为列表与渐进披露，不直接缩小整张画布。
- 左滑只能是快捷入口，不得成为危险操作的唯一发现方式；手势必须区分纵向滚动并阻止结束点击穿透。
- 按[移动端尺寸、布局密度与触控](#移动端尺寸布局密度与触控)区分视觉高度和点击区域；处理长标题、底部安全区、横竖屏和软键盘。

### 浮层与滚动

- 页面明确一个主要纵向滚动所有者；弹框、抽屉和长画布避免内外双滚动。
- 移动端浮层使用统一 history 栈，系统返回与 Escape 只关闭最上层。
- 弹层交接时先释放上一层 history 占位，再导航或打开下一层。
- Teleport 浮层随滚动、缩放、视口与键盘变化更新位置，最大高度为上下两侧保留空间。
- 内容滚动容器复用 `v-auto-scrollbar`；滚动条槽宽保持稳定，只改变滑块可见性，避免内容横向抖动。

## 跨端渲染

- 移动浏览器、移动 PWA 与 Android App 共用 `html.light-note-mobile-rendering`。
- Android WebView 类只用于引擎识别，不写业务视觉补丁。
- 关键状态使用实色描边、圆点/图标和文字色；中间字重、混色或阴影不可作为唯一信号。
- 关键布局为旧 WebView 提供 `:has()`、容器查询和动态视口单位的等价回退。
- 同一 CSS 视口下对照移动浏览器与 Debug App，覆盖浅色、深色及横竖屏。

## 典型页面模式

### 资源中心

- 定位为“跨书签、笔记、文件的查找与批量整理”，不复制标签模块的主题浏览与治理能力。
- PC 使用“资源范围 / 结果 / 当前资源检查器”三栏工作区：搜索与排序位于中栏顶部，左栏承载类型、状态和标签筛选，右栏只呈现当前资源及其动作。页面壳不滚动，左右栏和结果列表分别承接自己的滚动。
- 没有关键词时标题表达“最近内容”并默认按最近更新；有关键词时默认按相关度。结果始终保留书签、笔记、文件的分组标题，批量操作与无限滚动只作用于这三类资源。
- 标签命中使用结果上方的独立导航条，不与资源卡片混排。卡片展示真实标签图标、说明及三类资源数量，点击进入标签空间；标签粉只用于表达标签身份。
- 移动端把结构化筛选和当前资源检查器分别放入底部抽屉。点击结果先查看详情和动作，不在第一次点击时直接离开；抽屉的打开、分析、待整理、标签整理和删除与 PC 检查器共用组件及行为。
- 默认、hover/focus、当前资源、批量选择、加载、追加加载、空和错误状态必须保持稳定布局；移动共享渲染基线下，选中与错误不能只靠混色或阴影表达。

### 标签

- 顶部只使用“标签”单一入口；同一目录同时浏览关联内容并提供创建、编辑、删除和批量整理。
- 目录包含空标签，使用同一服务端分页摘要、筛选和排序，不为管理动作拉第二套全量读模型。
- 卡片表达可进入的主题：标签名、三类资源数量、最近内容和活动。粉色只表达标签身份与局部状态。
- 详情默认按“相关标签 → 书签 / 笔记 / 文件”分区；搜索或单类筛选才切换为服务端全局时间线。
- PC 保留页内搜索与结构化筛选；移动端复用共享搜索入口，保留结构化筛选和批量态。
- PC 使用固定标签目录；移动端在当前标签标题旁提供切换入口，以底部快速切换面板展示同一份标签目录、真实图标、总资源数与类型构成，支持搜索和快速切换，不恢复第二套标签管理页。
- 移动端“新建标签”复用资料模块共享顶栏的加号；当前标签的铅笔入口打开同一编辑器，删除作为编辑器内的危险操作呈现，避免在切换面板重复管理动作。
- readonly 管理员上下文隐藏写动作，但继续使用同一浏览布局。

### 笔记导航

- “页面”表示笔记树，“大纲”表示当前正文标题，两者使用不同标题和入口。
- 完整桌面可常驻页面树；移动端用底部抽屉逐级进入，不压缩复刻整棵树。
- 当前正文、当前浏览范围和 AI 范围分别表达，不用一个选中态冒充三种状态。
- 公开分享使用独立阅读页，不出现编辑工具、私人树、AI、登录弹层或私人资源入口。

### 设置中心

- 外观、通用、通知、AI、积分明细、账号与安全、隐私与协议共用分类目录。桌面使用稳定侧栏和单分类内容区，手机使用目录与子页；只有一个页面主滚动容器，手机返回恢复目录位置。
- 设置卡片、字段行和错误反馈复用设置展示组件。桌面保留舒展留白，说明在左、控件在右；窄屏多选项控件移至说明下方。主题采用三等宽缩略预览，选中态同时有实色描边与标记。
- 分组标题使用紧凑浅底标题栏、3px 短竖线与 15px 加粗标题；说明使用次要文字色，操作置于右侧。只标识卡片分组，不装饰普通字段标题，不扩大卡片高度；共享业务组件仅在设置页采用此模式。
- 普通偏好自动保存，正常过程不显示排队、保存中或成功提示；失败只在对应字段说明回滚并提供重试。保存状态仍用于禁用当前提交字段，避免重复操作。
- 当前浏览器的通知接收意愿、站点权限、连接状态和系统显示权限分别表达；检查失败标为未知。移动端不显示浏览器推送及其免打扰分组。免打扰启用或编辑先确认完整时段，取消保留旧配置。
- AI 与积分通过嵌入展示参数使用设置布局，独立入口保留自身呈现。账本按时间单列排列，桌面时间单独成列，手机并入摘要；详情仅展示已返回字段，不用跳转箭头暗示不存在的业务链接。

### 后台数据页

- 核心表格优先占据可视高度；指标按业务价值选配，不为凑卡片数量展示分页区间等重复信息。
- 风险、权限和任务状态使用实色 `BChip` 与明确文案；高风险写操作与只读分析分区。
- 业务时间默认显示北京时间；UTC 只在明确标注的技术详情中出现。

## 国际化与文案

- 固定展示文案使用 vue-i18n，并保持中英文 key 对称。
- 文案优先表达用户目标与结果，不暴露内部状态机、Provider、锁、轮询或协议术语。
- 菜单使用短动词宾语；复杂后果在确认层说明。
- 空态说明当前为什么为空和用户能做什么；不把加载失败伪装为空。

### 待办工作区

- 日历、四象限在浏览器可用高度不足时默认收起概览，工具栏允许手动展开；列表、议程保留紧凑概览。日历空提示与月份栏合并，四象限分类说明通过帮助提示查看。最近完成使用整行只读预览入口，详情标题区保持紧凑并允许长标题换行。

- 工作区导航、主操作、选中态与子事项进度使用原型紫色；逾期／今天到期／本周到期／已排期分别使用红、橙、紫、绿的圆形图标和数字。其他页面的待办行动对象继续使用全站待办语义色。浅深主题分别提供实色边界，不能只依靠阴影区分状态。
- 页面沿用全站统一标题与待办模块色圆点标识；桌面标题横跨整个工作区，右侧集中搜索、新建与批量操作，标题下方再分清单侧栏和任务正文。编辑器沿用统一抽屉，不采用常驻第三栏。
- 目录沿用书签、笔记库与云空间的中性工作区底色、圆角边框与灰色次要文字；选中行使用主题色细描边和浅底，清单自定义色保留在小圆点，不染色整个侧栏。
- 列表与议程的桌面侧栏提供快捷范围、单层任务清单与未归类；日历、四象限不提供目录或范围入口，跨清单展示；切回列表、议程恢复原范围。平板和手机仅在列表、议程使用范围抽屉。顶部全局概览固定统计未完成，不随关键词或局部筛选变化；目录角标跟随视图有效状态（议程、日历为全部），不受关键词和标签筛选影响，加载失败显示“—”。状态页签数字则遵循当前范围与筛选。四视图保留清单、标签和关键词；切账号清除会话筛选、展开与选择。
- 默认智能列表将重点任务提前，其余按清单及未归类分组，每项只出现一次；其他排序不强制分组。最近完成仅在全部任务、待完成、无额外筛选的默认列表提供最多五项折叠预览，不计入待完成数量。
- 列表与议程的子事项默认收起，进度按钮可展开，超过五项继续折叠余项；日历和四象限仅展示摘要。父子独立完成，父已完成后子项只读；受控勾选、按父项请求锁与行内失败重试共用实现。批量选择仅选择父待办，可移动清单或管理标签。
- 创建表单优先展示标题、说明、清单与优先级；子事项、资料、标签及时间提醒按需展开，已有值编辑时展开。高级功能说明为“每次生成独立待办，分别完成”；关闭有修改的表单统一用 Alert 确认放弃。
