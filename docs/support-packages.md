# 爱发电资源商店套餐 v5 规范

> 本文是独立资源商店中常驻套餐、限时套餐、历史首购范围、结算快照与权益发放的实现和运营规范。常驻目录的代码唯一事实源位于 `@lightnote/shared`，当前版本为 `support-packages-v5`。

## 产品边界

- 支付仍由爱发电处理，轻笺不接触银行卡、付款码或支付口令。
- `/store` 是唯一购买入口，承载 AI、永久空间和组合权益。购买金额、笔数和身份与历史支持者榜分开。
- `/support` 的旧链接重定向到资源商店的「订单记录 → 历史赞助」。订单按当前登录账号和用途分页读取。账号关联、解绑和原有公开偏好在历史赞助中管理。已有匿名、退榜或管理员隐藏状态继续有效。
- 已确认的历史赞助用途继续冻结为 `donation` 或 `legacy_support`，资源订单冻结为 `entitlement_purchase`。在爱发电直接发起的赞助仍按历史规则归档；没有匹配结算意图的商品订单保持 `unknown`，由运营核对。
- `support-ai-v1` 仅解释切换日前已承诺的 `legacy_support`。既有已发额度不追回；切换后的纯支持使用零权益策略 `support-pure-v2`，不得重新触发旧赠送。
- 常驻套餐与限时活动是两套独立目录。活动 SKU 直接配置最终售价与最终到账，不叠加、也不消耗历史常驻首购。
- 全部常驻套餐每次购买固定权益，`firstPurchaseScope=none`，不再核验或占用首购资格；组合包的 AI 与空间分别和同档单独套餐保持一致。
- AI 额度一次购买、永久有效，优先使用每日免费额度，购买余额不按日清零。云空间一次购买、永久扩容，按标示容量叠加、无需续费。
- 历史 v2/v3/v4 AI 与组合订单继续核验账号级 AI 首购，同时受轻笺账号与实际付款身份约束；v2 中任一 AI/组合首购记录视为已使用该范围。历史 v2/v3 纯空间继续按原 SKU 核验首购，v4 纯空间为固定容量。
- 旧赞助不回填首购领取记录。退款或订单反转进入人工复核，不自动恢复首购资格。
- 历史余额与已入账权益原样保留，不重新定价或换算。历史 v2/v3/v4 结算意图继续按冻结的基础/首购权益快照及其历史首购规则结算，不按新版额度重算；已有首购记录不影响新版固定权益购买。少付、多付、过期、身份冲突或功能关闭都只能等待复核，任何失败不得降级成纯支持或旧赠送。

## 常驻目录

常驻 SKU、价格、固定权益与组合节省金额只在 `@lightnote/shared` 的版本化目录中定义，并由服务端目录测试逐项锁定；本文不复制可执行数值。全部常驻套餐的基础与首购兼容字段保持相同，目录状态为 `not_applicable`。商店与确认弹窗只展示一份每次到账，不显示首购资格或重复的基础/首购到账。AI 与组合明确“一次购买，永久有效；优先使用每日免费额度”，纯空间明确“一次购买，永久扩容”。已发布目录不得原地改值；调整价格或权益必须发布新目录版本。

## 限时活动

- 活动有稳定 `campaignKey` 和递增版本；同一版本内套餐标识唯一，每个活动套餐使用跨版本唯一的 `campaignSkuId`。
- 草稿可创建和成本预览；发布时再次按当前成本口径计算，任一 SKU 保守直接成本余量低于 40% 时失败关闭。
- 已发布活动的价格和权益不可修改，只能暂停；调整必须创建新版本。
- 活动版本的 `public_enabled` 默认关闭，新版本不继承旧版本的开放状态。发布价格权益、暂停销售和“对用户开放”是独立操作；日期变化不会自动开放。只有 Root 且非代管上下文可操作，数据库记录操作人和时间。
- 手动开放前重新核验基础服务开关、发布状态、结束时间、所有套餐成本和固定商品绑定。允许提前开放并展示“即将开始”，购买仍须到开始时间。一次只开放一个推广版本；切换、关闭与创建活动意图通过同一 InnoDB 单行锁串行核验，切换在事务内完成。
- 暂停或结束撤下推广入口，已开放的详情保留状态说明；手动关闭则普通用户直达也不可用。活动关闭只阻止新意图，不改变原有快照、核单和到账资产。
- `GET /api/support/campaign-entry` 返回轻量入口或空结果；`GET /api/support/campaigns/:campaignKey` 按商店认证规则返回开放版本、服务端时间、生命周期和账号限购目录，不返回隐藏或草稿版本。所有入口共享缓存及在途请求，页面进入、恢复前台时刷新，到期撤下入口；隐藏时不渲染场景图片。
- PC 入口位于顶部搜索左侧；移动今日入口位于每日简报后、待处理前；个人中心复用共享入口定义，移动四格快捷入口保持原结构；商店保留次级入口。
- 管理员通过现有鉴权活动管理列表预览，正式展示与四档待核价预览共用组件。没有公开预览参数，示例不创建正式商品或支付入口。
- 新结算只允许在 `[startsAt, endsAt)` 内生成。生成后的意图保留 24 小时，活动结束或暂停不改变已有有效意图的快照。
- 每用户限购默认一次，可配置 1～20 次。首版没有全站库存，避免外部支付完成后因抢空无法到账。

## 结算与发放

1. 后端按用户选择的目录型号生成爱发电商品结算页 `product_type=1`，提交固定 `plan_id` 和一条 `sku`（`count=1`）。通过随机 `custom_order_id` 关联结算意图，数据库只保存随机码 SHA-256 摘要。每单一份。
2. `support_checkout_intents` 冻结爱发电商品方案和型号、金额、基础权益、预计权益、首购候选、目录/活动版本、活动时窗及限购。旧订单缺少商品快照，继续按原赞助类型和金额核对。
3. Webhook 仅登记待复核订单。发放前通过爱发电订单 API 核对支付状态、实付金额、付款身份、`custom_order_id` 和商品方案，并从 `sku_detail` 确认只有一条明细、型号相同、数量为 1。
4. 错误型号、明细缺失或多件写入 `support_entitlement_grants` 人工复核。实付金额不符、过期、身份、归属和限购冲突也进入复核。同价商品分别核验，按订单快照发放选定套餐。
5. AI 通过永久余额批次账本入账，空间通过共享容量流水入账；组合权益使用订单同步现有事务，任一步失败会整体回滚。
6. 只有历史首购候选会在发放事务内再次核验轻笺账号与实际付款身份。v2/v3/v4 含 AI 订单使用同一个账号级范围键，兼容已冻结的历史 AI/组合 SKU；账号和付款身份两组唯一索引阻止并发重复加赠。历史 v2/v3 纯空间首购写各自 SKU；v4 固定空间与 v5 全部常驻订单不读写首购事实。
7. `support_order_id`、AI 流水幂等键、空间流水 ref 和结算意图消费标记共同防止 Webhook 重推、历史同步或并发复核重复发放。
8. 已入账订单反转只标记 `reversal_review`，不自动扣除已使用资产，也不删除首充领取记录。

`POST /api/support/checkout-intents` 返回固定商品支付地址和安全意图 ID。原 `/api/support/checkout?skuId=...` 跳转使用同一套固定商品核验。旧赞助结算地址 `/api/support/donation/checkout` 和 `/api/support/checkout?option=...` 均返回 410；此前已创建的赞助意图保留原订单归属规则。

`GET /api/support/checkout-intents/:intentId` 只允许查询当前账号所属意图，直接读取已有核单和发放事实，返回待支付确认、处理中、到账、过期或人工复核。接口不返回支付凭证或第三方原始数据，不调用支付渠道、不触发入账；实发权益与预计快照分别展示。前端最多短时轮询约一分钟，关闭弹层、离开页面或隐藏页面即停止；账号切换清除安全 ID 与任务上下文并丢弃迟到响应。安全 ID 可在账号隔离的标签页存储中恢复，支付地址不持久化；到账后刷新资产和购买记录，返回任务由用户主动继续。

## 订单归属与未关联兜底

| 发起方式                             | 是否必须预先关联爱发电 | 归属与到账                                                                                             |
| ------------------------------------ | ---------------------- | ------------------------------------------------------------------------------------------------------ |
| 登录后从轻笺选择常驻或活动套餐       | 否                     | 一次性结算意图绑定轻笺账号；API 核单后按套餐快照发放，实际付款身份用于归属与冲突核验。                 |
| 已关联账号后直接在爱发电主页支持     | 已关联                 | 按爱发电身份归并到轻笺账号并计入支持记录；没有套餐意图时不发权益。                                     |
| 未关联账号且直接在爱发电主页支持     | 否                     | 订单保持未归属的纯支持且不发权益；之后关联同一爱发电身份时可归并记录并参与榜单，但不会补发 AI 或空间。 |
| 商品订单缺少匹配的结算意图           | 不适用                 | 用途保持 `unknown` 并进入人工复核，权益只按有据可查的结算意图发放。                              |

爱发电身份已关联其他轻笺账号，或一次性凭证与关联身份指向不同账号时，订单进入归属冲突/人工复核，禁止自动转移。权益购买必须从登录后的轻笺资源商店生成一次性结算意图；爱发电账号关联不是购买前置条件，只是付款身份核验、历史跨账号首购防重复和直接支持归属的辅助证据。

## 积分边界与观测

- 积分兑换目录、价格与限购以 `apps/server/util/pointsEconomyCatalog.js` 和 [积分经济](./points-economy.md) 为唯一事实源；资源商店不得复制或反推该目录。
- 至少观察 60 天。只有普通用户空间兑换累计达到 20 笔，或容量使用超过 75% 的活跃普通用户占比达到 5%，才启动下一版积分经济评审。
- 资源商店购买与积分兑换最终进入同一永久资产，但来源账本、版本和运营指标必须分开；人民币价格不能反推成可兑积分汇率。纯支持不进入任何资产账本。

## 发布开关与顺序

以下开关默认关闭：

- `SUPPORT_PACKAGES_CATALOG_ENABLED`
- `SUPPORT_PACKAGES_CHECKOUT_ENABLED`
- `SUPPORT_PACKAGES_GRANT_ENABLED`
- `SUPPORT_CAMPAIGNS_ENABLED`

`SUPPORT_PACKAGES_AFDIAN_PRODUCTS` 是服务端 JSON 对象，键为 `目录版本/型号 ID`，值为爱发电的 `planId` 和 `skuId`（各 32 位十六进制）。常驻套餐示例键 `support-packages-v5/ai-50`，活动键 `campaign:<campaignId>:v<version>/<campaignSkuId>`。每个外部 SKU 只能绑定一个键。价格以爱发电商品后台与轻笺目录核对一致为准；缺少绑定的套餐不可下单。改绑定只影响后续生成的结算意图。

Vite 开发环境若服务端目录版本不同或目录开关仍关闭，前端会从 `@lightnote/shared` 展示 12 个常驻套餐的只读本地预览。该预览展示固定权益并明确支付关闭，不显示首购资格，不得生成爱发电套餐订单。生产构建不允许使用此前端回退，仍由服务端目录与发布开关唯一控制。

安全发布顺序：

1. 确认已有套餐和活动迁移及 [v5 帮助同步](../apps/server/migrations/20261023_support_packages_v5_knowledge.sql) 就位，再显式应用 [固定商品迁移](../apps/server/migrations/20261107_afdian_fixed_products.sql) 和 `check:schema`。新列为可空，历史用途、价格、权益、发放记录及首购事实原样保留。
2. 滚动发布时关闭结算和发放。待全部 API 与 Worker 统一使用固定商品核验后，先开启发放以处理已有订单。保持 `support-pure-v2` 的原激活时间与已冻结用途。
3. 在爱发电上为要开放的套餐配置对应商品，逐项核对型号与售价，再填写服务端绑定。在受控范围验证一笔真实商品订单，确认 API 回传归属凭证、方案和单件型号，确认同价错型、多件和实付异常进入复核，确认历史订单仍可结算。完成核对后开放常驻目录与结算。
4. 创建活动草稿、通过成本门禁并发布。配置活动商品并启用 `SUPPORT_CAMPAIGNS_ENABLED` 后，由 Root 在后台手动开放指定版本。
5. 回滚入口时继续保留能处理既有固定商品的发放版本。回滚后端前关闭发放，核实已付款订单完成或进入待处理，保留本次新增列。


发布后按常驻/活动 SKU 分别观测点击、结算、实付、首充、复购、AI 消耗、空间占用、人工复核、反转和实际成本余量。

## 购买返回、成本与转化

- 获取入口通过标签页内、账号隔离的 24 小时上下文记录来源和返回位置。任务输入只保存在本机 sessionStorage，不进入 URL、行为事件或订单；退出和切换账号清除。返回任务先核对显式材料，再由用户主动继续；重新打开面板不自动调用 AI。
- 行为事件通过 `/api/support/events` 白名单写入现有操作日志，模块为 `entitlement_funnel`。结算入口只接收可选 `flowId` 做分析关联，不影响合同和付款归属；`checkout_created` 只能由服务端记录。付款、到账分别读取核验订单和权益流水，不用前端轮询推算。
- `scripts/reportEntitlementRevenue.js --days=7|28|60` 强制数据库只读、仅输出聚合。行为按账号/流程/商品去重，交易按订单去重，未匹配流程单列 unattributed。新用户指事件发生时注册未满 7 天；等级分组使用事件时等级，低等级额度不足统计按查询时 Lv.1–3，不能解释为历史等级。付款按核验时间窗口统计，尚未到账和窗口前创建意图会造成漏斗不齐，不能据此宣称严格转化率；不足 20 名买家标注样本不足。历史没有埋点的行为不回填。
- 模型价格唯一来源为 `aiCostPolicy.js`，按模型、缓存与峰谷核算。未知或价格生效前的调用返回未知；运营中心以“—”展示含未知项的估算，实际支付账单仍以供应商为准。部署前应用 `20260909_ai_cost_unknown.sql`，允许成本列为空，不改历史数据和用户资产。
- `support-cost-v2` 按现有各阶段模型配置的最高适用单价加 20% 计算 AI 保守成本；任一模型未登记价格时阻止核价。空间沿用满额使用 96 个月、加 30% 的假设，渠道费沿用 6%。这些是测算假设，不保证常驻套餐盈利，也不自动变更已发布合同。
- 管理端节日专题展示草稿的价格、权益和日期均为待核定，不创建支付 SKU；正式活动与草稿复用专题组件。有效数字草稿仍由现有成本和发布门禁管理，未发布活动不进入公共目录。

## 场景与展示

资源商店宽屏内容区上限为 1280px，桌面展示场景图和四列套餐，手机展示正文和两列套餐。秋日专题使用 `BrandSceneHero`，按端型选择场景图。页面沿用现有导航与移动顶栏，价格、权益和按钮始终为 DOM。深色主题对场景图调色，正文使用主题变量和可读字号。素材来源、编辑提示词和尺寸见 [场景素材说明](../apps/web/public/brand-scenes/README.md)。
