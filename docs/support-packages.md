# 爱发电资源商店套餐 v3 规范

> 本文是独立资源商店中常驻套餐、限时套餐、首购范围、结算快照与权益发放的实现和运营规范。常驻目录的代码唯一事实源位于 `@lightnote/shared`，当前版本为 `support-packages-v3`。

## 产品边界

- 支付仍由爱发电处理，轻笺不接触银行卡、付款码或支付口令。
- `/support` 只承载自愿支持，不赠送 AI、空间、积分或功能权益；已确认且可信归属的支持订单可以按用户隐私偏好进入支持者榜。
- `/store` 只承载 AI、永久空间和组合权益购买；购买金额、笔数和身份永不进入支持者榜，也不改变支持者身份。
- 两类业务虽然复用爱发电支付与订单核验，但必须由 `support_orders.order_purpose` 冻结为 `donation`、`entitlement_purchase` 或历史 `legacy_support`，禁止再按金额、档位或支付渠道推断用途。
- 用户绕过轻笺直接在爱发电主页付款且没有可信套餐结算意图时，一律视为纯支持；是否关联爱发电只影响支持记录归属和排行榜展示，不会把纯支持升级成权益购买。
- `support-ai-v1` 仅解释切换日前已承诺的 `legacy_support`。既有已发额度不追回；切换后的纯支持使用零权益策略 `support-pure-v2`，不得重新触发旧赠送。
- 常驻套餐与限时活动是两套独立目录。活动 SKU 直接配置最终售价与最终到账，不叠加、也不消耗常驻首充。
- 含 AI 的常驻套餐共用一次账号级首购：AI 精确加赠 20%，组合包的空间仍按基础值到账；买过任一 AI 或组合套餐后，其他 AI 与组合档位都按基础值到账。
- 纯空间常驻套餐继续按 SKU 各有一次整洁容量首购。资格同时受轻笺账号与爱发电付款身份约束；v2 中任一 AI/组合首购记录会视为已使用账号级 AI 首购。
- 旧赞助不回填首购领取记录。退款或订单反转进入人工复核，不自动恢复首购资格。
- 有 v2 结算意图的订单只能进入通用权益账本；它仍按意图冻结的基础/首购权益快照结算，但发放时与 v3 一样重新核验账号和实际付款身份，含 AI 套餐统一占用账号级首购范围。少付、多付、过期、身份冲突或功能关闭都只能等待复核，任何失败不得降级成纯支持或旧赠送。

## 常驻目录

常驻 SKU、价格、基础权益、首购权益与组合节省金额只在 `@lightnote/shared` 的版本化目录中定义，并由服务端目录测试逐项锁定；本文不复制可执行数值。v3 保持 AI、云空间和组合三类分档：AI 与组合使用账号级 AI 首购范围，纯空间使用 SKU 级首购范围。已发布目录不得原地改值；调整价格或权益必须发布新目录版本。

## 限时活动

- 活动有稳定 `campaignKey` 和递增版本；同一版本内套餐标识唯一，每个活动套餐使用跨版本唯一的 `campaignSkuId`。
- 草稿可创建和成本预览；发布时再次按当前成本口径计算，任一 SKU 保守直接成本余量低于 40% 时失败关闭。
- 已发布活动的价格和权益不可修改，只能暂停；调整必须创建新版本。
- 新结算只允许在 `[startsAt, endsAt)` 内生成。生成后的意图保留 24 小时，活动结束或暂停不改变已有有效意图的快照。
- 每用户限购默认一次，可配置 1～20 次。首版没有全站库存，避免外部支付完成后因抢空无法到账。

## 结算与发放

1. 后端生成含精确 `custom_price` 与随机 `custom_order_id` 的爱发电地址；数据库只保存随机码 SHA-256 摘要。
2. `support_checkout_intents` 保存金额、基础权益、预计权益、首充候选、目录/活动版本、活动时窗及限购的不可变快照。
3. Webhook 只把订单登记为待复核；发放前必须通过爱发电订单 API 确认实付金额、支付状态、订单身份和权威 `custom_order_id`。
4. 少付、多付、过期支付、身份冲突、归属冲突和限购冲突写入 `support_entitlement_grants` 人工复核状态，不发权益。
5. AI 通过永久余额批次账本入账，空间通过共享容量流水入账；组合权益使用订单同步现有事务，任一步失败会整体回滚。
6. 首购候选只是下单时的展示快照；发放事务会再按轻笺账号与实际付款身份核验历史 v2 SKU 和账号级范围键。部署后的 v2/v3 AI 与组合订单都写同一个账号级范围键，由账号和付款身份两组唯一索引阻止并发重复加赠；纯空间仍写各自 SKU。
7. `support_order_id`、AI 流水幂等键、空间流水 ref 和结算意图消费标记共同防止 Webhook 重推、历史同步或并发复核重复发放。
8. 已入账订单反转只标记 `reversal_review`，不自动扣除已使用资产，也不删除首充领取记录。

纯赞助与权益购买使用不同的轻笺结算端点：新版纯赞助固定走 `/api/support/donation/checkout`，权益购买走 `/api/support/checkout?skuId=...`。旧版 `/api/support/checkout?option=...` 不兼容跳转，必须返回 `410 SUPPORT_CHECKOUT_LEGACY_RETIRED`，避免前后端滚动发布期间旧页面承诺赠送、新后端却按零权益处理。

## 订单归属与未关联兜底

| 发起方式                             | 是否必须预先关联爱发电 | 归属与到账                                                                                             |
| ------------------------------------ | ---------------------- | ------------------------------------------------------------------------------------------------------ |
| 登录后从轻笺选择常驻或活动套餐       | 否                     | 一次性结算意图绑定轻笺账号；API 核单后按套餐快照发放，并用实际付款身份核验首充与跨账号重复。           |
| 登录后从轻笺选择“单纯支持”           | 否                     | 一次性支持意图绑定轻笺账号；API 核单后只记录纯支持，不发任何权益，可按隐私偏好进入支持者榜。           |
| 已关联账号后直接在爱发电主页支持     | 已关联                 | 按爱发电身份归并到轻笺账号并计入支持记录；没有套餐意图时不发权益。                                     |
| 未关联账号且直接在爱发电主页支持     | 否                     | 订单保持未归属的纯支持且不发权益；之后关联同一爱发电身份时可归并记录并参与榜单，但不会补发 AI 或空间。 |
| 订单携带无法识别的 `custom_order_id` | 不适用                 | 用途保持 `unknown` 并进入人工复核；不得猜成纯支持，也不得按金额匹配套餐。                              |

爱发电身份已关联其他轻笺账号，或一次性凭证与关联身份指向不同账号时，订单进入归属冲突/人工复核，禁止自动转移。权益购买必须从登录后的轻笺资源商店生成一次性结算意图；爱发电账号关联不是购买前置条件，只是付款身份核验、跨账号首购防重复和直接支持归属的辅助证据。

## 数据职责

| 表                                                      | 职责                                                |
| ------------------------------------------------------- | --------------------------------------------------- |
| `support_orders`                                        | 第三方订单唯一事实，以及不可变的支持/购买用途边界   |
| `support_reward_policy_state` / `support_reward_grants` | 历史支持赠送与新版纯支持零权益处理记录              |
| `support_campaigns`                                     | 活动版本、时窗与发布/暂停事实                       |
| `support_campaign_skus`                                 | 活动最终价格、权益、限购及发布成本余量              |
| `support_campaign_user_limits`                          | 用户完成次数与 24 小时活动意图占位                  |
| `support_first_purchase_claims`                         | 账号/付款身份的 AI 账号级或空间 SKU 级首购事实      |
| `support_entitlement_grants`                            | 订单金额、计算/实际 AI 与空间、首购、流水和复核状态 |

账号注销时保留去标识化交易快照和首充防重复事实；轻笺用户标识使用不可逆墓碑替换，活动未完成占位删除，未消费结算意图同时取消并收短有效期。注销后晚到的支付只进入 `account_deleted` 人工复核，不向墓碑 ID 发放资产。

## 积分边界与观测

- 积分兑换目录、价格与限购以 `apps/server/util/pointsEconomyCatalog.js` 和 [积分经济](./points-economy.md) 为唯一事实源；资源商店不得复制或反推该目录。
- 至少观察 60 天。只有普通用户空间兑换累计达到 20 笔，或容量使用超过 75% 的活跃普通用户占比达到 5%，才启动下一版积分经济评审。
- 资源商店购买与积分兑换最终进入同一永久资产，但来源账本、版本和运营指标必须分开；人民币价格不能反推成可兑积分汇率。纯支持不进入任何资产账本。

## 发布开关与顺序

以下开关默认关闭：

- `SUPPORT_PACKAGES_CATALOG_ENABLED`
- `SUPPORT_PACKAGES_CHECKOUT_ENABLED`
- `SUPPORT_PACKAGES_GRANT_ENABLED`
- `SUPPORT_CAMPAIGNS_ENABLED`

Vite 开发环境若连接到尚未重启的旧后端，或服务端目录开关仍关闭，前端会从 `@lightnote/shared` 展示 12 个常驻套餐的只读本地预览。该预览必须明确标注“结算关闭、首充待服务端核验”，不得生成爱发电套餐订单；生产构建不允许使用此前端回退，仍由服务端目录与发布开关唯一控制。

安全发布顺序：

1. 应用 `20260825_support_packages_v2.sql` 与 `20260825_support_donation_store_split.sql`，再执行最新的资源商店帮助同步；v3 复用既有首购事实表，以保留 v2 订单快照兼容。
2. 发布兼容代码并保持全部套餐开关关闭。滚动发布期间尤其要保持 `SUPPORT_PACKAGES_GRANT_ENABLED=false`；等待旧实例和旧 Worker 全部退出、确认所有发放进程都是同一版本后才能重新启用，禁止旧实例写 v2 SKU 与新实例写账号级范围键的混跑窗口。`support-pure-v2` 第一次写入的时间是新旧支持规则边界，不得在重跑迁移时移动；已冻结的 `order_purpose` 不得被后续同步重解释。
3. 执行测试、MySQL 5.7 Schema 门禁和只读线上核验；确认历史 `legacy_support` 仍保留旧处理结果、新 `donation` 为零权益、v2 待结算订单按原快照发放、`entitlement_purchase` 不进入支持者榜。
4. 确认全部实例已切到统一账号级范围键实现后，先启用 `SUPPORT_PACKAGES_GRANT_ENABLED`，再启用目录和结算，确保任何新付款都有当前处理器；服务端同时把发放开关作为结算的硬依赖，顺序配错时付款入口会失败关闭。
5. 观察常驻套餐结算与发放后，创建活动草稿、通过成本门禁并发布，再启用 `SUPPORT_CAMPAIGNS_ENABLED`。
6. 只能独立回滚商店页面或结算入口，已存在付款所需的发放进程必须继续保留 v3 实现；若后端本身必须回滚，先关闭发放并等待当前订单进入待处理或完成，禁止重新启用 v2 发放器。功能关闭期间的 v2 已付款订单必须保持待处理，禁止改走纯支持或旧规则。

发布后按常驻/活动 SKU 分别观测点击、结算、实付、首充、复购、AI 消耗、空间占用、人工复核、反转和实际成本余量。
