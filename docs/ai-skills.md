# 模块化 AI Skills

本文是轻笺现行 AI 产品形态、协议、执行与计费边界的唯一架构说明。Skill 清单和字段细节以代码注册表、共享协议和契约测试为准，不在文档复制易漂移列表。

## 产品边界

- 轻笺不提供万能助手、普通闲聊、全局工具选择或跨模块自由规划。
- 页面选择封闭的 `skillId`；服务端 Registry 决定版本、角色、资源类型、数量上限、历史窗口、模型策略和输出契约。
- 模型只处理当前 Skill 已授权的任务，不重新选择业务模块，也不能扩大资源范围。
- 一个高价值固定成果对应一个主 Skill Profile；Profile 可以复用证据加载、Grounding、Gateway 和 Execution 工厂，但不得把多种成果只区分为同一通用 Skill 上的不同用户提示词。用户输入只调整已选 Skill 的关注点，不能触发隐式跨 Skill 路由。
- 旧 Agent 会话、V2/V3 Runtime、Memory 和通用工具入口只保留数据导出、删除和审计兼容，不再进入普通用户上下文。旧回答反馈不再提供后台页面、处理接口或待处理中心任务；历史反馈数据沿用原有导出和删除边界。

## 请求与资源边界

- 请求只接受共享协议声明的字段；未知字段、未知 Skill、版本不符、非法终态和越权资源失败关闭。
- 客户端资源 ID 只是候选。服务端从认证后的 actor/subject 重新读取 owner、当前版本和内容，再生成范围摘要；标题、URL、正文和前端缓存不是权威身份。
- 聚合范围使用单个领域选择器而不是由前端展开资源列表。标签问答/分析只提交标签 ID；笔记目录问答提交服务端协议声明的 `parentId + includeDescendants`，其中 `parentId` 表示当前父页面、范围是其子页面，是否递归必须显式选择。Context Resolver 再从关系表或笔记树解析当前 owner 下全部存活资源、重新校验版本，并按 Skill 声明的明确上限失败关闭；不得用分页首屏或静默截断代替完整范围。
- thread 绑定 `skillId + skillVersion + actor + subject + scopeDigest`。不同 Skill、资源集合或 subject 不共享自然语言历史。
- 历史只用于理解省略，每轮事实都重新从当前权威资源加载。零历史 Skill 不得因前端保留聊天 UI 而获得旧材料。
- Help 只读取公开帮助；无命中时仍由模型生成问候或澄清引导，不补造产品事实、引用与链接，不将无命中呈现为读取故障或附带无效动作；Search 只读检索当前 subject 的私有资料；管理员上下文继续遵守 actor/subject 与 readonly/maintain 边界。

## 写入与确认

- 写 Skill 只能生成结构化草稿或预览。真实写入必须由用户确认，并复用 `util/services/` 的权限、事务、版本、幂等和审计能力。
- 模型文案、旧预览、HTTP 200 和成功语气都不是执行回执。对象版本变化时返回冲突，不能静默覆盖。
- 日期、时间、owner、资源绑定和执行字段由服务端确定性计算或注入；模型不得计算绝对时间、抄写已校验 ID 或自行指定目标用户。
- 结构化参数归一化后必须再次通过共享 Schema；失败时只允许协议定义的有限修复或明确错误。

## 来源与输出

- 有来源的事实回答通过 `submit_grounded_answer` 提交分段正文和来源索引；引用编号由服务端生成，模型不得手写。
- 来源缺失、越界或输出协议失败最多进行一次受控平台修复；修复不能扩大材料范围。
- 帮助问答沿结构化工具参数流逐段解析，只有正文与来源编号通过校验的完整段落才增量展示；完整工具调用与最终响应仍须校验。修复先重置中间结果，失败或取消不保留未完成结果，也不能保存为笔记。非流式入口复用同一输出协议与修复预算。
- 固定成果 Skill 在通用引用契约之上声明业务结构校验；该校验与通用协议共用同一次平台修复机会，修复后仍失败则硬终止，禁止在外层通过整任务重试无界增加模型调用。
- Coverage 由服务端实际装载和成功处理的证据计算，不用“全部、所有、唯一”等正文关键词猜测。
- 完整范围超过单次证据预算时，Skill 必须按固定批次生成带来源的中间结果，再映射回原始来源做最终汇总；响应同时返回总数、已纳入数、不可读数和截取数，不能把分批执行描述成抽样分析。
- 计数、完整列表、分类统计和执行结果来自结构化查询；模型基于这些权威事实判断重点、生成洞察和行动建议，不从片段或历史回答反推精确事实。
- 今日简报沿用账号自然日、开关、只读预览、幂等租约及“检查 → 有变化才更新”的链路。后台页面停止检查；更新或持久化失败保留已交付内容及真实数据截止时间，事实变化时标记旧条目，不能直接替换旧文数字。总开关及自动更新偏好由专用接口写入，旧页面整对象保存偏好必须保留二者。
- 简报精选当前需要关注的事项：单次待办最多一条，按优先级、真实逾期截止及临近时间选择；同档普通安排优先下一次尚未到来的事项。新旧重复任务均排除，单次任务的重复催办不视为重复任务。截止、开始、计划日与提醒时间分别表述，完成、删除、跳过和延期后的事实及时重新检查。待办不占满简报，不显示全量任务数字或“查看全部”清单入口；其他来源独立入选，不以是否存在待办为条件。项目最多一条，优先今天到期、逾期及七天内到期，其次是有明确下一步的活跃项目；新成果、有效待审核建议及资源整理也可出现。没有重要事项时仅显示简短状态，不强制生成洞察或建议；共同标签关联不入选；今日新增书签、笔记和文件的真实数量可作为顶部一行概览，不占重点条目，不扩写收藏习惯。
- 资源整理汇总最多一条，分别显示真实待整理资料和未忽略的无标签资源，使用对应列表的统一读模型；两类可能重叠，不相加为待处理总数。仅为仍有事项的类型提供入口。背景复用待整理列表中最近两项的标题与类型、当前有效审核建议的资源类型与建议种类；正文背景不扩写资料内容，不推断积压原因或处理收益；底部内容建议的有界读取规则见下文。这些背景参与事实版本，数量未变但对象更名或替换也须刷新。
- 未从工坊提醒中移除的处理失败或保存失败任务优先展示，普通暂停不视为失败；失败提醒与有效未保存成果各保留一条，不互相遮蔽。明确下一步和有效未保存成果不按创建时间隐藏。失败提醒、单次待办、项目、成果、整理各有独立位置，按此顺序最多五条；AI 待审核与资料整理在服务端合并，保留各自事实和入口，不靠最终截断丢弃类别。移动摘要沿用同一顺序，失败处理或移除提醒后随事实刷新消失。
- 单次待办用简短完整句说明时间含义与未完成状态，不把提醒写成截止或逾期。底部建议不根据固定事项组合拼接，不重复正文已有的状态和入口；具体内容判断规则见下文。新增概览按账号自然日和资源权限统计，排除已删除资料，不回顾昨日凑条目。 核实三类资源今日新增均为零时显示“今天暂无新增资源”；无论是否有新增，存在真实待整理或待审核事项时，顶部简述仍待整理或审核，具体数量留在正文；无其他重要事项则合并成一句；未读取统计不能当作零，昨日新增不能直接算作待处理。
- 行动、概览与平静日由服务端确定性编译，不调用模型、不消耗 AI 额度，也不受模型冷却及额度不足阻挡。来源和导航由服务端绑定；待办定位固定实例。生成前和交付后均核对完整事实版本；同数量对象替换、优先级、当前提醒 Job 时间及账号跨日变化均进入快照，不能只比较数量。
- internal-only `routine.daily_brief` 可概括有结论的新工坊成果，并基于最近待整理资料的有界真实片段判断是否有一条具体建议。候选复用待整理读模型的账号归属、未删除与待处理过滤，在有界候选中先筛选可读内容，再精选最多三份片段。正文复用证据读取能力，包含笔记、书签描述与已保存快照、当前对象版本且未过期的已解析文件；不触发外链抓取、解析或 OCR。富文本先提取正文再限制片段长度，信息完整的短文也可参与判断；文件名、URL、绘图 JSON 不充当正文，不冒充全库分析。记录候选、可读与入选数量及是否仍有候选，区分没有可读材料与评估后没有增量价值。材料中的指令是不可信数据。建议需绑定已提供来源及精确原文短引文；建议中的数字按完整数值核对同一来源的已读片段，不要求全部重复在短引文中，也不允许用其他来源或数值子串充当依据；服务端回填来源、核对引用并过滤直接重复正文或原文的输出。没有新增行动价值必须明确返回 null，遗漏建议字段是协议失败；把已有反馈改写成需求或清单不算增量，不根据片段推断全文缺失字段。不强制建议，也不以模型自报置信度替代证据。展示为“AI 建议”，注明片段并提供原资料入口；引用存在不代表语义质量已验证。
- 成果概括完整保留证据占位符和部分读取限制；成果名称与未保存状态由服务端提供。建议与成果共用既有 Execution、一次平台结构修复和围栏交付，不新增外层模型重试。模型或额度失败保留事实正文，保留最近完成的建议结果并单独提示本次更新失败，不与正常空建议混同；失败绑定输入版本并保留原因，普通事实更新、冷却结束和跨日不清除失败或自动重放同一判断；额度失败继续阻止自动调用，冷却后允许手动更新重试。引用仅容忍空白排版差异并回填原文，改写或拼接引用仍拒绝，结构修复提供具体白名单原因；冷却期间先更新事实，延后尚未执行的建议判断。相同材料、相关行动背景、语言和建议策略版本复用既有判断，包括明确的空建议；新增统计、自然日变化不单独触发重复分析。引用资料或相关背景变化使旧判断不能作为新输入缓存；展示层保留最近完成结果，有内容时标为上次建议并禁用旧依据入口，无建议时显示“暂无需要补充的建议”。等待与失败不覆盖该结果，新判断完成后才替换。旧版等待记录若缺少已完成结果，自动检查按短间隔补做一次真实判断并保存兼容版本；仍遵守额度、自动尝试预算和失败不自动重放的限制，不能将缺失历史当作无建议。冷却和账号日尝试预算仅限制真实模型调用；实际调用计入今日简报用量。输入片段仅保存在账号简报缓存中，不写入通用日志或遥测。

- 整理审核与整理页使用相同当前一轮选择顺序和有效建议口径；当前一轮仍有有效待审核建议就可进入简报，不按任务启动时间隐藏。审核入口绑定同一轮任务和资源类型。对象数、建议条数、待整理数、无标签数与未完成项不得互换，不累计历史批次，也不通过简报更新修改审核状态。
- 事实读取、Provider 外发和交付持有账号生命周期会话锁（[锁与连接预算](./architecture.md#worker-与副作用)），不跨模型等待持有普通账号行锁。多请求重读已交付快照；AI 结果须在根 Execution 成功结算前以租约围栏持久化，写入失败或租约失效视为无可交付结果并退回用户额度，不能以事实降级重试未知的持久化结果。

## Execution 与计费

- 所有真实 Provider 调用都必须经过 `aiGateway.js` 并归属唯一根 AI Execution；源码门禁禁止裸 Provider 和未登记调用方。
- 用户动作在第一次真实 Provider 调用前懒占位一次。缓存命中、确定性解析和纯本地处理不占模型额度。
- 额度闸门用包含在途预留的余额阻止并发超卖；用户界面展示已结算余额，并用 `pendingReservedTokens` 单独标出在途预留、用 `availableRemaining` 解释当前还能供新任务使用的额度。禁止把临时预留伪装成已消费或余额归零。
- `AI_QUOTA_EXCEEDED` 只表示当前总可用额度为零；余额仍大于零但低于本次调用保守预算时返回 `AI_QUOTA_INSUFFICIENT_FOR_REQUEST`，并携带本次所需与当前可用预算。所有 AI 入口必须复用共享协议和统一前端提示，不得把两类情况合并成“今日额度已用完”。
- 同一 Skill 内输出规模不同的固定动作应声明各自模型输出预算；标题、摘要、大纲等短输出不能沿用全文改写上限。无法在剩余额度内安全完成的全文任务应明确建议减少或分段处理，不能先向 Provider 发出可能超额的请求。
- Provider 阶段计划可在 Context Resolver 得到权威材料规模后、首次调用前重编译；一旦开始占位或访问 Provider 就锁定，避免聚合选择器被按“一项材料”错误计费或放宽调用上限。
- 主调用、图片识别、结构修复和 Provider 失败分别记录 Span，并由根 Execution 形成唯一终态；用户额度只结算明确属于用户的真实 usage。
- 平台协议修复由平台承担。usage 缺失按已声明预算保守结算，不能让已发出的调用变成免费，也不能超过预占。
- 等级每日上限由 `growth.js` 的 `RANKS` 唯一定义，Lv.1 为 10 万、Lv.10 为 30 万、Lv.15 为 50 万。新上限不清零当日已用量，不追扣历史消耗；在途请求按预占快照结算。页面仍显示 AI 额度和原 Token 数值。
- 每日等级额度与永久 AI 余额是两个可解释资产，按服务端固定顺序消耗；Root 不获得隐形免费调用。
- `system` 计费覆盖只允许受信任的服务端调用方显式注入固定系统主体，公开请求、页面字段和客户端 Header 均不能选择该策略；执行仍保留完整 Execution、Span 与 usage 审计。
- Registry 同时支持公开与 internal-only Skill。internal-only Skill 不得出现在 `/ai/skills/config` 或被公开执行，但为了让用户理解真实 AI 消耗，其可读动作名可以进入用量目录。只有服务端传入的已登记调用者身份与该 Skill 允许的计费策略同时成立时才能执行；客户端 `surface`、body、query 或 Header 都不是内部身份。
- 新增标签的图标搜索与整理图标补全共用关键词转换：中文名称使用 `tag.icon_keywords` Execution，英文直接检索，缓存命中不调用模型；真实转换归入既有标签用量。整理图标补全在用户确认并完成轻量检查后分流：直接检索和缓存命中使用免费队列，关键词随任务保存；确需转换的才进入 AI 队列。未外发前新命中缓存可转为免费处理；AI 队列数量不是实际模型调用次数。暂停与额度不足只影响 AI，免费准备和匹配继续；预检、应用图标与批量应用均不调用模型。
- 整理工作区的规则预检与清理检查不创建 AI Execution。每个需要理解内容的资源使用一次 `organize.metadata` Execution，笔记标题和标签、书签名称与描述和标签分别共享各自的主调用；同义标签按本轮候选分批比较，预先规划调用与修复上限，找到明确目标后停止；文件名称与标签按已准备材料编译视觉理解、全文分批归纳、候选汇总及平台格式修复的阶段上限与总预算，不固定为一次调用。确定性解析和有效缓存读取免费，部分读取的可审核成果按部分成功结算，读取未完成且无可审核建议按失败处理；额度不足保留成果并暂停剩余 AI 队列，用户明确继续后才恢复消费；已外发且结果不确定的失败不自动重试。用户元信息写入和文件重命名不调用模型。任务快照、租约及应用一致性见 [架构](./architecture.md#资源标签与待整理)。
- 用量模块的筛选、统计和显示共用 `@lightnote/shared/ai-usage-modules`；动作归属由服务端计费目录解析，新动作必须通过模块覆盖断言。整理显示为「AI 整理」，简报显示为「今日简报」，未登记动作才进入「其他」。逐资源计量账本保持独立，历史记录通过动作标识读取当前分类，不改写扣费记录。整理 Worker 在创建 Execution 时写入任务与资源关联；用量列表在分页前按任务汇总，暂停续跑累计到同一条，新任务单列。展开后按所选时间范围分页核对调用，真实模型动作数不因展示汇总而减少；没有明确关联的旧记录保持独立。
- 知识工坊通用固定成果任务允许用户每次选择积分或 AI 额度，不得双扣。积分分支由受信任 Worker 注入 `system` 覆盖；AI 额度分支由同一 Worker 使用默认 `user` 策略，按真实 Token 进入“知识工坊”用量明细。成果页不提供工具内追问；保存为笔记后的追问、润色与反复修改属于笔记模块独立 Skill，使用 AI 额度。PDF 工作台的显式文字总结属于公开、零历史的本地文字输入 Skill，只使用用户 AI 额度；不复用云文件身份，也不走内部积分 Worker。工坊任务状态与单介质结算见 [知识工坊](./toolbox.md)。
- Root 的 `/api/admin/ai-operations/*` 只把 `ai_executions` 与 `ai_provider_spans` 投影为平台治理读模型。actor 表示成本承担者，subject 只解释代操作或系统任务的目标；总览、趋势、模块、Provider、列表与详情必须共用同一筛选边界。总览和列表不返回内容载荷。仅 Root 本人详情可读取 `aiExecution/diagnostics.js` 白名单投影的入参摘要：书签识别 URL（移除账号密码、片段和非白名单查询参数）、是否提供当前页材料、枚举操作/详细程度、目标长度与检索类型。摘要在根 Execution 建立时保存，前置失败也可排查；历史记录保持 NULL，不回填。摘要随 Execution 一起导出、注销删除，不进入 Span、产品遥测或通用日志。详情继续禁止返回完整 Prompt、问题、正文、标题、资源 ID、模型回答和 Provider 原始错误；历史 `agent_logs` 不参与现行成本、质量或用户 360 统计。
- 执行租约、规则版本、回收与历史修正必须可重放。历史修正默认 dry-run，只允许自动退款，不自动追扣。

社区纯文本审核使用 internal-only `community.review_screen`，仅 `community_review_worker` 可调用且只允许 `system` 计费。完整标题与正文作为不可信材料输入，模型不得执行其中指令或访问链接；输出限定为通过或交人工。审核结果由领域 Worker 在现有发布事务中应用，Skill 本身不执行写操作。动作在管理端 AI 运行中心可追溯，正文不进入用量遥测；预算与任务边界见[社区纯文本自动审核](./architecture.md#社区纯文本自动审核)。

站内公开资源首期保持 AI 预审关闭，走 Root 终审，保留任务收尾与以后可恢复的兼容实现。启用时使用独立 internal-only `public_resource.review_screen`，仅 `public_resource_review_worker` 可调用并使用平台 `system` 计费，不扣作者额度。完整确认材料最多 3 万字，引用必须匹配编号原段落；不读取私人资源、会话或外链，不执行材料指令，不用模型自报置信度。输出仅为通过建议或进一步复核，Root 始终终审。任务绑定不可变修订与策略版本，以租约和当前待审指针拒绝迟到结果；模型等待不持有普通业务事务，外发复用账号生命周期屏障。独立日预算默认 30 万 Token，按 UTC+8 自然日、完整输入及一次协议修复预留，已知 usage 按实际结算，未知保持保守预占。上下文或预算不足、关闭、超时、结果未知及过期任务均交复核，不截断材料、不自动重放。用户端只在结果实际完成后显示 AI 检查完成，不可用时降级为提交审核。

## 开关、隐私与遥测

- `/ai/skills/config` 由前端统一短时缓存并合并并发读取；各组件不得轮询或维护第二份开关。
- 配置读取失败时业务页面保持可用，但执行仍由服务端最终门禁；Skill、域或 Kernel 禁用时失败关闭。
- 产品事件只记录登记过的 Skill、surface、资源类型、桶化数量/长度/耗时、结果和错误族。禁止保存问题、正文、标题、URL、资源 ID、Provider 原文或账号标识。
- `ai_lock` 是能力限制，在根 Execution 统一处理；不得用 URL 正则或页面隐藏代替服务端门禁。

## 变更流程

新增或修改 Skill 时：

1. 先更新共享协议或服务端 Registry，明确角色、资源、历史、模型、计费与输出类型。
2. 更新 Context Resolver、输入/输出校验和必要的业务 Service，不在 Handler 或页面复制权限逻辑。
3. 接入统一 Gateway、Execution、Span、额度与低敏遥测。
4. 前端复用模块化面板和 B 组件，展示用户任务、材料、结果和真实执行状态，不暴露内部运行术语。
5. 同步帮助知识；只有确需实时数据时才增加受控查询能力。

## 验收门禁

- `pnpm --filter server check:ai-model-access`
- 服务端协议、Registry、归属、空材料、解析失败、额度不足、Provider 失败、输出校验、幂等与冲突测试
- 前端加载、成功、空、错误、取消、重试和确认状态测试
- 类型检查与受影响构建

日常测试使用 Provider mock、协议夹具和确定性结果。只有变更 Provider 协议、模型或生产兼容性且获得明确授权时，才运行最小真实调用；报告不得包含用户材料或 Provider 原文。

### 工坊翻译

内部 `toolbox.translation` 仅允许 `toolbox_worker` 调用，计费策略限定为用户 AI 额度。权威正文准备完成后按全部分段编译 Provider 调用预算，所有分段共用一个根 Execution，并仅允许一次平台承担的结构修复。结构化输出包含段落身份、完整标记与译文；流式草稿从 Gateway 的结构化增量解码并还原代码／链接占位，不将未完成 JSON、半个转义字符或保护标记直接显示给用户。草稿只用于页面预览，平台修复可重置当前段落；校验代码／链接标记、表格列及 Provider 截断状态，完整成果提交成功后才能按实际用量结算。页面展示、双语切换及保存不调用 AI。材料来源、隐私保留和取消规则见 [知识工坊](./toolbox.md#ai-翻译)。

### 资料转表格

内部 `toolbox.extraction_suggest` 与 `toolbox.extraction_extract` 仅由 `extraction_worker` 调用，仅允许用户 AI 额度。建议或每个完整处理窗口分别拥有唯一根 Execution，每次最多一次用户计费的生成调用，结构或原文引用校验失败时可进行一次平台承担的修复，修复后仍执行同等严格校验；完整性失败及结果不确定的外发调用不自动重发。失败不扣用户额度，实际用量从执行账本聚合，解析与本地 OCR 免费。完整分段计划决定剩余调用预算；提取时服务端为当前窗口的原文行及简单表格单元格编号，模型选择编号，由服务端回填精确原文和位置；同一行多个条目可用该行内唯一的短原文细分锚点，编号不能扩大资料范围。引用目录超限明确失败，不截断后冒充完整输入。服务端继续校验字段结构、横表归属、值与依据的确定性缺口及输出完整标记，租约围栏持久化成功后才结算；引用存在不证明字段语义正确。修复反馈包含具体校验位置；失败回执只记录白名单原因与数字索引路径，不记录原文或模型草稿。提取材料中的指令作为不可信数据处理，来源身份由服务端绑定。数据生命周期、样例范围和人工核对边界见 [知识工坊](./toolbox.md#资料转表格)。
