## 1. 已实现的隐私流程

1. Launcher 入口为原生 `PrivacyConsentActivity`。
2. 用户作出选择前不创建业务 WebView，不访问轻笺在线页面，也不初始化非必要第三方能力。
3. 隐私政策和用户协议从 `apps/web/public/legal/` 同源构建，可在无网络时从 APK 内完整查看。
4. “暂不同意并退出”不会写入同意状态，并关闭当前 App 任务。
5. “同意并继续”只在 App 私有本地存储中记录政策版本和同意时间，然后进入业务 WebView。
6. 政策版本改变后，旧版本同意状态自动失效并重新提示。
7. Web 设置页提供隐私政策、用户协议入口；Android 原生隐私政策全文页在文末提供“撤回隐私同意”操作。
8. 用户确认撤回后，原生端清除本地同意状态、停止当前业务页并重新进入首次启动提示；不会自动删除账号或云端内容。
9. “设置 → 账号与安全”提供账号自助注销；开始前明确建议导出数据，并说明云文件备份仅含元信息。
10. 注销验证码只发送到服务端读取的当前账号绑定邮箱，Redis 仅保存 5 分钟有效的加盐摘要；前端不能指定收件人。
11. 验证码和精确确认文字通过后，账号在事务内立即去标识化并停止登录，所有会话随即清除。
12. 数据库内容、OBS 对象、笔记图片和书签图标进入可重试物理清理任务；全部完成前不会伪装为成功清理。
13. GitHub 登录在跳转前单独展示境外接收方、目的、信息类型、处理地点和权利渠道；拒绝后仍可使用邮箱登录。
14. GitHub OAuth 授权地址由服务端生成；一次性 `state` 在 Redis 保存 10 分钟，并与浏览器 HttpOnly
    随机 Cookie 绑定。回调按 `pending → processing → completed/failed` 原子认领，完成结果短暂保留用于恢复本站会话；
    授权码同时使用 PKCE 约束，换取令牌时再次提交同一回调地址，且仅向预先探测选定的线路提交一次，
    防止登录串号、授权码替换和授权码重放。

当前隐私同意版本为 `2026-08-11`；用户协议继续使用 `2026-07-28`。隐私版本升级用于披露可选的
Android 通知权限，安装新版本后会重新展示首次同意页，旧版本同意状态不会被静默沿用。

## 2. APK 权限证据

当前 Android 源码 Manifest 与 `2026-08-11` 构建的 Root 试点 Release APK 声明如下。该包保持
`1.0.1` 版本号用于同签名手动覆盖安装，已用 `apkanalyzer manifest permissions`、`apksigner verify`
和 SHA-256 复核，并在同一次发布中同步更新 `ANDROID_RELEASE`：

| 权限                                                       | 来源              | 用途                                            | Android 运行时敏感权限 |
| ---------------------------------------------------------- | ----------------- | ----------------------------------------------- | ---------------------- |
| `android.permission.INTERNET`                              | 应用声明          | 访问轻笺页面、API、文件及用户主动打开的网络服务 | 否                     |
| `android.permission.ACCESS_NETWORK_STATE`                  | 应用声明          | 判断网络状态并提供断网与重试反馈                | 否                     |
| `android.permission.POST_NOTIFICATIONS`                    | 应用声明          | 用户开启 App 系统提醒后展示通知栏与桌面未读角标 | 是；Android 13+ 由用户授权 |
| `android.permission.REQUEST_INSTALL_PACKAGES`              | 应用声明          | 应用内更新：把已下载的轻笺安装包交给系统安装器  | 否；需用户在系统设置授权 |
| `<applicationId>.DYNAMIC_RECEIVER_NOT_EXPORTED_PERMISSION` | AndroidX 自动生成 | 限制应用内动态广播接收器通信                    | 否；签名级应用内权限   |

当前发布包除可选通知权限外，不声明相机、相册/存储、定位、麦克风、通讯录、短信、电话等运行时权限。
文件和图片由 Android 系统选择器提供；拍照入口由系统相机 Intent 完成。通知权限拒绝后不影响站内通知中心和核心功能。

### 2.1 `REQUEST_INSTALL_PACKAGES` 最小化说明

轻笺通过自有官网分发、不经应用商店，更新只能由应用自身引导。该权限用于「我的 → 版本更新」
下载完成后把安装包交给系统安装器，替代让用户自行在文件管理里查找安装包（鸿蒙兼容层实测既不
弹系统下载通知、文件也不落在「下载」目录，用户很难找到）。

边界：

- 仅安装本应用经 `DownloadManager` 下载的文件，且 `WebViewSupport.installDownloadedApk` 会校验
  该下载记录的原始地址位于 `boluo66.top` 域名下；其它来源一律拒绝。
- `DownloadManager` 按 uid 隔离，其它应用的下载记录在本应用内不可见。
- 不具备静默安装能力：是否安装由系统安装确认页决定；未授权「安装未知应用」时不做任何安装动作，
  只跳转系统授权页由用户自行决定。
- 下载与安装均由用户在界面上主动触发，不存在后台自动下载或自动安装。

最终备案候选 Release 必须重新执行同一检查。若权限集合变化，须定位到直接或传递依赖，先更新
功能说明和隐私政策；无法解释或不需要的权限不得保留。

## 3. 原生依赖与 SDK 判断

当前 Release 运行时的直接原生依赖：

| 依赖                            | 作用                                                | 是否面向业务数据的第三方移动 SDK |

备案系统中的“是否应用 SDK 服务”应以最终 Release 依赖和 APK 扫描结果为准。服务端调用或网页
跳转到第三方服务，不应误报成嵌入式 Android SDK；反之，未来新增的移动 SDK 也不能漏报。

## 5. 已核实的保存与删除规则

| 信息或记录              | 当前规则                                                         |
| ----------------------- | ---------------------------------------------------------------- |
| 账号与云端业务内容      | 保存至用户主动删除、注销账号或服务依法终止                       |
| 普通 / “记住我”登录会话 | 最长 1 天 / 7 天；退出、改密或注销时提前失效                     |
| 安全事件                | 默认 90 天；注销时解除账号 ID 关联，依法继续按剩余期限保存       |
| 接口、操作和转化日志    | 最长 180 天；服务端每日自动分批物理清理                          |
| 系统邮件投递记录        | 默认 180 天；注销事务删除与账号或原邮箱直接关联的记录            |
| AI 产品事件             | 默认 180 天，不保存问题或回答正文                                |
| AI 响应恢复快照         | 10 分钟                                                          |
| AI 临时文档             | 通常最长 24 小时                                                 |
| AI 临时会话             | 用户选择 1 / 7 / 30 天；标准或长期会话由用户主动删除或注销时清理 |
| 账号注销清理任务        | 失败前保留以便重试；成功即清空对象路径，完成记录 180 天后删除    |

基础设施灾备副本按既有覆盖周期到期移除；业务数据删除后，残留副本与正常业务隔离，不用于恢复已注销账号。
账号注销链路会直接删除与该账号关联的接口、操作、邮件、AI 和业务记录，不以常规到期任务代替注销删除。

## 6. 定稿结论与后续复核

已完成以下 P4 定稿项：

- 华为云备案控制台核对现有 ICP 个人主体，法定名称已同步到两份正式页面；
- 用户确认长期公开使用 `1902013368@qq.com` 受理用户权利、注销与投诉；
- 接口、操作和转化日志统一采用最长 180 天规则，并接入自动分批清理；
- DeepSeek 采用不依赖退出设置的保守披露；第三方未公开固定期限时采用“功能所需最短期间 + 公开规则”口径；
- GitHub 登录已实现境外接收方分场景告知、单独确认、拒绝后邮箱登录替代路径和同意证据；
- 用户申请删除时，文案明确轻笺侧删除以及适用情况下向第三方传达或协助行权；
- 未成年人、争议解决、政策更新与重新同意规则均已形成不排除用户法定权利的保守表述；
- 两份页面、Android 同意常量均切换为正式版本 `2026-07-28`，并移除审阅稿、TODO 和 `noindex` 标记。

P4 技术材料已定稿。此前生成的 P5 本地预候选包仅供材料核对和留证；其后源码又完成了单一静态
品牌封面、Web 首屏就绪通知、首次同意页正式文案收口，以及华为鸿蒙真机的 WebView 兼容、
文件选择过渡和导航反馈优化，因此旧包已失效，不能直接递交备案。
当前源码提交后，须从该提交执行干净 Release 构建并重新提取全部特征。进入实际备案提交和公开
发布前仍必须：

1. 逐项对照候选 APK 行为、Manifest、Release 依赖、服务端实际配置和网络流量。
2. 在 P6 填报前结合备案审核意见复核 GitHub 跨境处理的适用路径；如审核要求补充材料或关闭入口，按同一候选版本处理。
3. 在用户授权的环境执行账号注销迁移与完整验收；当前不得把尚未执行的迁移描述成线上已生效。
4. 若服务内容、第三方服务、权限、包名、签名或政策文字发生实质变化，重新生成候选包和证据。
