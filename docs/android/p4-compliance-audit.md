本文记录 Android APK 当前真实行为与 P4 技术实现，供隐私文案定稿、App 备案和最终 Release
审计使用。本文不是法律意见；备案系统字段和最终文案仍应按备案主体、服务实际行为及审核要求复核。

## 1. 已实现的隐私流程

1. Launcher 入口为原生 `PrivacyConsentActivity`。
2. 用户作出选择前不创建业务 WebView，不访问轻笺在线页面，也不初始化非必要第三方能力。
3. 隐私政策和用户协议从 `apps/web/public/legal/` 同源构建，可在无网络时从 APK 内完整查看。
4. “暂不同意并退出”不会写入同意状态，并关闭当前 App 任务。
5. “同意并继续”只在 App 私有本地存储中记录政策版本和同意时间，然后进入业务 WebView。
6. 政策版本改变后，旧版本同意状态自动失效并重新提示。
7. Web 设置页提供隐私政策、用户协议入口；Android App 环境还提供“撤回同意”操作。
8. 撤回后原生端清除本地同意状态、停止当前业务页并重新进入首次启动提示；不会自动删除账号或云端内容。

当前同意版本为 `draft-2026-07-28`。此版本故意带 `draft`，正式文案定稿时必须更换版本，以确保
测试阶段的同意不能被误当作正式同意。

## 2. APK 权限证据

当前 Debug APK 经 `apkanalyzer manifest permissions` 检查，仅包含：

| 权限                                                       | 来源              | 用途                                            | Android 运行时敏感权限 |
| ---------------------------------------------------------- | ----------------- | ----------------------------------------------- | ---------------------- |
| `android.permission.INTERNET`                              | 应用声明          | 访问轻笺页面、API、文件及用户主动打开的网络服务 | 否                     |
| `android.permission.ACCESS_NETWORK_STATE`                  | 应用声明          | 判断网络状态并提供断网与重试反馈                | 否                     |
| `<applicationId>.DYNAMIC_RECEIVER_NOT_EXPORTED_PERMISSION` | AndroidX 自动生成 | 限制应用内动态广播接收器通信                    | 否；签名级应用内权限   |

当前 APK 不声明相机、相册/存储、定位、麦克风、通讯录、短信、电话等运行时权限。文件和图片由
Android 系统选择器提供；拍照入口由系统相机 Intent 完成。

最终备案候选 Release 必须重新执行同一检查。若权限集合变化，须定位到直接或传递依赖，先更新
功能说明和隐私政策；无法解释或不需要的权限不得保留。

## 3. 原生依赖与 SDK 判断

当前 Release 运行时的直接原生依赖：

| 依赖                            | 作用                                                | 是否面向业务数据的第三方移动 SDK |
| ------------------------------- | --------------------------------------------------- | -------------------------------- |
| `androidx.core:core:1.15.0`     | Android 版本兼容、文件共享、广播与系统栏适配        | 否，AndroidX 基础库              |
| `androidx.webkit:webkit:1.12.1` | WebView 兼容、安全浏览、受信 Web 消息与本地资源加载 | 否，AndroidX 基础库              |

其传递依赖包括 AndroidX Annotation、Collection、Lifecycle、Profile Installer、Startup、
Tracing、VersionedParcelable，以及 Kotlin 标准库和协程运行时。当前 APK 未嵌入广告、统计、
推送、支付、地图、社交分享或第三方登录移动 SDK。

备案系统中的“是否应用 SDK 服务”应以最终 Release 依赖和 APK 扫描结果为准。服务端调用或网页
跳转到第三方服务，不应误报成嵌入式 Android SDK；反之，未来新增的移动 SDK 也不能漏报。

## 4. 业务涉及的第三方服务

以下是网站或服务端按功能需要使用的外部服务，不等同于 APK 内嵌 SDK：

| 服务                   | 触发场景                   | 可能涉及的信息                                   | 定稿前工作                                       |
| ---------------------- | -------------------------- | ------------------------------------------------ | ------------------------------------------------ |
| 华为云对象存储         | 用户上传、预览或下载云文件 | 文件、图片、文件名、类型、大小及存储元数据       | 核对服务提供者法定名称、地域、保存和删除规则     |
| DeepSeek               | 用户主动使用 AI 功能       | 问题、用户选择的上下文、必要检索结果             | 核对实际接口、模型方规则、是否用于训练及保存期限 |
| 阿里云百炼 / 通义千问  | AI 备用通道                | 同上                                             | 核对启用条件、服务主体、规则链接和保存期限       |
| GitHub OAuth           | 用户主动选择 GitHub 登录   | 授权返回的账号标识、登录名、授权范围内邮箱和头像 | 核对授权范围、境外处理说明和公开规则链接         |
| 高德 IP 定位接口       | 账号区域展示或安全风控     | 访问 IP、返回的省市级粗略区域                    | 核对调用时机、必要性、服务主体与保存方式         |
| 邮件发送服务           | 验证码和账号/安全通知      | 收件邮箱及邮件内容                               | 确认实际供应商、日志和保存期限                   |
| Iconify 等在线图标服务 | 用户主动搜索或选择在线图标 | 搜索词、网络请求信息、所选图标                   | 核对实际域名、供应商和是否仍在线调用             |

最终文案需以 Release 候选版本的实际网络流量、服务器配置和功能开关为准，不可只按代码中的
备用配置填写。

## 5. 正式定稿阻塞项

以下信息目前无法仅从代码安全确定，未完成前不得把审阅稿改成正式政策或公开发布候选 APK：

- 与网站备案、App 备案完全一致的运营者法定名称；
- 备案和用户权利处理所需的有效联系地址；
- 每项日志、账号、内容、备份、临时文件和第三方处理的明确保存期限或可执行判断规则；
- 第三方服务提供者的法定全称、隐私规则链接、处理目的、信息类型、处理地域和删除机制；
- 账号注销的产品内自助或人工流程、身份核验方式、预计处理时限和结果通知方式；
- GitHub OAuth 及 AI 服务可能涉及的跨境处理范围与适用告知；
- 未成年人规则、争议解决条款和格式条款的最终法律审阅；
- 正式生效日期、版本号，以及政策更新后重新征得同意的判断规则。

定稿时还必须：

1. 删除两份 HTML 中的“备案前审阅稿”、TODO 和 `noindex` 标记。
2. 同步更新两份页面的版本、生效日期及 `LegalDocuments.PRIVACY_POLICY_VERSION`。
3. 逐项对照 App 行为、Manifest、Release 依赖、服务端配置和抓包结果。
4. 由用户审核最终文案和主体信息，再生成新的备案候选 Release APK。
