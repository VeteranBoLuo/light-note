# 轻笺架构

本文描述当前系统边界、分层、核心数据域和关键运行链路。路由、表、环境变量和 Skill 的完整清单以源码、Schema 与契约测试为准；本文不复制易漂移的实现枚举。

## 系统概览

轻笺是书签、笔记、文件、标签、待办与个人知识处理平台，使用 pnpm monorepo：

```text
light-note/
├── apps/
│   ├── web/          Vue 3 + Vite Web、PWA 与 Manifest V3 扩展
│   ├── server/       Express 5 + MySQL + Redis + OBS
│   ├── android/      Android WebView 原生壳
│   └── host-agent/   本机服务器只读采集与白名单运维代理
├── packages/         共享协议与领域包
└── scripts/          本地开发、检查与部署脚本
```

主要运行链路：

```text
Browser / PWA / Android WebView / Extension
                    │ HTTPS / same-origin realtime
                    ▼
               Express API
        ┌───────────┼───────────┐
        ▼           ▼           ▼
      MySQL       Redis         OBS
        ▲                       ▲
        └──── domain Workers ───┘

Browser → Express /api/infra/* → Unix Socket → Host Agent
```

MySQL 5.7 是兼容基线。Redis 保存会话、短期票据、实时失效与租约；OBS 保存用户文件和私有派生资源。浏览器不能直连数据库、Redis、Host Agent 或任意服务器命令。

## 后端分层

```text
router/ → router_handle/ → util/services/ → db / Redis / OBS
                              │
                              └→ Worker queues / domain side effects
```

- `router/`：认证、中间件、参数与 HTTP 路径。
- `router_handle/`：请求编排和响应，不承载可复用业务 SQL。
- `util/services/`：跨页面、AI Skill、Worker 和脚本共享的权限、事务、幂等与副作用。
- `db/index.js`：HTTP、Worker 和脚本的统一数据库连接与环境安全边界。
- `packages/shared`：前后端共用的版本化协议与领域常量。

API 使用 `resultData(data, status, msg)` 信封，snake_case 响应键统一转 camelCase。客户端只依赖稳定业务错误码，不依赖 raw 异常文本。

### 身份与权限

- GitHub 登录按服务端验证的稳定 `github_id` 找回账号；已验证邮箱与现有轻笺账号相同时，先提示邮箱已注册，用户明确确认后才添加 GitHub 关联并登录，不额外要求原密码或邮箱验证码，保留原账号密码、会话、资料与权益。待确认身份仅保存于本次 OAuth 的服务端短时票据，限定浏览器 nonce；取消、过期、凭据或邮箱变化、已有其他关联时拒绝，重复确认幂等恢复结果。旧格式绑定票据不可恢复；完成回调也须核对当前关联与凭据快照，签发会话与最后一次账号复核共用用户行锁事务，避免并发改密或解除关联绕过。绑定处理租约允许中断后重新认领，但不延长票据期限；已提交或结果不确定的重试只恢复仍存在的同一关联，账号变化等终止错误作废票据；Redis 写入回包丢失只复核本次结果，旧处理者不能覆盖新认领。未提供已验证邮箱时，以 GitHub ID 生成内部占位邮箱，不能借占位地址合并账号。邮箱接口网络故障与“确无已验证邮箱”分开处理，已绑定身份可按 GitHub ID 继续登录，新身份不得因接口故障误建占位账号。通用个人资料保存不能修改登录邮箱；旧客户端回传同值仅视为未改动。
- GitHub 一次性授权码换票前，按相同 POST 方法进行无用户凭据的线路探测，换票使用独立 TLS 连接并限制整次请求时间；仅在确定未发出换票 POST 时允许恢复本站回调，换票结果未知时必须重新授权，不向其他 IP 重放原 code。`state`、PKCE 与浏览器 nonce 校验不因网络降级而取消。
- 独立登录密码状态由 `user.login_password_set` 维护：新邮箱注册及成功设置/重置写入已设置，GitHub 新账号写入未设置；历史 GitHub 账号的未知状态不按哈希非空猜测，也不覆盖原密码。设置页读取服务端 `hasPassword`（布尔值或未知），首次设置及找回通过邮箱验证，常规修改验证原密码；各密码变更成功入口统一撤销旧会话。
- 会话有效性以 MySQL 为准，Redis 命中仍须等待数据库确认归属、有效期与未撤销状态，续期不得复活已过期或删除的会话；缓存清理失败不能恢复登录权限。更换邮箱在提交事务中再次锁定核验发起会话，不能只信任请求入口的鉴权结果。
- 注册不强制邮箱验证。邮箱健康检查按 UTC 自然月分批扫描有效账号，以格式、域名 DNS 和实际 SMTP 收件人阶段明确的 `5.1.1` 失败为依据；不按邮箱名称猜测，不进行批量试发或邮箱探测，临时 DNS/投递故障不判无效，无 MX 时保留 A/AAAA 收信回退。巡检兼容标准单标签域名与 IP 字面量邮箱，后者不做 DNS 或主动连接探测；不把新邮箱入口的格式支持范围当成无效证据。GitHub 内部占位地址跳过。账号、邮箱摘要与问题码构成独立持久去重事实，通知与事实在同一事务提交，删除通知也不重发；检查只生成可跳转账号设置的站内通知，不进入邮件、浏览器或 App 系统通知通道。检查不能证明邮箱归属，也不限制正常注册、登录与使用。
- 更换登录邮箱只通过账号与安全的专门入口：验证原密码，或使用当前会话十分钟内服务端记录的 GitHub 登录证明，再向新邮箱发送独立用途、五分钟有效且最多五次尝试的验证码，不依赖旧邮箱。票据绑定用户、会话、目标邮箱和账号凭据快照，确认时锁定重验，邮箱唯一键裁决注册及更换竞争；已占用邮箱拒绝且不合并账号。更换保留用户 ID、密码、GitHub 关联和数据，撤销原会话；管理员代看不能读取或执行该流程。
- 可用账号角色为 `visitor`、`user`、`test`、`root`；`deleted` 只表示正式注销后的墓碑状态，不参与正常权限分配。管理员停用保留原角色并写入 `del_flag=1`，因此物理资源清理必须同时复核生命周期，完整约束见 [停用状态不能冒充正式注销](./pitfalls.md#ln-pit-199停用状态不能冒充正式注销)。
- `test` 只在运营统计中按内部账号过滤，不失去普通产品能力。
- 普通请求以 `req.user` 为身份。管理员代看分离真实操作者 `billingUser` 与资源主体 `resourceUser`。
- 管理员上下文使用短时 `X-Admin-Context`，所有路由在 `adminRoutePolicy.js` 显式声明；遗漏失败关闭。
- `readonly` 只读；`maintain` 只允许可逆内容维护并抑制目标账号成长、转化和权益副作用。
- Root 高风险操作使用 `ensureRootRole()` 并保留意图与终态审计。
- 账号 IP 定位只在身份确认后异步补充展示元信息，不参与登录恢复成功与否；外部定位或回写失败保留原资料。代看、游客维护及 Root 指定其他账号的读取不更新目标账号 IP，迟到结果不能覆盖已变更的 IP 或停用、注销后的账号。

### 安全事件自动处置

应用层自动处置独立于累计风险分封禁，只接受可信游客身份、公网 IPv4、GET/HEAD 且已被签名规则 403 拦截的明确敏感文件探测证据。业务资源路径、正文内容、登录失败、普通高频、观察模式、规则例外及安全白名单不进入自动处置；其他事件保留人工复核。入口与精确匹配范围由 `autoResponsePolicy.js` 维护，`SECURITY_AUTO_RESPONSE_ENABLED=false` 可停止新增自动处置。

符合条件的事件自动确认并保留证据；同来源 5 分钟内两次命中才限制游客来源 1 小时，生效期间不续期，不改变账号状态。已认证正式用户及精确的认证恢复入口不受该自动来源限制影响，请求自身的攻击检测仍执行。人工来源限制保持原有作用范围；人工解除后 1 小时内不自动重封。将任一触发证据改判为误报、授权测试或良性异常时，同事务解除由它触发且仍属于此策略的限制。

复核、来源限制、策略审计和操作审计同事务提交，任一步失败则回滚并保留待复核；同来源并发串行化，普通风险计分不得覆盖正在生效的来源限制。

## 前端与客户端

### Web

- 路由入口位于 `apps/web/src/router/`，页面位于 `view/`，共享 UI 位于 `components/`。
- Pinia Store 与 composable 承担跨页面状态、请求和业务动作；桌面/移动视图不复制领域逻辑。
- 断点由 `config/responsive.ts` 和 bookmark Store 统一提供。
- 主题变量位于 `assets/css/theme.less`；资源语义色位于 `config/resourceColor.ts`；静态 UI 图标位于 `config/icon.ts`。

### 应用入口

- 根路径 `/` 保留响应式官网。首屏和底部固定显示“开始使用轻笺”与“注册 / 登录”；等待身份确认期间只显示固定占位的加载状态。确认游客后主入口进入 `/workbenches`，账号入口打开账号弹窗；已登录两者均进入 `/app`。身份检查失败留在官网并反馈，不凭近期登录记录判断身份。
- `/app` 是应用入口：移动浏览器回访、移动 PWA 与 Android App 固定进入“今日” `/workbenches`；桌面按账号首页偏好进入，无偏好回退书签。
- 手机浏览器第一次访问根路径展示官网；回访分流只使用本地记录，不改变搜索引擎得到的 HTML。
- 移动端底部一级导航为“今日｜资料｜新建｜待办｜社区”，个人中心由顶栏头像进入；“今日”负责快速收集到待整理，“新建”面板中笔记类型选择与文件上传在原页面完成，书签和待办进入各自的完整创建页，并提供知识工坊入口。全局文件上传在云空间内继承当前有效文件夹筛选，其它页面默认保存到“全部文件”；资料模块顶栏“+”仍负责当前目录或当前文件夹内的新建。书签、笔记库、云空间、标签与待办的“更多”统一提供资源中心、资源整理与知识工坊入口，分别进入全部资源、整理总览与工坊首页，不继承当前模块的类型筛选。移动端资源中心与整理中心是两个独立二级页面，不展示桌面的同级分区导航；个人中心常用入口提供整理中心，回收站归入底部管理工具。
- 被动身份变化不会自动弹登录框；登录/注册弹框只响应用户明确意图或受保护操作的再次确认。

### Android

- `apps/android` 只负责 WebView 容器、安全导航、文件选择、下载、系统返回、开屏与版本标识；业务 UI 继续由 Web 端维护。
- Release 固定加载 HTTPS `/app`，关闭 WebView 调试、拒绝 SSL 错误并禁用不需要的文件访问。
- Debug 可在构建时覆盖局域网 Vite 地址；Web 代码通过 HMR 更新，不因普通前端改动重装 APK。
- 移动浏览器、PWA 与 App 共用 `html.light-note-mobile-rendering` 渲染基线；Android 引擎类不承载业务视觉。
- 系统分享由 `MainActivity` 接收 `SEND` / `SEND_MULTIPLE`，不申请新权限。`IncomingShareStore` 只读取外部应用授予的 `content://`，拒绝 `file://` 与本应用 Provider，把文字和文件复制到私有缓存（单次最多 100 个文件、共 500MB、正文 6 万字），只保留最近一次，24 小时过期。首次同意隐私前只把分享请求转交给同意页，不读取内容。接收时由原生顶部提示显示真实的已处理文件数，Activity 重建后恢复订阅，新分享替换旧进度；完成后通知网页打开快速添加。
- 网页在身份确认后通过受信桥 `share.peek` 取清单，从同域 `/__native-share/{id}/{序号}` 按上传队列读取由原生拦截返回的文件，清单阶段只预填元信息到「快速添加」，待整理来源记为 `system_share`；上传全部或部分成功时，若当前在云空间，静默刷新已加载文件、目录和容量，保留筛选与排序；游客先登录，管理员代管上下文不自动打开。保存成功或关闭弹窗后 `share.complete` 清理暂存，切换账号或刷新页面保留暂存并重新处理。

### PWA 与扩展

- PWA Service Worker 处理页面导航、离线页与经浏览器授权的推送通知，不缓存私有 API 数据；`start_url` 为 `/app?source=pwa`。浏览器订阅按账号和设备世代隔离，退出或切号清理绑定与本地通知；iOS / iPadOS 需从主屏幕 Web App 开启。
- Android App 内不注册 PWA 安装能力。
- 浏览器扩展使用 Manifest V3 Side Panel；官网展区、公开产品页与设置入口共享同一商店配置，完整权限、认证、入口和资源流程见 [浏览器扩展](./browser-extension.md)。

## 核心领域

### 资源、标签与待整理

- 书签、笔记、文件是三类资源；待办是行动对象，不进入资源标签关系。
- `tag` 是标签本体，`resource_tag_relations` 是三类资源与标签的唯一关系事实。
- “标签”使用单一浏览与治理模块：`/manage/tagMg` 只作为兼容 URL，由 `TagSpaceEntry` 在路由提交前进入上次使用或最近标签；历史 `TagMg` 页面实现已删除。浏览、创建、编辑和删除都在同一标签目录与 `/tag/:id` 工作区完成，不再挂载第二套标签总览页。历史 `?mode=manage` 只做兼容规范化。
- `/tag/:id` 按标签 ID 读取内容；同名标签不合并。目录摘要、分区预览和跨类型时间线都由服务端分页读模型提供，不能先分表截断再在前端伪造全局顺序。
- 资源中心不提供全局图谱；历史 `/graph` 与 `/search?section=map` 进入资源查找。
- `/search` 是资料与待办的全局查找工作台，批量整理仅作用于书签、笔记和文件；普通结果包含三类资料及待办实例，默认包含已完成待办；标签只作为筛选条件，以及关键词命中时可进入 `/tag/:id` 的独立导航匹配。
- 全局搜索的 `separateTagMatches` 是向后兼容的可选协议。开启时服务端从 `items/groups/typeTotals` 中剥离标签，并在首屏元数据中返回轻量 `tagMatches`（真实标签图标及存活书签、笔记、文件计数）；`ordered` 查找允许显式请求待办，标签仍独立返回；未显式请求待办的旧调用方以及 `global` 资料分页保持原范围。PC 与移动快捷搜索共用包含待办的建议查询和打开规则。
- `ordered` 分组续页使用当前类型的完整排序键与 ID，游标绑定账号、筛选和类型，保留 SQL 的 NULL 与文本排序规则；旧 offset 游标仍可使用，续页响应逐步转为排序键游标。书签、文件的时间排序复用 owner/删除状态/时间/ID 索引。跨类型关键词相关度先在当前筛选的完整候选集合上排名，按相关度、类型次序及类型内稳定排序键分页，再按当前页 ID 回填正文、标签和其他附属信息；不对各类型先截断采样。相关度根据资源字段匹配，不由截断后的展示摘要决定，未完成待办仅在同档位内弱加权。该链路使用独立作用域的游标，旧全局 offset 游标仍可续用；时间索引的收益不能推及名称、正文和计算相关度排序。
- 资源中心空关键词按最近更新浏览，出现关键词后默认按相关度搜索；结果保持按资源类型分组并使用服务端游标滚动加载。右侧检查器和移动端底部检查器对资料提供打开、分析、待整理、标签整理与删除动作；待办只展示状态、截止时间等信息并跳转待办工作区。待办不参与资料批量选择或查询全选，搜索总数与可整理资料数量分别统计。
- 桌面、移动快捷搜索与资源中心共用搜索结果导航：文件“打开”按稳定 ID 进入云空间预览，“定位”独立保留按展示名称筛选文件列表的入口；书签打开继续遵守用户偏好，定位进入书签列表。移动搜索先释放浮层 history，再导航和打开文件预览。
- 资源中心的书签检查器与更多菜单提供“阅读已存正文”，原地复用存档阅读器的只读模式；打开原网页仍沿用用户偏好。阅读不自动存档或生成摘要，关闭不重查搜索列表；移动检查器先释放浮层再打开阅读器，身份或搜索现场变化时关闭旧阅读上下文。
- 资源中心打开笔记保留原搜索 URL；返回时按当前账号与管理上下文重新查询已加载范围，再恢复结果锚点和检查器选中项。当前标签页只短期保存导航元数据，不缓存资源正文；其他入口不继承此搜索现场。 整理中心“无标签资源”打开笔记同样保留关键词、资源类型与已加载结果的虚拟行锚点；返回重新读取当前筛选，已加标签或删除的资料不复用旧快照，失效锚点按列表位置回退。
- `resource_inbox` 保存书签、笔记和文件的待整理关系。入口参数和页面位置不构成待整理事实。
- `/organize` 是资源整理的统一工作区；`/inbox?tab=todo` 只承载待办，历史资源待整理地址在路由提交前规范化到 `/organize?issue=pending`。待整理数量来自 `resource_inbox`，不并入无标签、重复网址和疑似失效的治理总数。
- `/api/organize` 只编排共享领域 Service：无标签判定复用有效标签关系口径，标签写入与软删除复用资源中心能力；所有查询按 `resourceUser` 隔离，写操作继续受游客和管理员代管策略约束。知识结构的产品入口只由知识工坊承载，不计入整理中心摘要与待处理角标。
- 管理员仅可在 `maintain` 模式为游客账号创建、控制和审核通用整理任务，用于维护演示内容；普通用户账号不开放此代管能力，游客本人仍只读。任务保存服务端认证的发起管理员身份，Worker 复核管理员仍为有效 Root、目标仍为有效游客，AI 额度由发起管理员承担；续跑沿用同一计费主体，资源归属保持游客。旧标签批次不开放代管。
- 新整理按资源、适用项目、范围、确认依次选择。前后端共用 `@lightnote/shared/organize-capabilities` 的适用关系：名称／标题建议用于书签、笔记和文件，描述补全仅用于书签，空内容检查仅用于笔记和文件；没有适用项目的资源不进入预检范围，规则数量按实际适用资源统计。书签名称只补空缺或以网址命名的项目，描述只补原字段为空的项目；已有正常内容保持不变，两类建议均独立审核后应用。文件只改善自动编号或默认名称，名称与标签共用全文／视觉材料和分批分析，保留原扩展名、正常名称与已有重命名冲突检查。返回修改后重新预检，旧任务已有的名称建议仍可审核。
- 整理对象可独立选择标签，`tag_icon` 只补全空图标；标签不是第四类可打标签资料，不进入资源关系表。范围在预检时冻结，图标补全进入逐资源队列，复用新增标签的关键词转换与 `tag.icon_keywords` Execution，在事务外有界搜索并持久化候选；额度不足暂停，已外发且结果不确定时不自动重试。应用按标签名称和原图标快照复核，仅更新图标；同一标签的所有引用共享结果，外部改名或改图标返回冲突。
- 同义标签合并仅比较本轮冻结范围，以稳定方向避免互相合并；按有界批次比较名称和说明，只交付高置信同义写法，相关主题或上下位概念不合并。已有图标不影响合并范围，免费图标匹配与付费同义分析独立路由，暂停时新缓存命中仍可释放免费任务。合并不进入批量应用：用户确认目标后，在同一事务复核源标签、目标名称／说明与源关联指纹，迁移并去重三类资料、待办／系列、收集表单的关联，保留回收站资料关系和两侧说明，再删除源标签；外部变化拒绝旧建议。
- 书签失效检查可在整理项目中勾选，冻结范围进入既有持久整理免费队列，复用 `linkHealth` 的观测写入、有效状态与疑似失效入口；只把 404／410 记为疑似失效，未知结果不抹掉旧观测，用户“标记正常”继续有效。检查不自动删除书签。
- 批量智能打标签通过绑定来源身份的一次性内存交接进入整理确认；交接失效不回落全量范围。显式选择任务可追加标签，分析已有标签资料并剔除已关联建议，应用只追加；普通整理和历史任务仍默认补齐无标签资料。标签模式保存于任务选项，并贯穿规则和续跑重查。
- 通用整理任务使用独立的任务、资源快照和建议模型，一项资源允许多条独立审核的建议；旧标签批次继续读取和审核。预检按请求标识幂等，在一致性事务内只读取 ID、类型和名称并批量冻结完整范围；读取候选时不持有用户锁，写入前再锁用户并复核幂等。正文读取、版本哈希与证据快照在启动后分批保存，独立规则先交付，重复检查基于本轮完整快照分组。预检不调用模型、不逐项生成建议，正文相关数量尚未确定时返回未知。重复笔记比较完整原始内容哈希，不复用 AI 摘录；文件规则检查只读取元数据和就绪解析；新版文件材料在直接处理阶段准备，AI 外发前再复核就绪状态。应用在事务内校验归属与资源版本，复用标签、笔记版本、云文件重命名及回收站服务；本任务内成功修改更新后续建议基线，外部修改转为冲突。清理前锁定并复核关系与子树，删除后关闭剩余建议，重复清理至少保留一份。新表使用独立迁移和只读 Schema 断言，不由服务启动自动建表。
- 新整理任务使用 `runVersion=3`：范围确认冻结对象与名称，启动后先分批完成仅含 ID、权限和元信息的轻量检查；全部检查结束后才领取直接处理与 AI 工作。`organize_processing_jobs` 持久保存处理种类、路径、准备结果、状态及租约，任务与工作键唯一约束防止重复派发。正文、版本证据、网页读取及解析在直接处理阶段准备；图标缓存关键词随任务保存，免费路径不能隐式调用模型。需要 AI 的项目准备就绪后独立入队，标题与标签共享内容分析；重复检查等待完整证据，读取失败不得报告无重复。检查、直接处理和 AI 使用独立有界执行通道，文件等待释放租约，不占用进程轮询。旧任务保留原执行协议，不回填分流或重放已交付成果。
- AI 暂停仅阻止领取新 AI 项目，检查和免费处理继续；在途成果保存。额度不足、功能不可用或权限限制保留剩余队列，继续时重新验证账号、权限及额度；外发结果不确定的 AI 不自动重试。新缓存命中在未外发前转入直接处理，实际零模型调用的成果归免费路径。结束关闭未执行工作并保留在途 AI 成果，不允许继续；检查、全部依赖与两条队列都结束后才能标记后台完成和发通知。建议审核独立于后台完成。整批对象结果分布从对象、有效建议及新版处理事实聚合，按优先状态互斥归类，与建议条数保持不同口径；整批统计不随 Tab 或分页变化，分组数量按当前类型和检查筛选计算。结果首屏合并读取当前任务、完整摘要与展开分组的有界首批内容，折叠分组按需读取，续页不重复计算整批摘要；分组复用同一对象结果判定。资源批量操作先补齐当前筛选下的全部可应用建议，不能把全选范围缩为已加载项；标签沿用独立分页和跨页选择。刷新保留已加载范围和展开选择。处理中、未完成和本次未检查独立展示，卡片保留具体剩余检查；应用或忽略只结束对应建议，仍有待审、执行、失败或人工事项时不能归入已处理；人工已解决的检查不再按历史失败归类，原执行记录保留。本轮建议删除资料属于已处理，外部删除属于已失效；旧记录无法确认完成时不推断为无需修改。新版表通过显式迁移安装，预检在结构未就绪时失败关闭；账号删除同步清理队列。
- 文件整理复用文档来源、确定性解析和覆盖记录。缺少正文时入解析队列，整理项保存 `waiting_content` 与下次检查时间后释放 Worker；同进程不能轮询等待解析。免费准备可在租约过期后恢复，付费运行过期按不确定外发失败处理。解析完成必须重读当前对象、正文与覆盖情况；等待项参与暂停、结束和完成判定。
- PDF 按页复用可靠文字，缺字的非空页补本地 OCR，剩余缺页才按共享页数预算进行视觉理解。图片理解与严格转录用途分开；视觉证据独立保存于文档来源，不写入原文分块，缓存绑定 owner、来源、文件对象版本、页码、用途与识图策略。缺页、超限及失败必须保留可靠内容并显式报告部分覆盖。长正文按连续证据批次全部分析，汇总只选择可回指原始定位的候选；标题、原文、视觉证据不可混淆。
- 重新分析未推荐文件由服务端从原任务完整范围筛选未审核的失败或无建议文件，排除已应用、已忽略及已有有效标签的文件，重新核验 owner 和现状后创建冻结预检。前端不能用当前页拼凑重试范围；新任务仍需确认，不自动回填历史结果。
- 快速添加的书签仅自动读取网页标题作为名称，不自动填入网页描述、调用 AI 或启动浏览器渲染；读取在数据库事务前执行并有总时限，失败仍保存，名称依次回退到分享标题、域名。描述和标签由用户主动发起单条智能分析或整理中心批量重新分析来完善。同名时以「名称 (2)」形式避让（`nameConflict: 'suffix'`）；用户手动填写名称的入口不自动覆盖，仍按同名拒绝。
- `bookmark.url_exact_hash` 是相同网址候选索引；所有 URL 创建、导入、恢复和编辑入口必须同步写入。自动治理仍以完整 URL 二进制复核，并在事务内检查快照、笔记引用和待办引用后才允许软删除。
- `organize_issue_suppressions` 保存可撤销的忽略决定；重复网址忽略绑定当前问题上下文，成员、标签或引用变化后自动重新出现。`organize_action_requests` 保存高风险合并动作的请求幂等结果。
- `bookmark_health` 将外部观测、被检测 URL 哈希和用户“标记正常”分列保存。仅明确 HTTP 404/410 进入疑似失效；网络、DNS 等未知结果不覆盖同一 URL 的既有结论，URL 变化才使旧覆盖决定失效。全量检测由 HTTP 入口创建或复用账号级持久任务，资源治理 Worker 按快照分批领取、受控并发并写回进度；任务租约过期后可由新 Worker 续跑，不能依赖 Node 进程内存保存状态。
- 书签识别和网页快照共用分层网页读取器：静态 HTML 先提取 Open Graph、Twitter Card、JSON-LD 与正文，并按页面特征判定脚本空壳、环境验证、登录门槛或非网页；只有用户明确触发的识别/存档在必要时进入短生命周期 Chromium。Chromium 子进程不继承后端密钥或用户 Cookie，root 后端必须降权运行，所有主文档、重定向和子资源都经 DNS 全量校验并固定公网 IP 的本地代理，且受并发、队列、超时、端口、方法、请求量和输出预算约束。输出以 `static_html`、`rendered_dom`、`browser_capture` 标记证据来源；两层都失败时返回稳定原因，不调用模型根据 URL 猜测。浏览器扩展仅在用户点击 AI 补全并授权当前精确 Origin 后提供当前页可见文字，服务端再次校验捕获 URL 与书签 URL 一致。
- 书签正文存档由 `bookmark_archive_jobs` 按书签持久排队，资源治理 Worker 领取，租约过期后续跑；网络类故障最多尝试三次，访问限制、登录、404 和无正文明确失败。结果事务复核 owner、当前 URL 和租约后，原子保存正文及任务终态；失败保留已有正文。整理向导的网页正文存档项目仅适用于书签：检查当前 URL 是否已有正文，缺失项在规则租约内、事务外逐项读取，成功正文作为整理草稿持久化，失败直接交付原因；列表只返回草稿元信息与短摘录，完整预览按归属独立读取。用户应用时复核资源版本与 URL，在同一事务保存草稿正文和建议状态，不再次抓取，并撤销旧存档任务租约以防迟到覆盖；已有正文跳过，不调用 AI。手动失败重试每次最多 20 项，仅处理当前用户已有失败记录，不自动回填历史缺失存档。正文来源保存在 `bookmark_snapshot.source`，历史未知来源保持空值；正文不承诺包含网页全部内容。
- `tag_relations` 保存由有效共享资源派生的标签关系；软删除资源保留的恢复关系不能计入活跃统计。

### 站内公开资源

- `/api/public-resources` 是独立发布域，不依赖社区广场开关或帖子副本。本人在 `/search/publications` 选择书签或纯文字笔记，服务端预览完整材料并生成指纹；提交复核本人原稿、指纹、公开确认和发布版本，不能由请求正文或 owner 指定内容。内部链接目标、附件、私人标签与目录不进入公开快照；含媒体或画板的笔记拒绝提交，不静默删除媒体。书签仅公开已确认标题、网址与说明，拒绝凭据和分享令牌。
- 一个本人原资源对应一个发布对象，修订内容不可变且最多一个有效待审版。AI 只提供建议，所有提交包括 Root 本人均须 Root 终审。待审或更新未通过时继续展示旧公开版，批准时原子切换；作者撤回及单条、批量、整理中心或笔记子树删除在同一事务停止公开并取消待审任务。恢复原稿不恢复公开；下架阻止作者自行重提，解除下架只恢复提交资格。
- 公开管理通过本人专属 `/workspace` 读模型关联活跃原稿与发布状态。列表首批最多返回1000项轻量元信息，完整状态数量由 SQL 聚合，不在列表阶段读取或校验整库正文；数量表示候选资源，媒体、长度及网址资格在预览和提交时权威校验。超过首批范围时有界自动续页，前端复用虚拟列表控制节点数量。原稿删除或类型不在支持格式时从候选列表隐藏，既有发布及修订记录由发布域保留；恢复原稿不自动恢复公开。详情只提供“预览”和“提交记录”：预览优先显示当前原稿，不可用时显示最近提交材料，并明确标注来源；“有未公开修改”按材料指纹核对，标签与目录不参与。
- 公开管理常显勾选框；点击资源行只预览，勾选同时更新当前预览。未公开、审核和已公开资源共用一份选择会话，最多100项，跨筛选保留；全选只覆盖明确标注范围，超过100项时写明选择前100项，不隐含整库公开。PC Shift 与手机首尾连选复用共享手势，超限整次拒绝，保留原选择。提交前在原工作台准备明确所选材料与指纹，再通过一次简短公开确认冻结范围与公开后果；已预览材料变化时须重看，确认后不得重新取新稿冒充原确认材料。在原列表和正文旁显示提交状态，结束后原位汇总结果，成功项退出选择，失败原因留在原行。取消公开仍须后果确认。
- 批量材料准备只读取本人明确选中的完整材料，返回指纹与发布版本，不传输整批正文；写入逐项重读原稿并复核指纹、公开确认、归属及版本。提交、撤回和 Root 批量终审复用有界批量请求、独立事务与逐项请求收据，不增加后台批次生命周期；账号写入频率按一次明确批次计数，单项接口仍受同一限流约束，不在前台每20项停等。Root 可直接批准当前项或所选待审项，拒绝及下架仍须作者可见原因。每项独立处理版本冲突与失效，成功项不重复执行；撤回先按本人发布 ID 复核状态和版本，范围变化须重新确认。整批传输失败不代表所有事务失败，结果不明先查逐项回执，只有明确重试才能以原请求 ID 再发；禁止用新提交覆盖未确认收据。清空选择不清理未确认结果，切号或离开页面结束本地会话，迟到响应不回填新身份。
- 登录用户主动开启全站范围后，本人资源与其他用户的获批公开资源混排，保留原有类型分组、排序与快捷建议容量。范围在当前账号会话内共用，仅手动切换时按账号持久保存到当前浏览器或 App 本地，首次默认关闭，不增加设置项或跨设备同步。切号、重新登录恢复对应账号偏好，游客及代管不读取或写入本人偏好；功能临时不可用不覆盖记忆值。搜索 URL 保留关键词、范围及筛选，明确范围优先恢复本次搜索但不改写长期偏好；切号时旧账号 URL 范围须替换为新身份自己的范围。关键词、类型和时间作用于两个来源，私人标签、无标签和待办条件仅作用于本人资源。公开条目使用独立 DTO 与来源键，只能进入只读详情、保存副本和举报，不能进入个人编辑、AI 或批量整理。公开详情保留经站内路由校验的实际来源，历史匹配时回退，刷新或深链时替换为来源页，无有效来源时回到资源中心；快捷搜索不虚构资源中心来源，公开详情间跳转不递归携带返回参数。
- 混排复用个人查询与相关度规则，在 MySQL 5.7 兼容的完整可见集合上统一排序、游标分页后回填；本人自己的发布不重复出现。原个人接口保留兼容，关闭全站时不请求新搜索；公开查询失败回退个人结果并标明公开数量未知，混排游标不能传入个人协议。独立读查询有界并行，完整可见集合的精确计数批量返回；列表只回填公开摘要，读取详情仍独立复核权限。
- 搜索、续页、详情和保存复用有效账号、获批修订、存活原稿、撤回／下架及双向屏蔽判断，停用立即隐藏，正式注销清理正文、任务、收据及私人关系。响应使用 `private, no-store`；重新打开与恢复前台重新校验，不持久缓存公开正文。权限变化阻止后续读取，不承诺抹去已阅读或复制的内容。
- 所有写入通过请求收据幂等，既有发布另校验版本。保存副本与收据、公开有效性复核及原有创建 Service 共用事务；文字笔记按公开修订幂等，书签已有同网址或回收站副本时返回入口，不覆盖私人内容。新副本由服务端按获批修订和公开身份保存作者与公开条目来源链接；笔记正文保留署名及链接，书签来源通过 `public_resource_saved_sources` 独立展示，不挤占 255 字说明或替换目标网址。来源按接收者和现存私人副本鉴权，不依赖原发布仍公开；作者更新、撤回或注销不改写副本与来源，接收者注销清理自己的来源关系。举报绑定当时公开修订，治理及通知事件与审核决定同事务落库，处理记录保留操作者和版本；本域接口一律拒绝管理员代管。
- 审核分区位于社区管理的“公开资源”，独立加载，旧广场关闭或失败不会阻断。审核结果和待审核提醒仅进入站内铃铛，失效待审通知不再展示，不进入浏览器、华为或原生通知同步。同一次 Root 批量终审按操作者、批次和作者合并结果通知，摘要显示各审核结果数量；独立审核与历史通知保留原粒度。审核事务与通知投递分离，队列每轮有界连续消费，事件重放不重复通知或重置已读，用户删除不被后续结果恢复。发布开关、迁移与回退见[发布规范](./release-acceptance.md#schema-与-worker-门禁)，AI 边界见 [AI Skills](./ai-skills.md)。

### 笔记

- `note` 同时承载正文与页面树节点；`parent_id = NULL` 表示根层，最大深度为 8，不新增文件夹实体。
- 无筛选的非根单层目录展开只读取目标父链和直属子项；搜索结果按当前页批量补齐祖先与相关子树统计，重叠子树只累计一次。根层读取为保留任意长度历史环和孤儿恢复，仍检查完整父子拓扑，但普通后代不回填展示字段或参与排序；异常根单独补齐，超深结构、大量异常或恢复过程中结构变化时回退完整快照。写入、递归搜索和分享范围继续使用各自的完整结构校验，不能用局部读模型代替。
- 同级排序限定在 `(owner, parent_id, is_top)` 兄弟组。树负责同级前后排序，卡片/列表负责移入或移出父页面。
- 新建笔记按账号偏好插入当前目录普通组顶部或底部，缺失值默认底部；切换偏好不重排已有页面，创建时也保留已有页面的相对顺序、置顶状态及更新时间。批量导入通过同批次幂等 ID 定位前后项，续跑与失败重试仍保留批次顺序；根层「全部笔记」继续按置顶、最近更新展示，不使用该插入偏好排序。
- 移动、批量移动、右键移动和关联已有页面都由服务端返回原/新父级，前端据此失效两侧目录缓存。
- 删除复用笔记树事务与删除批次；资源中心仅删除没有子页面的笔记，发现子页面时拒绝整笔混合操作，转到笔记库确认完整子树后删除，不能只标记父页面而留下孤儿。
- HTML、Markdown、手绘是正式正文类型。所有写入口复用 owner、revision、净化、历史还原点与资源引用事务。
- 图文组合是独立内容块，不挂在外层有序或无序列表项中；载入和编辑时拆开旧的列表嵌套，保留前后内容及原有编号，图注内部仍支持列表。编辑态点击右边框外侧可定位到块后，回退删除整块、回车继续正文；临时光标不进入保存内容，操作支持撤销。
- 数学公式支持行内和块级 LaTeX：富文本使用 `data-ln-math` / `data-ln-latex` 源码节点，Markdown 使用 `$…$` / `$$…$$`；含分隔符等特殊源码采用受控 HTML 保真。共享契约为 `@lightnote/shared/note-math`，KaTeX 仅在展示时按需渲染，生成 DOM 不入库。保存净化、格式转换与分享读取复用源码契约；HTML 导出内嵌公式样式及字体，PDF 等待渲染与字体就绪。公式不开放可信 HTML、外链命令或无限宏展开。
- 手动版本、格式转换、AI 修改和历史恢复使用明确 reason；普通保存与“保存版本”不是同一动作。
- 公开分享使用独立只读页面。令牌摘要落库，原令牌放 URL fragment 并换短时阅读票据；目录分享按当前页面树实时计算范围。
- 新建或移动页面进入有效分享目录时，服务端事务内检测新增暴露并要求显式确认；公开读取复用正式正文净化和范围校验。

- 笔记文件导入使用独立持久任务和 `noteImportWorker.js`：私有暂存上传文件，隔离进程解析 Markdown/HTML/DOCX/ZIP，用户确认后逐篇复用笔记创建事务、图片引用与幂等键。ZIP 内路径用于图片定位，第一版不恢复目录或双链。任务范围、分享确认与执行权限由服务端复核，成功笔记不因部分失败回滚。Worker 领取与暂存清理仅匹配本机可见的任务目录，防止本地开发与生产共用数据库时跨存储抢占任务。导入抽屉内的“导入任务”自动更新进度；列表和详情在同一壳内切换，返回恢复原导入草稿和滚动位置，关闭退出整个抽屉；未执行任务可放弃，终态记录可移除。移除操作保留任务幂等证据并标记待清理，只回收私有暂存文件，不删除已导入笔记；活动任务或有效租约期间禁止移除。 批量清空仅作用于当前账号已结束或已过期且无有效租约的任务，不隐含放弃仍有效的待确认或暂停任务；移除后立即到期，交给持有暂存目录的 Worker 清理。确认前暂存截止为任务创建后 24 小时，确认／重试与执行结束时重置为 7 天；执行中不因到期删除。
- 目录导出的完整范围由服务端笔记树解析，与客户端展开、分页和筛选无关；预检令牌绑定成员、父子关系和正文版本。子树 ZIP 保留页面正文与目录层级，图片沿用链接，不承诺完整离线备份。 批量与子树导出可选择保留原文合并为 HTML、Markdown 或 PDF；导出排序不修改笔记树。合并文件可自定义名称，并独立选择是否显示同名总标题及保留每篇标题；隐藏篇标题只移除正文开头与笔记名称相同的一级标题，其他正文标题和原笔记不变。合并不包含绘画，范围缺失、类型变化或转换失败时不交付缺篇文件。

### 账号数据导出

- 设置页在独立「数据导出」分类中通过一个入口勾选笔记、书签和文件，服务端生成一个私有 ZIP；各模块原有导入与局部导出保持独立。设置页仅展示新版导出，不再提供旧账号 JSON 下载和恢复入口；注销前的导出操作也进入此分类。
- `data_export_tasks` / `data_export_items` 固定本人未删除资源的范围、版本和导出路径。后台读取时复核归属和版本，快照进入私有暂存后不受后续编辑影响；资源缺失、转换失败或图片下载失败必须进入结果说明，不冒充完整成功。
- `dataExportWorker.js` 按运行环境、主机和私有暂存目录领取任务，租约与发布受令牌约束。每账号每环境主机只允许一个活动任务；关闭页面不取消。完成产物保留 24 小时，活动任务最长 24 小时，任务记录保留 7 天；注销立即取消任务，所属主机负责回收产物。
- 笔记按页面树导出，支持统一 HTML、统一 Markdown 或保留原始格式（富文本为 HTML、Markdown 笔记为 Markdown）；绘画保留 JSON。文件扩展名和同批笔记链接使用同一格式映射；可选图片实际下载并改写相对路径。图片读取复用归属校验和固定公网地址的外链访问约束，失败保留原链接。附件原件由文件选项导出。书签 Excel 使用与当前网址匹配的已保存正文，超长内容分段存入同一工作簿；文件按业务目录流式复制原件。

### 文件与派生预览

云文件格式由 `@lightnote/shared/file-category` 的格式注册表统一登记，前后端分类函数与数据库分页前的分类筛选从同一配置派生。已知扩展名优先决定分类，无法识别时依次使用 MIME 和历史分类兜底；分类用于图标、标签与筛选。普通文件预览独立读取格式的预览策略：有扩展名时只按扩展名识别，无扩展名才使用 MIME。图片分类只表示候选，缩略图与大图预览共用服务端有界文件头识别，以实际内容决定支持范围，不信任后缀或声明的 MIME；HEIC/HEIF 名称下的 JPEG 等直接预览，真正的 HEIC/HEIF 经受限解码生成浏览器兼容副本，其他不支持的格式明确提示。大图校验复用本人、分享或聊天附件的来源权限；HTTP 格式识别最多读取 64 KiB 文件头。可直接显示的图片按识别的 MIME 签名原件，需要转码的图片返回派生预览及独立的原件下载地址，不改展示名与原件。列表热路径不读取原件；历史图片首次可见时惰性登记缩略图任务，由 Worker 校验并解码实际内容。文档直接预览与 Worker 派生预览共用格式来源，但只有派生格式可进入文档 Worker。

云文件置顶是账号内文件元数据，不改变原件、分享或派生预览。目录、类型与搜索先限定范围，服务端再按置顶优先、用户所选排序和稳定 ID 排序后分页；置顶组内沿用所选排序。移动目录及回收站恢复保留置顶状态。

云空间的文件显示范围默认仅当前文件夹，可选择同时展示所有层级子文件夹中的文件。登录用户的选择保存在账号偏好中，进入云空间时读取；游客仅在当前浏览器记忆。该字段通过独立接口按字段合并，旧客户端整份偏好保存不得覆盖。列表、搜索、类型筛选、总数和分页使用同一服务端目录范围；上传仍保存到当前选中的文件夹，批量操作遵循显式选择，目录清空或删除遵循各自确认范围，不继承浏览偏好。

云空间表格和卡片网格复用动态高度虚拟列表，分页数据与批量选择保持完整的已加载范围，DOM 仅保留可见窗口和正在编辑、拖拽或持有焦点的行。卡片按实际 CSS 列宽分组，宽度和密度变化按资源键恢复所在行；每种视图只有一个纵向滚动容器，复用分页、下拉刷新和滚动位置语义。

托管图片通过 `image_assets` 登记原件，通过 `image_asset_refs` 维护正文、历史版本、模板和云文件引用；预览产物与任务复用 `file_preview_artifacts` / `file_preview_jobs` 的 `image_asset` 来源，不以临时 URL 作为身份。首期仅笔记库普通图片卡片与云空间卡片接入，手绘和外链不走此服务。

图片预览由 Worker 生成独立 WebP 并保存在私有 OBS，卡片规格以共享图片协议为准；卡片优先读取预览；云空间图片卡片失败或等待超过 3 秒后，浏览器可直接预览的 2 MiB 以内原图自动回退展示，更大或大小未知的图片提供手动查看入口。原图加载失败停止自动尝试；无权访问或源文件缺失不回退。正文保存、历史快照/裁剪、模板及物理删除在业务事务内维护引用；回收站保留引用，无引用后保留 24 小时再异步清理。未完成回填对账的资产禁止自动删除；清理失败和所有上传尝试的对象位置持久化保留，删除中资产拒绝新引用及任务发布。物理删除后保留一天的删除记录以回收迟到上传，不按预览访问时间淘汰有效小图。

HEIC/HEIF 原件保持原格式、名称、存储位置和容量语义。缩略图复用图片 Worker，大图通过已有 `image_display` 策略及文件来源权限按需入队；HTTP 只核对有界文件头、登记和读取状态，不执行解码。大图复用派生任务的租约、去重、ETag 核验和清理，输出私有 WebP，下载始终签名原件。解码取主图并校正方向，嵌入色彩配置先转换到 sRGB 再去除元数据；大图保留完整画面，长边不超过 4096 像素、体积不超过 8 MiB。HEIF 输入上限为 50 MiB，解码前校验容器属性中的单图尺寸不超过 64 Mi 像素，子进程沿用线程、内存、磁盘及 60 秒预算。历史不支持状态随卡片策略升级惰性重建，不批量改写历史原件。

图片卡片策略版本由共享协议统一定义。JPEG/PNG 等超大图片通过受限 CLI 解码与磁盘像素缓存处理，不按固定像素数直接拒绝；HEIF 额外遵守上述解码尺寸限制。长图先按方向校正，再生成顶部局部预览，浏览器可直接显示的图片在正文和主动查看大图时仍使用原图。`preview_metadata_json` 保存图片展示方式，不复用压缩包清单。失败按文件、资源限制和服务异常分类；卡片提供可触达的原因说明，只允许暂时异常受限重试。同一原图版本的已有缩略图可在策略升级生成期间复用，不跨版本回退。

图片上传尝试的输出账本在任务终止后保留至少 24 小时，覆盖旧租约的迟到上传。清理按任务 ID 分页推进，删除成功的位置退出账本，失败位置保留重试；有效预览对象始终保留。清理以终态与账本快照核对并发变化，不修改任务执行时间，避免重开已复核异常或虚增最近完成量。

图片生成和两处卡片读取分别有开关；`IMAGE_PREVIEW_CLEANUP_ENABLED` 默认关闭，只有完整回填及引用对账后才开启。旧预览 Worker 不认识新来源，不得直接回滚运行。原件存储位置与云空间额度语义不变，派生小图不计入用户原件容量。

- 上传确认按账号与对象键幂等：重试返回现有文件，不因重命名、移动或原目录失效重建记录；回收站对象须先恢复。同名显式覆盖更新原记录，保留文件 ID、分享、标签和置顶，仅重建受内容变化影响的文档与图片关联。普通和托管上传共用事务内目录归属校验，列表关联目录时也限制 owner 和存活状态。
- 客户端上传键只代表暂存对象，不能直接成为新文件的存储身份。普通／托管确认先在单对象事务中冻结服务端专用 `published/` 副本，再按副本实际大小在账号事务内核算容量；重试不重新复制，原签名再次写入也不改变正式文件。冻结不持有账号行锁，发布重新校验两侧对象生命周期。暂存键与副本在远程复制前登记持久清理身份，无引用对象至少一天后回收，正常区、回收站和图片引用继续保护正式副本；复用既有生命周期表，无请求内 DDL 或历史回填。
- 云对象发布与物理回收共用 `cloud_legacy_object_lifecycle` 账本。确认提交前在账号行锁内核验对象状态；清理在相同锁序下检查全部文件引用（含回收站、历史缺失对象键）与图片资产，先提交 deleting 再释放事务连接访问 OBS。deleting/retired 不接受新发布，失败由现有清理 Worker 续跑；因此提前读取的元数据不能复活已开始删除的对象。托管取消、普通覆盖、回收站和注销清理遵循同一边界。

- 展示名、OBS object key 与稳定 `files.id` 相互分离；托管上传的随机对象键在重命名时保持不变，只更新展示名，下载签名通过响应文件名交付新名称，预览签名保持原行为。历史名称对象改名先在短事务校验并取得快照，释放事务连接后以源 ETag 为条件复制到账号内独立随机地址，再在新事务复核文件快照、同名和图片资产状态并提交；普通改名与整理建议共用这一协议，事务回调只因内部准备信号重试一次。随机迁移地址后续改名保持不变。资产 ID、内容版本、引用及已生成的缩略图保持不变；正在执行的图片任务撤销旧租约后从新地址续跑。随机副本在远程复制前登记 `cloud_file_rename_staging`；改名事务须将 pending 记录原子转为 adopted 后才能更新文件与图片引用。Worker 先在短事务把过期或已放弃的 pending 转为 deleting，再释放连接删除对象；deleting 不得重新提交为文件。提交结果未知时以账本状态判断，adopted 只删除账本行。未完成准备保留一小时，删除失败按到期队列重试；删除墓碑保留一天并重复清理以覆盖迟到复制。随机目录只能由服务端生成，不接受普通名称上传。旧名称对象在改名事务内登记持久回收意图；Worker 在短事务复核文件（含回收站和历史缺失对象键）及图片引用，标记删除后释放连接再调用 OBS。普通上传与备份上传签发随机托管地址，确认优先使用客户端回传的账号内随机地址；旧客户端按服务端名称映射确认，并在 HEAD 前后校验映射代际。已退休的旧名称地址保留墓碑且永不重新签发，迟到删除只影响旧地址；名称映射与墓碑随账号注销清理。账号内 AI、新手引导与历史子目录对象键也与展示名分离，改名保持原键；新手引导按原键去重，不能因改名再创建一份。回收站恢复只对正常文件分配不冲突的展示名，同名自动添加序号；原对象地址与引用保持不变，历史缺失对象键先按原名补齐。
- MP3 内嵌封面复用云文件图片资产、引用和缩略图 Worker；只读取有上限的 ID3 标签，优先正面封面，不联网匹配外部图片。无封面保存为正常终态，卡片保留音频占位；历史文件按可视卡片惰性登记，原件及容量保持音频文件语义。
- 视频封面复用云文件资产、引用、私有派生存储和缩略图状态接口，以 `video-card` 产物类型进入独立串行消费通道。服务端分段读取受控原件到临时文件，由受限 FFprobe/FFmpeg 读取时长并抽帧，再复用图片压缩生成 WebP；视频帧保留完整比例，不执行长图顶部裁切。时长随封面元数据持久化。列表只请求封面小图，生成中或失败时保留占位和原因，不加载原视频；点击播放才加载原件。上传时登记，历史视频首次可见时惰性登记；重命名及移动目录复用同一内容版本的产物。封面生成不包含播放转码。
- 上传使用 prepare → signed PUT → confirm；普通名称上传与托管上传共用展示名校验，名称不得包含路径分隔符，不能借普通上传写入随机对象或正式副本目录。已签发的 PUT 在有效期内仍可执行，但只影响暂存对象。
- 托管上传按对象键使用数据库会话锁协调冻结与取消删除；重复冻结可有界等待，取消及维护插入在锁忙时立即返回可重试结果。取消先在账号事务内核验已保存结果，再释放账号锁执行对象删除；容量、目录和同名检查仍在确认事务内完成。确认失败后的清理也要重新加锁核验，避免误删已保存对象；删除失败不能返回确定的已删除结果。对象锁释放失败必须销毁连接，不能把持锁会话归还连接池。
- 快速添加的多文件上传只合并传输请求，批次逐项复用托管上传领域服务与账号权限，不共享一个全成全败事务。已确认文件不参与失败重试；确认结果未知时保留当前草稿的对象凭据，先核验原对象再决定是否重传。关闭草稿不承诺跨会话续传。启用批次请求的 Web 版本要求对应 API 已可用。
- 派生预览以受控 `source_type` 区分个人云文件和聊天室临时文件；来源类型参与唯一键及 OBS 派生对象键，两个数据域不得只靠数值 ID 关联。聊天室来源仍先经过父消息可见性校验，现有云空间与分享预览接口保持独立。
- 文档解析、OCR、压缩包清单和 Office 转换由独立 Worker 处理；HTTP 进程只创建任务与读取状态。
- 图片预览任务及清理由生产运行环境或连接本地数据库的开发环境消费；本地连接远程数据库时，即使获准写入也不领取图片任务、不清理共享产物。笔记原图位于服务器本地目录，不能把开发机缺少原图误写成生产文件缺失。
- 派生资源有尺寸、条目数、超时、输出大小和进程并发上限；解析子进程不继承数据库、Redis 或 OBS 凭据。

### 待办

- 笔记正文引用与待办参考资料支持书签、笔记、文件、待办实例和标签。共享引用协议统一链接解析与账号归属校验；待办引用指向固定实例（完成后仍可打开），标签引用仅打开 `/tag/:id`，不展开成员或自动打标签。重复任务复制时保留原引用目标。选择器由调用方显式启用五类，AI 上下文和资料操作的默认范围不随引用扩展。

- `todo_items` 是任务实例；提醒计划、系列模板、提醒规则和实际投递 Job 分表保存。单层 `todo_lists` 只组织行动，每个实例与系列模板分别保存可空 `list_id`；历史实例默认未归类。删除清单在同一事务解除两类归属，不删除待办或提醒。
- 每条待办最多关联 4 个标签，前端限制选择、服务端复核保存及批量合并结果；历史超限关系不自动删除。待办多标签通过 `todo_tag_relations` 独立保存实例和模板关联，复用全站标签身份，不进入 `resource_tag_relations`。创建、滚动补齐、完成后生成、转换与重建均继承归属；仅改归属走局部更新，不重建实例、不调整提醒 Job。省略字段保留，显式 `listId: null` / `tagIds: []` 解除关联。
- 普通编辑默认仅本次；系列归属的“当前及以后／整个系列”更新相应未完成实例及后续模板，保留已完成历史。清单、标签与实例的查询和写入都限制当前 owner，新写接口纳入管理员路由策略。
- `/todo/workspace` 提供分页、当前筛选的状态计数及全局未完成概览。清单和状态数来自服务端，不以当前页长度计算；待办筛选多标签为同时包含，全局搜索沿用任一标签规则。今天／周一至周日按截止时间筛选；已排期包含开始、截止或实例日期。日历按可见日期范围查询，服务端过滤与[月历日期归属](./design.md#待办工作区)一致。
- 列表通过 `/todo/workspace` 的 `presentation: series` 读取分组摘要，`/todo/workspace/group` 按普通实例或系列摘要节点分页，`/todo/workspace/series` 独立读取系列实例。先对当前筛选的完整实例集合聚合，再选择代表实例和分页；同一系列只出现一次，有重点实例时整个摘要归入重点，否则随代表实例归入清单。完成历史不聚合，实例数量和展示项数量分别返回。新游标绑定 owner、筛选、排序和稳定节点键；其他视图保留原有实例接口。系列日期使用与生成器一致的 Temporal 时区计算，不依赖数据库安装 IANA 时区表。 无分组总览及无分组／重点页的节点计数直接复用筛选成员与节点身份去重，不重复计算代表日期；其他分组计数保留代表实例决定清单归属的完整聚合。
- 待办列表同组、同优先级且无截止时间时，按下一次有效提醒从早到晚排序；取未投递 Job 的当前时间，包含“稍后提醒”的调整，新旧提醒均校验账号和有效状态。排序先于游标分页；无有效提醒沿用计划日期与稳定顺序，提醒排序不改变日历日期归属或议程的计划时间定位。
- 标签目录与详情独立提供待办总数、未完成数和分页待办页签；仅关联待办也属于非空标签。资料总数、相关标签、资料图谱和标签 AI 仍只统计书签、笔记、文件。编辑资料标签关联不触碰待办关系；全局搜索支持父待办标题、说明、标签名称及真实标签筛选，关联多个标签不重复返回父任务。
- 普通／高级创建共享内容、清单、标签，分别保存时间与提醒草稿。普通截止时间不充当计划结束日期；高级的首次日期、停止条件、每次时刻分别保存，时刻可空。草稿变更同步作废旧预览，仅最新有效服务端预览可提交，同稿重试复用幂等键。系列实例与旧任务保留兼容编辑入口。
- 待办 Schema 使用显式加法迁移 `20260908_todo_workspace.sql`，无运行时自动建表补齐路径；先执行迁移并通过 Schema 断言，再发布读写新字段的版本。回滚代码保留新增表及关联数据。
- 创建、状态变更、撤销和 Agent 操作统一复用 `todoService`。
- 日期、DST、月末、系列实例和提醒时间由服务端确定性计算器处理，前端和模型不自行计算。定时提醒的固定时间支持同一待办配置多个日期时间；服务端按分钟归一、排序、去重，每个时刻按渠道生成独立 Job，不生成额外待办。旧单时间配置继续兼容，多时刻仍受单待办提醒投递总量限制。
- 系列与提醒写入使用幂等请求和数据库租约；关闭新建入口不能停止既有调度。
- 新旧提醒每 5 秒按状态与到期时间索引查找待执行任务；租约恢复及历史免打扰兼容每分钟独立处理。单轮有界领取并防止同进程重叠，扫描周期不代表外部通道的设备送达时限。
- 邮件投递与提醒状态回写分开判定。SMTP 结果不明、邮件租约过期，或 SMTP 已受理但提醒回写失败时转入待核对状态，禁止自动重发；站内通知继续按来源键幂等重试。
- 单条待办的重复提醒未设置日期／次数上限，且停止条件没有有效截止时间时，预览显示“长期有效”；后端滚动补齐未来提醒，预计算窗口数量不代表总次数。续排按规则版本、渠道与原定时刻去重，不以窗口内序号识别同一次提醒；任务完成、删除或提醒关闭后停止续排。

### 社区广场

- `/community/feed` 以话题组织图文讨论，不再提供独立的内容类型与“暂无他人回应”筛选；正文以安全的 Markdown 存储，编辑界面复用 CodeMirror 与 TinyMCE，支持 Markdown／富文本切换。正文插图使用独立段落 `![说明](community-image:图片ID)`，与集中附图共用上传清单、修订与权限；不加载外链内嵌图片或其他媒体。新提交兼容现有协议使用 `share` 类型；“标记已解决／重新开放”和采纳回答仅面向当前属于“使用求助”（`help`）话题的帖子，由作者操作，不以旧内容类型判断；详情为 `/community/posts/:id`，本人发布/评论/处置管理为 `/community/manage`，Root 管理为 `/community/moderation`。通用文件附件与含媒体笔记不属于开放分享能力。官方活动复用独立的充值活动与话题发帖任务入口。
- 帖子详情的“更多”提供保存为笔记、保存为书签和复制链接。笔记保存当前安全渲染正文、配图与作者来源，正文插图保留原位置，附图统一放在正文前；图片按 ID 建立私人副本映射，复制到当前账号云空间并使用受本人权限保护的稳定读取地址；原帖更新不覆盖副本，原帖删除不删除已复制图片。对外分享笔记不会扩大这些私人云图片的访问权限。保存复用笔记、书签和托管云上传服务，同账号同帖使用稳定幂等键；已有副本直接打开，回收站副本提示恢复，标签失败单独重试。评论不随帖子保存。
- 话题详情 `/community/topics/:slug` 展示说明、可见公开帖子及本人的任务状态；从话题进入发布时预选该话题并保留草稿正文。Root 在社区管理中维护中英文名称/说明、开放状态、官方置顶与发帖任务标记，使用请求收据和版本冲突保护；停用不改写历史帖子修订，但禁止新提交选用并停止公开话题入口。配置存于 `community_topics` 与 `community_topic_details`，通过显式 `20260916_community_topics.sql` 加法迁移安装。
- 官方充值活动继续由资源套餐活动配置控制。话题发帖任务独立于充值，Root 可配置活动窗口与每人一次的经验／积分奖励；未配置奖励的话题不发奖。窗口内提交、审核公开后固化奖励快照，审核允许晚于活动截止时间。广场活动卡与话题页可领取，也并入工作台／成长中心的一键领取；共用事务和唯一收据，不能重复发放。未领取时要求对应帖子仍公开并保留话题；已领取的奖励不因撤回自动回收。配置一旦产生完成记录即锁定，停用只停止新完成。`20260916_community_task_rewards.sql` 显式安装配置与完成收据表，不回填旧帖子。账本与边界见 [积分获取与治理](./points-earning.md#社区发帖活动奖励)。公开帖子数量沿用账号、屏蔽与不看该帖的可见性规则。
- 社区周任务与成就复用成长体系，计数、版本和领取边界见[社区周任务与成就](./points-earning.md#社区周任务与成就)。话题 `enabled` 决定发现入口、直接访问和发帖选择是否开放；管理员可提前准备隐藏的节日话题。中秋与国庆共用前端封面映射，公开页和管理预览读取同一素材；普通话题不强制配置大幅封面。新建节日种子默认隐藏，幂等迁移不覆盖管理员已有选择。
- 发布话题使用可搜索的单项选择，前后端均限制最多一个话题。编辑器桌面端通过右栏管理话题、图片和资源，移动端通过底部入口打开共享发布设置面板；图片采用三列缩略图并支持预览，面板超出视口时独立滚动。
- 广场使用动态高度虚拟列表与近底部自动游标分页，续页沿用已提交的筛选快照；失败保留列表并暂停自动重试，从帖子详情返回时按帖子锚点恢复阅读位置；从其他模块进入广场自动读取最新列表并清除旧提示。持续停留期间通过轻量轮询发现新的可见帖子，才展示点击刷新入口，不自动打断阅读。
- 帖子图片校验真实 JPG/PNG/WebP 内容、尺寸和单张 5MB 上限，每帖最多 9 张。`community_post_images` 登记私有对象，`community_revision_images` 固定修订内顺序；客户端只提交图片 ID，不能引用他人或其他帖子的上传。待审图片仅作者和 Root 可读，公开读取重新校验父帖、账号、屏蔽和当前公开修订；浏览器通过鉴权代理读取，不暴露 OBS 签名地址。未绑定上传 24 小时后待清理，明确移除或账号正式注销标记待清理，由社区 Worker 重试删除；帖子历史修订仍持有其图片。
- 图片表使用 `20260915_community_images.sql` 加法迁移，能力接口单独校验字段与索引；缺失时不开放图片上传，不影响文字广场。编辑器支持选择、粘贴、拖入、移除及失败重试；发帖草稿使用 localStorage 按账号、角色和帖子隔离保存，兼容迁移旧 sessionStorage 草稿；关闭标签页后仍可恢复，但不跨浏览器或设备同步。恢复仍校验帖子版本，发布成功或清空仅删除当前草稿。已上传图片 ID 随草稿保存，刷新后未完成的本地文件需重新选择。工具栏直接选择文件并插入光标位置，无正文光标时插到末尾；右侧附图区只管理顶部配图，并明确提示正文插图入口。信息流仅显示文字摘要与附图缩略图，正文插图不作为广场配图；详情按顶部附图、图文正文的顺序复用图片查看器。正文图片的位置只存于 Markdown，草稿的资源池与附图成员参与同一份撤销历史；删除正文图片不会自动转为附图，物理文件仍遵守修订持有与未绑定清理规则。能力接口 `inlineImagesEnabled` 控制插图入口，提交携带 `contentVersion: 2`，服务端拒绝旧客户端覆盖含正文插图的目标版本。
- 资源分享只支持本人书签和文字笔记的固定副本，每帖最多 3 项。候选展示前由后端复用快照校验过滤不支持的内容，校验只返回可选键，不创建副本或返回正文。后端按原资源所有权读取；书签保存标题与 HTTP(S) 网址（拒绝凭据及分享令牌），笔记只保存本页纯文字，最多 3 万字，拒绝图片、媒体、画板及过大内容，不携带子页面、排版、内部链接目标或原资源 ID。预览确认后绑定帖子修订，原资源修改或删除不影响副本；撤回帖子停止对其他成员展示。
- `community_resource_snapshots` 与 `community_revision_resources` 通过 `20260915_community_resources.sql` 显式加法迁移，缺表或缺索引仅关闭资源选择能力。未绑定副本只允许本人预览，读取已分享副本重新校验父帖、账号、双向屏蔽与当前公开修订；作者及 Root 可审核历史／待审内容。列表只返回元数据，正文按需读取；未使用副本 24 小时后清理，每人最多 12 个待绑定副本，正式注销删除副本及关联。编辑器草稿只存副本元数据，恢复时资源过期可移除后重新选择。

- 评论仅两层，保留精确回复对象。撤回、屏蔽或账号失效的根楼使用无正文、无身份的占位，合法子回复仍可分页访问。提及使用社区公开身份 ID，普通 `@文字` 不自动解析为身份。

### 社区纯文本自动审核

- `COMMUNITY_AI_REVIEW_ENABLED` 默认关闭，且依赖广场、写入与社区 Worker 开启。新帖及编辑仍先保存待审修订；只有完整纯文本、无图片和资源快照且无媒体嵌入的普通作者帖子进入自动审核。Root 本人发布及评论保持原有规则；关闭或未安装审核 Schema 时走人工，不回填历史帖子。
- 自动审核任务独立于社区通知消费；任务绑定唯一修订和策略版本。Worker 在账号生命周期外发屏障内调用内部 Skill，发布事务重新校验作者权限、帖子版本、当前待审指针、租约与开关，复用 `publishRevision()` 的奖励、审计和通知。人工处理、新修订、撤回及删除均不能被迟到结果覆盖。
- AI 只可批准或交人工，不能拒绝、处罚或读取外链。超时、无效结果、预算不足和过期任务均交人工；已运行但结果未知的任务不自动重新调用模型。转人工后才生成管理员待审通知；自动通过生成现有审核结果通知。模型运行时现有人工队列仍可接管。
- 显式迁移 `20261008_community_ai_review.sql` 安装任务与平台日预算表，纳入社区迁移入口及 Schema 门禁。平台预算按北京时间自然日预留并依据完整 Provider 账本结算，未知用量保留保守预留；不扣作者额度。账号正式注销清除任务与审核原因；审计、奖励和通知沿用原有生命周期。

### 共建建议通知

- 用户提交建议或补充内容后，向有效 Root 管理员发送通知中心提醒，排除操作者本人；官方规划不触发该提醒。审核提醒独立于个人共建进度订阅，沿用通知中心及浏览器推送链路。

### 模块化 AI Skills

页面选择封闭 Skill，服务端 Registry 绑定资源、权限、历史、模型、输出与计费；所有模型访问经过统一 Gateway 与 AI Execution。完整规范见 [模块化 AI Skills](./ai-skills.md)。

Root 的 AI 运行中心是统一 Execution/Span 账本上的平台治理读模型；个人用量与后台治理共用动作、调用和计费事实，管理员详情的入参摘要遵守 [AI Skills](./ai-skills.md#execution-与计费) 白名单边界，不恢复旧助手日志作为现行业务数据源。

旧助手的会话、来源、反馈等表只用于导出、删除与审计兼容，不再作为普通 Skill 上下文。

私有资料检索由 `personalKnowledgeSearch.js` 保留数据库归属与内容代际校验。正文按资源与字节估算分批读取，文件分块先按稳定顺序选取 ID 与字节数，再按预算回填完整正文并复核归属和可用状态；单个超大资源单独读取，读取期间的并发变化意味着该预算不是硬内存上限。标签只回填实际索引资源；大型正文预处理及索引构建、候选检索使用不访问数据库的工作线程。索引输入分批传递，返回候选仍须主流程复核权限和版本。冷构建及线程请求都有并发、等待和超时上限；缓存共用 `personalSearchIndexCore.js` 的数量、估算字节与有效期策略，超限材料仍可完成当前查询，不能静默截断覆盖。线程退出后可重建有效缓存，淘汰中的在途查询只保留临时索引；索引始终从权威资源重建，不再维护没有读取方的持久正文镜像；跨实例失效继续递增数据库代际并清理旧版本遗留的分块，账号注销同样保留清理。估算缓存预算和线程堆限制不等于进程 RSS 硬上限。

### 公共帮助与知识库

- `knowledge_base.category = '帮助中心'` 与 `status = 'public'` 共同定义普通用户可读、可导航的公开帮助边界；展示分组不得改写或替代这层权限语义。
- `knowledge_base.help_section` 是帮助中心栏目唯一事实源。帮助首页主题、左侧目录和栏目文章列表都由公开文章返回的该字段生成，不在前端按标题或正文关键词猜测；空值只兼容归入“其他帮助”。
- 帮助问答先按章节检索定位文章，再在总量与单篇预算内装载正文；超长文章保留命中与相关章节并声明截取。装载时重新校验公开、帮助分类和未归档状态，HTML 正文中的 HTTP(S) 链接保留为材料。来源入口由服务端文章 ID 绑定，使用 `/help?article=ID`，不采用模型生成的内部路径。
- 新增或修改公开帮助文章时必须维护栏目。栏目随首篇有效文章出现，随最后一篇文章下线或归档而消失；栏目顺序继承服务端文章维护顺序。

### 知识工坊

- 浏览器本地工具、积分任务、AI Skill 与文档 Worker 共用版本化工具目录，但保持不同执行和数据边界；完整规范见 [知识工坊](./toolbox.md)。
- 本地 PDF 与图片处理不创建服务端任务、不上传原文件；固定成果工具使用报价、任务、成果和保存收据分离的状态机。资料转表格采用独立的 `toolbox_extraction_*` 持久化域，API、文档 Worker、账号导出与注销共享这一事实源；范围、计费和证据边界见 [资料转表格](./toolbox.md#资料转表格)。
- 研究、学习与写作复用同一持续工作区域，只保存目标、资料引用、事项与推进记录；模板文案不分裂底层事实表，资料正文仍由原资源域持有。
- 积分 AI 工具通过受信任 Worker 进入统一 AI Execution，但不重复消耗用户 AI 额度；成果页不提供工具内追问，保存后的笔记助手属于笔记模块的独立能力。

### 成长、积分与支持

- `user_growth.exp` 是所有角色的等级事实源；Root 身份不等于满级。
- EXP、积分、AI 永久余额、空间和道具使用各自可审计账本，展示快照不能替代流水。
- 背包跨渠道获得记录复用已有账本与可靠收据，资产发放和来源记账同事务提交；范围与历史边界见[背包获得记录](./points-earning.md#背包获得记录)。
- 新手任务的创建入口复用完整书签表单、笔记格式／模板选择器和文件快速添加；打开或取消入口不推进任务，完成及领奖仍由原有服务端事实裁决。首页仅在完整首次保存任务状态确认均未完成时优先展示首次收藏和笔记，待领奖任务保留优先级；完整任务页保持既有顺序。笔记入口参数一次性消费，取消返回原任务页，选定格式后保留该返回来源。
- 每日回顾是独立的账号日历业务域：`daily_content_review_sessions` 固定账号当天的会话，`daily_content_review_items` 固定最多三条书签、笔记或文件、候选判定时的账号本地资源日期及逐条动作；GET 只读已有会话，幂等 ensure 才生成清单。展示日期和回顾理由使用该固定日期，不按浏览器时区重新解释。打开内容或进入原因标签算作当日已回顾，全部有效条目处理后完成；仅当至少一条当日仍可用内容全部通过这两类真实回顾动作完成时，才按账号自然日自动结算一次 5 EXP，复用统一成长账本和每日 EXP 上限。7 天后再看、不再推荐和只收起今天都不触发奖励，也不产生任务、积分或连续天数压力。
- 工作台正式今日简报在管理员上下文中只读取目标账号已经持久化的产物；前端不发起事实新鲜度检查、生成、更新或设置写入，服务端也不向任何管理员上下文开放这些写入口。目标账号没有当日产物时返回并展示只读默认态。
- 桌面工作台与移动「今日」复用同一份每日回顾状态和组件语义，成长页不再挂载另一套回顾列表。`growth_recap_state` 只负责跨日的 7 天延后、永久屏蔽与最近展示日期；工作台渐进加载，回顾失败不阻断今日核心内容。
- 成长周报按账号时区的自然周统计，与每周挑战同一周一重置：本周统计到今天并对比上周同一时段，上周统计完整七天并对比再前一周；周一推送的通知固化上周快照，仍是上周时前端换用实时数据。活跃天数只计有新增或完成记录的天，签到单独计数。周报卡只含汇总数字；新增书签、笔记、文件的标题只在本人实时请求中返回，不写入通知快照，管理员上下文也不返回。
- 积分获取与消费使用不同版本：获取规则见 [积分获取与治理](./points-earning.md)，消费见 [积分经济](./points-economy.md)。
- 知识庄园共用 `user_growth.points`，不另设货币。庄园存档不保存余额；购买、建设和出售在成长账号锁内与原积分流水、存档版本和操作收据同事务提交。重试沿用原请求号，返回原操作结果与最新余额；客户端不能提交存档、时钟、随机结果或任务完成状态。作物生长按真实经过时间计算，日周额度按账号日历刷新，调整时区不能清空已使用日期的每日额度；任务与连签奖励只认原成长域事实。
- 庄园已确认的独立场景通过同源 iframe 接入，认证与 API 调用由轻笺宿主处理，令牌不进入场景 URL。桌面加载与失败时保留主站导航，场景就绪后铺满页面并使用游戏内返回；退出后恢复主站导航，手机加载时保留独立退出入口。服务端与场景共用共享包中的规则；Vite 生成经典脚本，正式构建不依赖被忽略的原型目录。素材、场景比例和玩法的改动与正式接入分开评审。
- 庄园启动进度按实际资源解码和场景准备完成统计，首帧就绪后才开放引导，后台暂停渲染不计入加载超时。存档读取与静态资源下载并行，经典脚本及样式按原顺序合并、按内容版本更新缓存；固定首屏素材从入口并行下载并解码，DOM、CSS 和 WebGL 共用页面内资源地址，停用 HTTP 缓存时也不重复下载；存档与余额不进入素材缓存。环境动物的纹理和动效在核心画面可交互后空闲启动，离开场景后不启动旧任务。游戏内返回首次在顶部提示，3 秒内再次点击确认退出；确认后直接导航到进入前的主站路由，取消读取与场景，不受 iframe 历史、引导或钓鱼状态阻挡。积分在庄园内打开账本，退出后的积分和背包刷新不阻塞导航。固定场景图层、低频纹理和岸线距离遮罩在素材生成阶段预合成，浏览器只解码并上传纹理，不在入场时读取整幅像素或导入水面计算 Worker；动效不可用时保留静态场景，非首屏区域在可交互后空闲预取。仅对已开放庄园的 Root，在主站首屏与前台请求稳定后串行低优先级预取当前端静态素材，不运行隐藏场景；输入、导航、前台请求或切到后台时中断，省流量与弱网跳过。图片缓存与发布约束见[发布流程](./release-acceptance.md#部署顺序)。
- 庄园的 Root 重置入口使用独立测试存档，从首次引导开始并复用正式规则；测试购买、出售和奖励不调用资产写接口。测试存档按账号与协议版本保存在当前标签页的 sessionStorage，刷新继续同一测试进度与真实生长时间，主动返回正式庄园时清除；正式存档与积分仍以服务端为准。进行中的正式操作先完成或恢复收据，不能被测试重置清除。
- 资源商店与纯支持共享支付渠道但使用不可变订单用途分域。套餐、首购和权益发放见 [资源商店套餐](./support-packages.md)。
- 头像框视觉等级与动效不由经济目录定义，唯一设计规范见 [头像框设计](./avatar-frame-design.md)。

### 服务器管理

- 浏览器只访问 Express 的 `/api/infra/*`。Express 负责登录态、Root 权限、确认、审计和幂等。
- `apps/host-agent` 仅监听 Unix Socket，不开放 TCP，不加载后端 `.env`，不持有数据库、Redis、OBS 或 SSH 凭据。
- Agent 只提供白名单指标、服务状态、受限日志和固定动作；不接受任意路径、命令或进程名。
- 写动作先落 intent，再由 Agent 以 job ID 原子保存未知/成功/失败终态。网络重试和进程崩溃不能自动重复执行。
- 主站完全不可用时仍需人工 SSH；Host Agent 不是远程多主机控制平台。

### 后台异步任务健康

- 队列状态仍由各业务领域维护。健康统计只计当前有效资源和当前处理版本，提醒任务与其邮件投递日志合并为同一事项；任务 SLA 汇总覆盖全部当前任务，明细条数限制不影响汇总。页签角标可同时读取两区，SLA 指标及其来源缺失判定按当前分区计算，人工待处理不混入异步任务超时。
- `admin_async_job_archives` 保存人工确认的历史异常归档，绑定任务状态和更新时间。归档不改原失败或未知投递事实，不入队、不发邮件；当前任务状态或版本变化后重新参与健康统计。批量归档仅处理超过 24 小时的终止失败或结果未知记录，以及已退役且创建超过 24 小时的旧预览任务；执行前核对完整快照摘要与数量，保留管理员审计。

### 总览真实活跃统计

- 总览待办新增计数、同期比较与“最近新增”列表共用用户创建任务的口径：单次任务使用自身创建时间，重复系列按系列创建时间只展示一次；滚动补齐、完成后续生及编辑产生的替代系列不计为新建。旧版重复任务只保留原始任务；已删除、教学示例与账号过滤沿用总览边界。
- 后台总览的活跃账号以可信点击、触摸、键盘、主动滚动及其后 5 分钟前台阅读为口径；隐藏或失焦结束阅读资格，再次交互恢复。自动请求、鼠标移动和程序滚动不计入；这是客户端运营信号，不用于奖励或防作弊。
- Web、PWA 与 Android WebView 共用入口采集器，输入回调只更新非响应式内存；上报按分钟节流，同源标签页协作、Redis 按账号和北京时间日期合并写入。遥测不进入 API 日志或成长事件，故障不降级为无界数据库写入。
- `user_activity_daily` 是总览人数、周期去重、同期比较及用户抽屉的唯一事实源；`user_activity_metadata` 标记启用时间。查询统一排除游客、注销/停用账号，按内部账号开关过滤；用户备注只读取当前管理员自己的备注。
- 昨日同期在昨日属于完整采集日时独立展示；7 日同期均值仅在前 7 个完整日均已覆盖时展示，否则标注数据积累中。完整采集日没有记录计为零，上线首日不纳入比较。
- 每日首次/最近活跃时间存北京时间 DATETIME；历史不足不回填 API 日志，切换首日标注不完整，统计不可用不显示零。抽屉按最近活跃时间倒序、用户 ID 倒序分页；首次请求时间固定入选范围，最近活跃仍读取当前值，翻页期间再次活跃而前移的用户需刷新后查看。最近活跃不代表在线状态。
- 用户管理列表的最近活跃显示、排序、活跃范围筛选与用户详情统一读取每个账号最近一天的真实交互记录；无记录时保持未知，不回退会话时间，排序置后。设备会话的活跃时间仍表示认证会话使用。
- 总览「查看活跃用户」提供近 7 / 30 / 90 天的逐日折线图，可点击日期或用日期选择器查看当天人数与分页名单；历史日期按全天统计，今天截至查询时间。采集前显示缺失而非零，启用首日与今天标注非完整日；内部账号开关同时作用于趋势与名单。
- 产品运营分析仍使用其既有 API 日志口径；会话最近活跃与成长有效行为保持各自领域语义，不与总览指标互换。

### 后台增长统计

- AI 功能使用人数与结果采用是两个指标：前者保留主动执行等历史口径；结果采用仅关联同主体、同 Skill 与匿名化请求标识的已交付执行，按当前窗口聚合。新版事件携带 `measurementVersion=2`，点击结果操作单列，`draft / insert / copy / saved` 分别表示填入草稿、插入编辑器、成功复制与成功保存，类型可重叠。旧客户端或缺少关联的历史采用单列，不回填、不混算为新口径，也不以记录缺失证明实际未使用。
- AI 采用里程碑按执行、采用类型和身份幂等；请求标识沿用遥测 HMAC，正文、标题、网址及资源 ID 不进入维度。表单生成内容被撤销或完全改写时不计其保存采用；埋点同步异常和异步失败均不阻塞生成、编辑或保存。

- 注册漏斗主指标按浏览器指纹独立去重，不等于跨设备唯一账号。四阶段近似路径允许秒级时间相同，每阶段先收敛最早可达时间再关联下一阶段，避免重复事件的组合膨胀；路径只用于诊断，不证明同一次尝试或同秒因果顺序，不用事件 ID 伪造顺序。
- 产品运营分析的七日资料激活仅纳入完整观察 168 小时的普通注册账号，复用首个自有资源事件；没有成熟样本或来源不可用时比率为未知，不回退到全部新增账号作分母。
- D1/D7/D30 表示注册满 1/7/30 天后接下来的 24 小时 API 回访，分子和分母都等待注册满 2/8/31 天。查询按账号与时间索引检查事件是否存在，不展开全部日志后去重；各列队列不同，不能拼成同一条留存曲线。日志缺失或清理仍是历史覆盖限制，不等于真实未使用，也不补造真实交互历史。
- 「后台 → 产品运营分析」默认查看最近 7 天，可切换 30 / 90 天。活跃人数按普通有效账号检查窗口内请求是否存在，避免展开全部日志再去重；各聚合限时并独立降级，不以单个来源失败阻塞其他结果。
- 页面内「新用户有没有真正用起来」是核心使用报告的可见入口，由管理员本人手动生成。全页只有顶部一个 7 / 30 / 90 天选择，访问、注册、分周回访与报告均使用这一范围；首次使用与核心报告仅纳入其中完整观察 168 小时的账号，默认近 7 天通常尚无合格分母，显示等待而非零。调整时间会清除旧范围的报告并忽略其在途响应；打开页面、调整时间或点击普通刷新都不自动生成报告。CLI [报告入口](../apps/server/scripts/reportCoreUsage.js)与页面复用[同一聚合服务](../apps/server/util/services/coreUsageReport.js)，不维护两套指标 SQL；接口与鉴权见 [管理员报告 Handler](../apps/server/router_handle/adminCoreUsageHandle.js)。
- `core-usage-v1` 复用成长成功事实计算资料/整体首次行为及跨日核心行为，历史资料激活和真实交互代理单列；零经验事实仍可计入，既有资源幂等会折叠重复操作。覆盖起点未确认、覆盖不全或来源异常时保留已观测人数和缺失原因，完整比例为未知；页面另外以已观测人数除以合格人数展示「已记录比例」，并注明记录不全可能低估实际使用。无合格人数或来源异常不计算比例，已记录 0% 不能解释为实际零使用。渠道和完整扩展历史不由现有状态表猜测；浏览器不能声明采集覆盖起点。
- 报告只返回聚合，单连接只读事务内串行查询，每条 SELECT 使用 MySQL 5.7/8 的 5 秒执行上限。同进程同范围的在途请求共用一次计算，不同范围并发请求提示稍后重试；无自动刷新、定时任务或持久缓存。HTTP 共用连接池时只设置事务只读，不留下会话级只读状态影响后续业务写入；CLI 使用独立只读连接。报告失败不执行迁移、建索引或回填。
- `u7Reuse` 统计注册后 168 小时内、主动打开更早北京时间自然日保存的自有资料的人数，书签、笔记、文件合并按账号去重。前端只在可信交互引发的打开或已加载资料内主动操作时上报；刷新、预取、隐藏页面与系统事件不单独计入。书签表示发起外链打开，文件表示进入预览，不保证目标已加载或读完。服务端复核账号、归属、存活状态与创建日期，并排除 `onboarding_seed_resources`；身份来自认证，不接受客户端时间或 owner。
- 再使用数据由 `resource_reuse_milestones` 保存，每账号每类型最多一个首次时间，不保存资源 ID、标题、正文、URL 或操作轨迹；资料 ID 仅用于当次归属校验。新接口不进入 API 活跃日志，不发奖励，故障静默、有界限频，无离线补发；注销沿用账号锁与显式清理。报表复用同一只读聚合，缺表、覆盖未知、旧客户端漏报不解释为真实零使用。`resource_reuse_metadata.started_at` 在部署并验证客户端采集后显式登记，不以建表或第一条事件证明覆盖；启用步骤见[发布规范](./release-acceptance.md#资料再次使用统计)。
- 日期统一东八区，存储时区须与数据库会话核对。CLI 参数见 `pnpm --filter server report:core-usage --help`，默认最近 28 天、最多 90 天；覆盖起点仅在查证后传入，不能以最早事件时间代替。历史报告仍受当前日志保留截止约束，不能还原已经清理的数据。

### 华为 App 通知推送

- 显式启用的 Android 联调包与正式候选包复用前台通知桥、现有推送订阅/队列及 production-only Worker；普通正式包仍不包含华为 SDK。联调包单独告知，正式候选包在新版隐私政策同意和系统通知授权后初始化 SDK、上传 Token；注册按账号与世代隔离，退出撤销 Token，注销清理订阅和任务。详见 [Android 推送说明](../apps/android/README.md#华为通知正式候选包)。
- 除仅限站内铃铛的公开资源通知外，通知中心可见的新通知统一进入华为队列，发送前复用通知中心的账号、删除/撤回、社区权限与来源可见性。仅真实待办提醒任务可使用 WORK，另复核待办状态；SUBSCRIPTION 依赖实际获批权益配置。其余消息显式使用 MARKETING，仍受厂商频控；未传 category 也会被华为归入资讯营销类。卓易通不支持这类消息后台转发，不能把通道已连接等同于所有分类都能后台到达。待办远程通知可显示当前标题和说明摘要；聊天室提及、回复在复核当前消息及接收者权限后可显示发送者与短摘要，非文本显示类型提示；两类请求锁屏隐藏且仅在厂商侧保留短时效；聊天室订阅预览保留「订阅」前缀，满足分类文案要求。其余通知保持统一文案，点击均进入通知中心。API 按当前设备绑定标记远程通知，前台只更新角标与回执，避免额外本地弹出。
- 推送订阅表的 `endpoint` 支持内部 `huawei:` 命名空间；Token 只作为厂商请求体使用，不解析成外部 URL。浏览器入口仍只接受原有 HTTPS 厂商白名单。复用既有 outbox、租约、重试、免打扰与失效订阅状态，不新增运行时 DDL。厂商已受理消息不能保证即时撤销，离线退出时不能保证立即停止展示。

- 每次华为发送前保存独立 attempt 与 `bi_tag`，收到厂商响应后记录 requestId 和受理状态；仅验签成功且应用、Token 摘要、attempt 与请求一致的送达回执才更新设备送达事实。`/api/notification/huawei/receipt` 使用厂商 HMAC 验签，独立于用户会话，并在通用请求正文日志之前处理。V1/V2 均可接收，重复与乱序回执幂等保存；控制台固定测试样本只确认连通，不能算作设备送达。
- 回执结果 2/5（或 V1 201 下的对应子状态）仅退休匹配的绑定世代并取消其未发任务；权限关闭、营销频控等不删除有效绑定。诊断表不保存原始 Token 或消息正文，随既有任务保留期和账号注销级联清理。历史受理结果不能补算为设备送达。

### root 聊天室全量订阅

- 仅当前 root 身份可修改 `rootAllMessages`，无设置记录默认开启；普通用户与管理员代看不得借此扩大提醒范围。两个设置入口复用同一接口和组件。聊天室角标档位不变，全量订阅独立于档位，仍遵守站内/聊天室总开关、屏蔽和来源可见性。
- 普通新消息写入 `community_chat` / `meta.kind=subscription`，复用消息来源与接收者唯一键；回复优先于提及，全量订阅不重复生成，自己发送不提醒。仅发送成功后的新消息触发，阅读聊天室不取消通知事实。
- 关闭全量订阅保留通知中心历史，并永久取消该订阅尚未发出的提醒；重新开启不补发。列表、未读、批量已读、原生同步及推送发送前复核当前 root 与来源权限。沿用华为 `SUBSCRIPTION`、发送者与短摘要、锁屏隐藏正文及通知中心点击入口。

### 浏览器通知

- 前台铃铛通过独立 SSE 接收本人通知的变更信号，同一标签页的铃铛和通知页共享连接。新增、阅读状态、删除、管理员撤回／归档，以及聊天、社区、公开资源、待办和相关账号可见性变化在事务提交后发信号；回滚不发送。信号不含正文或未读数，跨进程经 Redis 发布，权威可见性与计数仍由通知接口核验。来源变化按来源合并，仅查询当前已连接账号的既有索引范围，向实际关联通知的接收者发信号；无连接时不查库，不增加扫描任务。客户端合并连续信号、静默更新已打开列表，并重新核验已定位通知和打开的通知正文，来源失效后及时移除或关闭，保留低频校准和断线退避；隐藏页面暂停连接与校准，恢复或重连后补齐。管理员代看保留原范围的低频读取，不订阅操作者的事件。SSE 只负责前台同步，设备后台提醒继续走浏览器或 App 推送。
- 通知中心是浏览器推送的唯一来源；各业务保持原有通知范围。新老用户的浏览器通知偏好默认开启，之后主动关闭按账号保存在当前浏览器；旧账号级偏好不决定设备状态。已有系统授权时自动订阅，未授权时由用户点击授权按钮完成授权，拒绝或订阅失败不能展示为已接收。客户端持久化绑定后才激活服务端订阅；前台照常提醒，多标签页由同一 Service Worker 去重。当前仅向 PC 开放浏览器推送；共享移动渲染模式隐藏推送设置、免打扰与授权入口，不自动订阅，并在账号同步时撤销当前设备旧绑定。Android 原生壳不接入。
- 通知行的 `browser_push_pending` 与微秒创建时间构成原子待投递记录。通用写入、聊天室批量写入和周报都在新增通知时写标记；旧通知不回填。独立 Worker 按通知创建时已启用的订阅及其世代展开任务，关闭、重开或新设备不补发旧通知。
- 通知设置的免打扰只延后浏览器推送，覆盖所有推送类型；站内与邮件按原计划投递。沿用已有时段与时区配置，推送 Worker 发送前复核，延期不消耗失败重试次数、不延长 24 小时有效期；待办规则旧免打扰策略仅保留协议兼容，不再参与投递。
- 浏览器推送及其后台通知来源（新旧待办提醒、周报、成长提醒、整理完成通知）仅由生产运行环境消费。统一复用运行环境解析，未声明环境按本地处理；本地即使获准连接生产数据库或误开推送配置，也不扫描、领取、恢复通知任务或消耗待通知标记，避免上游抢单后只生成站内通知、线上无法再投递。生产站内和邮件调度不依赖浏览器推送开关。FCM 可配置最多两个独立中转，按配置顺序发送，再回退直连；仅网络或可重试服务错误切换，密钥拒绝、失效订阅不换路重发。中转只收到加密请求与短期签名，不持有通知明文或 VAPID 私钥；设备仍须连通其浏览器厂商服务。
- 外部发送不进入业务事务；任务使用租约、来源去重、有限重试和最长 24 小时有效期，订阅失效或通知撤回/删除时停止投递。投递日志只含数量、延迟和稳定错误码；厂商受理不代表设备已收到。厂商明确拒绝的失效订阅保留独立状态，设置页可见时定期复核并提示重新连接；重连必须撤销旧订阅并申请新地址，禁止重新激活已知失效地址。
- 浏览器标题与摘要复用共享通知展示规则。点击只唤起通知中心并按当前账号定位目标，不自动已读、不完成待办、不执行通知业务跳转。未登录先登录，目标不可用统一提示；业务操作仍由站内通知组件执行。
- 站内通知的业务链接支持站内路径与完整 HTTP(S) 地址；同源完整地址转换为路由并保留查询和锚点，外站地址正常导航，其他协议及带凭据地址不执行。

## Worker 与副作用

- 文档/文件预览 Worker：解析、OCR、压缩包与 Office 派生，并按来源类型隔离、回收个人云文件和聊天室临时文件的派生物。
- 文档进程内的文档/Office、图片、视频与工坊模型等待独立轮询；媒体处理共用有界准入，免费 OCR 也计入媒体预算。领取前等待准入，已经领取的工坊任务等待本地处理时继续维护租约；停机停止领取并等待在途任务后才关闭连接。
- 知识工坊 Worker：租约领取积分任务，复用 AI Skill 或文档来源生成成果并结算积分。
- 整理建议 Worker：新旧队列共享文档进程；规则按记录数与序列化字节上限批量持久化，AI 每次调度处理一个资源。规则读取不放入持有用户锁的事务，持久化时以任务租约校验防止迟到写入。笔记的标签与标题共享一次结构化元信息调用，文件内容按覆盖范围分批归纳；书签名称、描述和标签共用书签元信息推荐核心与一次主调用，已有名称与描述完整时直接分析，缺失时读取网页；网页读取失败不生成名称或描述，标签仍可使用已有有效材料。网页材料准备在外发锁之外完成，外发前复核资源版本、任务与租约，按实际材料估算额度；规则不经过 Provider；计量边界见 [AI Skills](./ai-skills.md)。外发持有与账号注销、后台角色及停用变更相同的 MySQL 账号生命周期会话锁，普通用户行锁仅覆盖初始身份验证；等待生命周期锁时归还池连接，API 与 Worker 必须连接同一主库。外发准入按进程限制并发并预留回调连接预算，回调仍保留原事务边界。结果在 Execution 成功前提交，并以任务与资源租约令牌防止迟到回写。过期的已运行任务无法证明 Provider 未执行，因此只标记中断，不自动再次收费；用户可明确重新整理。注销同步清理任务、快照和建议。
- 整理完成通知复用站内通知来源键去重，由 Worker 持久化补发。新任务耗时超过 30 秒且完成后通知；部分失败明确说明，主动结束不发送完成通知。设置中的「整理完成通知」默认开启，并受站内总开关约束；以投递时偏好为准，关闭时跳过且不在重开后补发。历史任务不追补通知。
- 书签图标 Worker：持久任务、去重、受控下载和活动引用检查。
- 资源治理 Worker：只读扫描与经确认的低风险清理。
- 动态网页渲染不是常驻业务 Worker：HTTP 进程只在静态读取不足时调度有界、一次性的低权限 Chromium 子进程；系统浏览器与沙箱配置由 `check:web-renderer` 验证。
- 待办/提醒与其他调度：数据库事实、租约、幂等和有界批次。

业务事务先提交权威状态，再触发可补偿旁路。Worker 任务表而不是 API 日志用于解释执行状态。部署到 Linux 的后端包不得依赖本机平台 native Node 二进制；图像/OCR 使用服务器受控 CLI。

### 游客教学示例

- 游客 v2 清单由显式维护工具安装，独立于 v1 回执；复用资源、标签、待整理、待办和工坊领域服务，普通账号不参与。图片先进入托管与缩略图链路，手绘保存原场景。
- `visitor_example_maintenance` 由显式迁移建立，默认关闭。安装后登记业务键、对象 ID、日期偏移和版本快照；资源治理 Worker 每分钟检查北京时间日期，在同一事务锁定状态和对象，每日最多成功一次，停机后补到当前日期。只滚动登记的日期，不改正文、标签、历史推进或资料创建时间；对象缺失、归属变化或人工编辑时整批回滚，低敏记录并有界重试。
- 游客简报通过 `GET /api/workbench/visitor-brief` 只读生成，普通游客与管理员代看游客共用；来源重新核验，标为教学示例并显示实际维护日期，滞后时不伪装为今天。此链路不调用 AI、不保存正式简报、不触发奖励或通知。正式账号仍使用原简报机制。
- 安装、停用与恢复入口及授权边界见 [游客示例维护](./release-acceptance.md#游客示例维护)。

## Schema 与部署边界

- Schema 有显式 `migrations/*.sql` 和运行时 `ensure*()` 两条轨道；前者负责历史迁移，后者只补幂等结构。
- `tag_db.sql` 可能落后于运行时，不能作为唯一事实源。
- 发布前运行只读 Schema 与受影响 Worker 门禁；有输出即未就绪。
- 部署脚本从本地打包后 rsync 到 Linux。健康检查失败不会自动证明已回滚，必须按发布输出执行精确恢复。
- 本地预览、发布授权、分支处理和验收步骤见 [本地预览与上线](./release-acceptance.md)。

### 公开收集数据域

知识工坊公开收集使用独立 `collection_*` 表，表单关联标签，提交原文与类型化答案支持分页管理、聚合和流式导出；不复用工具任务或资源关联表。公开路由独立于通用鉴权链，Root 专属账号表单按需读取可信会话，管理路由保留所有权校验；提交奖励复用积分发放收据，并与回答在同一事务结算。生命周期与统计口径见[公开收集](./toolbox.md#公开收集)。共享契约为 `@lightnote/shared/collection-forms`。

### 内容转存为笔记

已有内容转存入口统一通过 `useSaveAsNote` 与笔记领域的 `SaveAsNoteDialog`。标题可修改（255 字符），默认根目录，可选择父笔记、标签与项目；标签不继承来源。普通笔记编辑、新建、扩展采集、冲突副本和保存为书签不进入此流程，也不为原本没有复制能力的分享页面开放转存权限。

工坊成果（含 OCR、PDF 总结、翻译）使用持久成果适配器；PDF／Word 提取文本、资料生成抽屉的快捷分析和预览、书签／笔记／云文件分析、标签问答使用文字适配器。前者沿用成果保存回执与回收站重建规则，后者沿用稳定请求身份和正式笔记创建接口；正文格式与引用处理由来源负责。社区入口保留公开快照、作者来源、个人想法、图片复制及空间提示，创建前重新校验公开来源，重试复用上传回执。

保存配置按账号与来源隔离，页面离开或账号变化清理；结果未知时冻结配置并重放原请求。标签和项目关联在笔记创建后执行，部分失败只重试失败关联。保存成功刷新笔记目录，“保存并打开”经移动浮层关闭流程导航；保存到共享父笔记仍走既有分享范围确认。
