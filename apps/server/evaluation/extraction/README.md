# 资料转表格核心能力实验

这是资料转表格的固定材料质量实验入口。正式工作台、Skill 和队列使用 `util/extraction/` 的实现；本目录用于验证：用户提供资料和一句目标，AI 能否建议字段、提取多个条目，并给出可以核对的依据。

在仓库根目录运行：

```sh
pnpm --filter server exec node evaluation/extraction/run.js
pnpm --filter server exec node evaluation/extraction/run.js --smoke
pnpm --filter server exec vitest run evaluation/extraction
```

默认只打印固定测试范围和预算，不读取凭据或联网。`--smoke` 只检查真实 Execution/Gateway 导入与生产基础设施隔离，不调用模型。

显式质量实验（会产生 Provider 实际费用，不能加入常规测试或 CI）：

```sh
pnpm --filter server exec node evaluation/extraction/run.js --live
```

仅支持仓库中四组公开事实节选／自编材料，不接受任意文件或私密用户输入。每组自动建议字段一次、提取一次；最多 8 次模型请求、80,000 Token 保守预占，每次请求限时 90 秒。禁止自动修复和失败重试，任何失败停止余下实验。重新执行 `--live` 会创建新实验并再次付费，不能当成无副作用续跑。

可用 `--cases=events,boundary` 显式选择尚未运行的固定案例。选中的案例仍会重新调用模型，不复用其他实验的结果。校验失败的候选输出也存入 `results.json` 供诊断，必须与通过校验的 `records` 区分。

调用使用现有 `callStructuredSkillModel → Gateway → Provider` 和唯一根 Execution。独立 Node 进程的导入钩子仅替换生产持久化／额度依赖为失败关闭的适配器入口，实际注入本地 JSONL 账本和固定实验预算。不会读取或修改生产 MySQL、Redis、用户额度和资料。仅读取 `.env` 中明确列出的模型配置项。结果写入 Git 忽略的 `docs/plan/extraction-evaluation/<run-id>/`。模型实耗和未知实耗分开记录，不将本地预算结算称为生产计费验证。

验证范围：

- 三个官方来源的明确节选：MIT 四门课程、Raspberry Pi 四种相机的横向参数、W3C 四场会议。来源、读取日期和精确节选均在 fixture 中；这些输入已是文本，不能验证解析器、OCR 或整页读取。
- 自编中文边界材料：模拟跨段条目、重复页眉、数字冲突、不可读第三页和材料内恶意指令。
- 自动评分按记录身份和对应字段比较。合并字段、单位表达和未识别的列名须人工复核；不得直接把所有评分差异宣称为提取错误。引用匹配不等于语义正确，需人工检查是否真的支持该字段、是否属于该条目。
- 严格的 `HH:MM–HH:MM` 时间段可拆成起止两个评分检查项，计数不是输出物理单元格数，不猜时区。简单管道分隔表格保留原文行列定位与表头；完整单元格可消除名称前缀歧义。复杂表格、合并单元格和带转义分隔符的输入不在该规则支持范围内。
- 日期引用缺少年／月／日、横表参数落到其他产品列或值没有出现在引用里时，保留原值并标为 `evidence_incomplete`。这些是确定性缺口检查，不是语义正确性证明。
- 完全重复的字段名被拒绝。近义字段、重复时间表达和系统元信息列给出建议确认提示，不静默删除可能有不同含义的列；AI 建议阶段仍需用户确认。
- 该实验一次性完整送入限定文本；超出 24 KB 输入预算直接拒绝，不截取后冒充全量。它不实现长文件分段、跨批次去重、人工修改、队列、数据库、权限和 UI。

后续质量改进应综合真实材料测试、人工纠错工作量、失败案例与实际用量，不能仅凭固定小样本宣称已证明产品价值。产品边界见 [知识工坊](../../../../docs/toolbox.md#资料转表格)。
